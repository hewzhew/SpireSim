# 本地战斗搜索与学习实验

这些入口用于独立检查表示、训练和行为。它们不是日常跑局入口，也不声明自然 A20H 能力。
Rust 的 `sts_guided_search` 共享真实转换、合法动作、数值编码与重放；Python 拥有网络和训练。
外部 LLM 接入已退役，当前实验不依赖 provider、提示或文本回复。

## 实际终局的实体价值小试验

[`entity_continuation_trial.py`](entity_continuation_trial.py) 使用同一个
[`continuation_value`](../../crates/sts_guided_search/examples/continuation_value.rs) owner，
每个准备后的起点独立调用无模型、固定工作量的搜索与实际战术续打；不注入来源胜利后缀。
网络只有两个后果头：实际获胜与实际保留血量／最大血量；死亡对两者都给零，计算截断与
逃跑明确拒绝作为完成标签。候选分数为两头的均值，复用实际玩家的胜利加保血效用，
不是启发式局部分数。这里没有动作模仿，也不向生产搜索加载权重。

试验从当前模拟器新构造持续／临时降力量、最后一费的用途以及 BattleTrance／ShrugItOff
出牌顺序。准备输入来自原生合法动作表，并保留精确前缀与派生局面；同 seed 的分支整组
划分训练与检验。模型输入使用实体 schema，不含原始 RNG；它不能精确区分所有将来的
随机映射。检验预测和选择先冻结到磁盘，再运行检验续打。除整体误差，还单独统计结果
不同的候选组，避免大量同结果组掩盖不会取舍的问题。所有结果和生产者版本进入新 artifact。

```powershell
cargo build --locked --profile dev-opt -p sts_guided_search --example continuation_value
.\scripts\py.ps1 tools/guided_search/entity_continuation_trial.py --output <fresh-directory>
```

## 独立候选续打资源试点

[`entity_resource_pilot.py`](entity_resource_pilot.py) 从新构造的 SlimeBoss/Looter 战斗采样
真实候选，以现有实体编码学习固定工作预算下的完成概率及完成时的血量、钱包加待领取失窃
金币、击杀/逃走出口。未找到完整打法只监督“本预算未完成”，不监督死亡或终局资源。
当前固定保留药水，不能据此声称学会药水价值。整场 seed 划分训练与检验；冻结模型的预测
和每组两个候选先写入 artifact，再执行检验续打。对照使用抽样池中原保留侧的前两个候选
及当前血量的前两个候选；这是离线预算分配试点，不接入生产 beam，不代表完整原搜索。
原生编码、推理、采集、训练与续搜成本分别记录，选择结果保留具体资源，不兑换金币与血量。

运行：`.\scripts\py.ps1 tools/guided_search/entity_resource_pilot.py --output <fresh-directory>`。
范围、来源、权重、预测和实际结果保存在新 artifact；普通战后奖励不在此金币目标内。

## 策略与价值的实际出牌循环

当前循环入口是 [POLICY_ITERATION](POLICY_ITERATION.md)：从当前代码新采示范，训练实体
策略/价值网络，以有限 PUCT 选择并实际执行动作，保留根动作访问分布与实际终局回报。
每代先让学生实际打完新战斗，每场抽取一个决策点，从它的真实状态调用 solver 续搜。
教师续打与学生原续打比较实际终局资源，保留更好的胜线用于教学；没有胜线则不制造
动作标签。动作网络同时继续练习本次运行的初始化示范。搜索的试探访问、估值和
直接终局结果单独保留。再固定更新后的策略，以当前
搜索玩家实际打完战斗的结果训练价值网络；旧价值标签不混入新一代。
它使用具体敌方效果输入，覆盖声明的普通怪、精英与 Guardian 构造任务。后续教学和续打
交叉变化初始血量与攻防牌比例。教学使用实际打通的续线；实际出牌仍由有限 PUCT 决策，
不要求先解完整场，也不读取旧实验数据。合同见链接，结果保存在 artifact。

## 条件资源评价试验

[`resource_value`](../../crates/sts_guided_search/src/resource_value.rs) 是显式启用的
小型 ReLU 网络，由 [`retention_learning.py`](retention_learning.py) 拟合并导出 JSON 权重，
Rust 原生推理。当前仅接受 A20 Guardian、75 最大生命、空药水槽，以及代码声明的卡牌、
能力和遗物范围；它不是全怪物模型。模型在搜索开始时冻结并校验，不改变合法动作、精确
状态去重、回放或完整终局资源比较。

输入包括形态阈值、累计伤害、意图、双方能力、卡牌类型和 SharpHide 的出牌触发关系，
以及卡牌种类、升级、正在选择的牌、各牌堆位置摘要和接下来五张抽牌。位置摘要不是完整
牌序，原始 RNG 不进入网络；相同特征不表示相同状态，也不能据此合并搜索节点。这是使用
Oracle 局面的近似评价，不是 No-SL 观察。特征 schema 和有序名称同时随模型校验。

Schema 4 逐张保存最多十张手牌的身份、当前费用、可用性、逐段伤害请求、段数、格挡与
抽牌请求，以及敌方压力和变形差额等上下文。效果数值复用机制与卡牌计算；请求不保证最终
造成同样伤害或实际抽到同样数量，不能据此跳过模拟。空手牌位置全部置零。旧 schema 的
模型和数据需要重新导出，加载器不自动猜测或迁移。

待完成选择另保存模拟器给出的作用、来源牌区、选择数量上下限、能否取消，以及真实候选
的卡牌与升级计数；每张手牌标记其 lineage 是否在候选集合中。当前 pilot 只接受消耗、
升级手牌与把弃牌放回抽牌堆顶这三种选择，其他作用明确拒绝。候选不按牌名或位置猜测，
这些输入也不指定应该选哪张牌。虚拟选择仍使用原有的已选成员输入。

重放已有收据重新编码时，教师的输入、终点、回报与续打合同必须原样保留；编码器版本、
原文件摘要和独立重放来源另记。新编码产生的临时续打结果不能替换原教师目标。信息缺口、
选择完成前后的估值一致性与完整战斗资源分别检验，输入更完整不自动意味着搜索更强。

训练可显式加 `--hand-hidden 16`，用共享的小型 ReLU 层处理每张手牌，再把各维的总和除以十
及最大值，与原上下文一起输入价值网络。空位置在池化前屏蔽，不能贡献网络偏置。该结构
随权重导出并由 Rust 校验、原生执行；默认 `0` 仍使用平铺输入。牌序摘要仍留在原上下文中，
共享手牌表示只用于近似估值，不改变状态身份或允许合并不同牌序。输入表示、辅助误差和
实际搜索效果需要分别检查。

`--resource-model model.json` / `SolverConfig.resource_model` 用学习分数替换第四条
候选保留通道，保留原先攻击、防御、能力准备三条通道。各通道内部独立排序，没有把网络
输出与原评分数值相加。`resource_evaluations` 计实际用于保留的推理次数；推理耗时包含在
搜索时间限制中，逻辑工作量仍统计模拟转换与回放。候选池没有超宽时不请求估值。
原有回合响应 inspection 仍只支持原评分通道；普通参考路线审计使用实际启用的评分。

先准备符合上述范围、彼此独立划分训练和评测 seed 的 `combat_solver` 输入，然后：

```powershell
cargo run --release --locked -p sts_guided_search --example combat_solver -- --input <training-cases.json> --output <new-collection-directory> --work 50000 --value-data-work 1800 --value-continuation-work 2000
$valueInputs = (Get-ChildItem -LiteralPath <collection-directory> -Filter '*-value.json').FullName
.\scripts\py.ps1 tools/guided_search/retention_learning.py --input $valueInputs --output <new-model-directory>
cargo run --release --locked -p sts_guided_search --example combat_solver -- --input <evaluation-cases.json> --output <new-results-directory> --work 50000 --resource-model <model-directory>/model.json
```

离线采集复用真实 solver 的胜线、败线和保留前缀，并增加实际执行的被动续打对照。
`--value-data-work` 限制额外的完整单步分支展开；非零 `--value-continuation-work` 为至多
64 个按索引均匀选出的真实候选各提供这么多续搜工作。采集不是线上搜索预算的一部分，
其模拟、独立回放、续搜工作量和耗时分别落盘。每行保留首次到达它的父行和真实分支，
每条实际打法独立重放；不同精确状态即使编码相同也保留为不同样本。JSON 中间数据可能
较大，采集范围应显式控制。整场、同源 seed 及其分支必须放在同一训练／评测分组。

可选 `--value-response-work N` 为上述数据追加一份全场共享的敌方回应展开预算。
它在续搜轨迹采集后寻找真实回合入口、采集根，以及已有单步动作会改变 Guardian 形态
的分岔。回合入口沿实际来源链识别，包括新回合强制选择结束后的第一个玩家决策；不
合成手牌，也不要求入口已经能够用一张牌触发变形。

起点按行号的固定 SHA-256 顺序排列，不使用胜负或改变游戏 RNG。每个起点沿全部合法
动作深度展开到下一完整玩家回合或终局，再处理下一个起点；新回合的强制选牌必须完成。
精确重复局面共享展开，仍保留不同牌序和 RNG。优先完成局部动作图有助于产生完整回应
标签，但不保证预算内每个起点都能完成。该阶段不改变原续搜取样，也不按即时战损给
整场价值贴标签。

`response_work` 单独记录追加模拟量；`responses` 保存各分岔的展开完整性、未展开节点数、
边界数量及一条最好边界的行号，代表路线从采集根独立重放并计入 `replay_inputs`。
`source_expanded=false` 且备选为空表示起点自身的动作集也未能在预算内展开，不代表完成。
`witness_trace` 指向经过该来源和首动作的具体轨迹，不借另一条到达相同终点的路线代替。
完整性指边界前的动作图已展开，不保证所有策略都会终止；预算截断保留缺口。
训练直接使用真实单步图传播终局上下界，不把回合边界当终局。该选项默认关闭，且需与
非零 `--value-data-work` 一起使用。采集收据保留预算及生产者摘要。

终局胜利的回报为实际终局 HP / 75，真实败局为 -1；不以预算耗尽制造败局标签，也不把
败局轨迹上的非终局一律教成 -1。训练沿记录的精确状态转换、来源边和轨迹传播已完成
续打的最好回报，作为可达下界；部分动作的记录也能提供下界，但不证明最优。没有完整
续打相连的环不会自行产生结果；相同特征也不创建状态连接。

这个试验范围没有战斗回血，上界来自当前 HP 加可用战后回血；只有全部单步动作已实际
展开的节点，才能通过所有后继上界的最大值进一步收紧上界。该机制上界不能扩展到含
回血卡或其他回血效果的范围。初始训练惩罚超出上下界的预测；处于区间内不被拉向某条
差打法的结果。上下界重合时提供确定目标。后续在动作完整展开的节点，对上一轮冻结、
按各后继区间约束的预测取最大值，再约束到当前区间。无折扣；更多出牌本身不扣分。
这些训练区间有记录和机制依据，部署的网络输出仍是近似预测，不继承区间的保证。

可选 `--response-weight 1` 在共享隐藏层上增加仅训练使用的本轮回应预测头，默认 `0`
关闭。目标为当前物理资源上界减去本轮结束后可达的最佳资源边界；活着进入下一玩家回合
时使用 HP 加可用战后回血，已终局时使用实际终局回报。因此它是资源损失，含死亡回报和
回血封顶的语义，不等同于原始受伤数，也不替代整场目标。

辅助标签从已记录的完整单步动作图计算，不仅取 `responses` 的起点。按来源回合截在
下一完整玩家回合或终局，新回合强制选择必须完成；可达任何未展开决策的节点不提供
精确标签。完整但没有可达边界的环不标成死亡；有边界时取可达的最佳结束结果，不声称
所有策略均会结束。不同精确行、不同 case 分别计算。此提取不额外运行模拟器。

辅助任务每次更新单独抽 128 行，先等概率选含标签的 case，再等概率选其中的行；使用
独立采样随机数，不改变终局任务的批次。终局头和共享层的初始参数也不因启用辅助任务
而变化。`fit.json` 分别记录整体与正损失样本误差、辅助权重、标签覆盖和训练器摘要。
可用 `--response-input <files...>` 单独指定辅助数据，保持 `--input` 的终局动作图、样本和
抽样不变，以隔离回应覆盖的影响；两份数据必须使用相同特征 schema，该选项要求辅助
权重大于零。辅助输入也记录独立的文件摘要，训练与评测仍需按整组 seed 分开。
`response-head.json` 仅供诊断，使用不同 objective，不能作为 Rust 的终局模型加载；
正式导出的 `model.json` 仍只有原终局头，不增加搜索时的网络尺寸或推理步骤。

`warm-model.json` 保存区间约束初始拟合，`model.json` 保存冻结后继训练后的模型；
`fit.json` 保存输入摘要、训练方法、实际成本、已记录结果的传播及约束统计。
`data_supervision` 将上下界重合的确定标签、只有区间的行及完整续打覆盖分开计数；
有阶段特征时另列非终局玩家决策，不把终局行数量当作早期决策的监督量。
每阶段的 `history[].supervision` 另列冻结网络产生的自举点目标，并分别计算确定目标
与自举目标的误差，以及当前预测触发／未触发的区间约束。自举目标使用本阶段训练前
冻结的网络，误差使用训练后的网络；区间宽度和误差沿用 HP / 75 的回报尺度。
这些统计不改变训练样本、目标或抽样，也不将图中相关行解释为独立样本。
`--mask-mechanisms` 是去掉显式 Guardian
形态／意图／反伤关系的消融对照，导出时也清零对应权重。它仍能看到 HP、攻击预览等
间接信息，不能当作完全移除了机制信息。

训练误差小也可能只是多数约束太宽，不证明排名有效或已理解机制。验收要检查完整根状态
的实际战损、资源和含推理成本的时间，保留退步样本；较好的混合搜索不能证明模型已经
可以独立取代所有评分。权重由调用者显式提供，默认搜索不加载模型。

### 固定续打后果学习

[`continuation_value`](../../crates/sts_guided_search/examples/continuation_value.rs) 采集上述
Guardian 范围内的实际续打。输入为 `[{"label": "...", "group": "seed-...", "spec": ...}]`；
`spec` 使用 `ConstructedCombat`，同 seed 的不同卡组、血量等干预使用同一 `group`。
原局与自然来源认证不参与这个构造试验。

战术对照固定为 `RetainedCombatTacticalPolicyV1` 的动作权重 argmax，平局取来源顺序第一项；
结构选牌使用现有 typed cursor 和成员权重，超过 64 个具体输入则明确报错，不截断动作集。
它不修改策略、不用模型选择动作，也不消耗 actor RNG。

默认 `--solver-work 10000` 在每个训练局面独立新建无模型 `CombatSolver`，使用原有默认搜索
配置和零用药合同。采集器比较搜索已验证的、长度不超过 `--max-inputs` 的完整胜线与实际
战术续打。采用真实终局 HP 更高的打法，平局保留战术；每个起点只依赖当前局面和
声明的冻结续打器，不使用来源轨迹已经找到的胜利后缀。兜底战术与搜索都禁止主动用药
与丢药；Fairy 等自动效果仍由模拟器执行，不能将零主动用药读作绝对库存不变。
搜索未找到完整方案时仍执行战术到实际终局，预算不足本身不产生死亡标签。
搜索若在确定工作额度前触及十秒保护上限则报错，
不混入不同工作额度的标签。每条收据保存搜索统计、所采用来源及完整战术对照。

战术路径和从原根采用的搜索路径共同提供采样局面；除了输入序号间隔，还采集实际强制
选择边界与每个已观察回合的首个完整玩家决策，并展开这些来源的全部单步备选（含 EndTurn）。
选定的根打法会影响覆盖，不声称是无偏状态分布。精确相等的状态保留首次来源；不同状态
不会按特征合并。原根之外先在普通玩家与待完成选择阶段之间轮流取样，各阶段内部再轮流
取不同回合；同组成员按输入前缀 SHA-256 排序，不读取续打结果、不消耗游戏 RNG。
默认每场至多 32 个独立搜索起点，含原根；`--max-anchors 1` 仅采集明确提供的起点。每个被选局面独立调用续打器，
只标注该次调用的起点；沿搜索胜线的其他状态不自动继承原根结果。备选的前置局面也不能
获得该备选的续打标签。

`--solver-work 0` 保留纯战术续打采集，非终局后缀可使用同一确定策略的终局回报。

每条轨迹从原根独立重放，核对整个续打状态序列，含牌序、实例和 RNG；保存前缀、续打输入、
完整 endpoint 和采集二进制 SHA-256。只有非终局决策行参与学习。终局胜利回报为实际
HP / 75，实际死亡为 -1；达到输入上限而未终局的行保留为截断，不提供死亡目标。
同一编码下不同真实局面的结果分别保存，不合并成最好结果。

[`continuation_learning.py`](continuation_learning.py) 直接回归指定续打器实际采用打法的回报，
复用现有共享手牌网络和 Rust 权重格式，不使用区间、最优值标签或 max 自举目标。
训练和评测不得共享 `group`，且必须使用相同采集二进制与续打合同。
当前 Guardian 标量续打导出 objective 为 `guardian_solver_plus_tactical_return_v1`，要求
每行 offset 为零。实体编码同时保存在每行的 `entities`，以 `entity_schema` 与
`entity_objective` 单独声明合同。实体范围以共享编码器为准；超出旧 Guardian 标量范围时，
`feature_schema` 为 null，旧标量训练器拒绝它，不把空特征当作可用输入。新 trial 不读取旧数据。
纯战术续打使用 `guardian_retained_tactical_argmax_return_v1`。这些续打目标都可通过原有
`--resource-model` 接入；默认搜索仍不加载模型。该值描述指定续打的表现，不是最优战斗
价值，也不能据此判定其他打法不行。对照研究可从每条搜索收据的 `tactical_control` 投影
同一起点的纯战术数据；必须同时替换输入、endpoint 和回报，并声明对应续打合同，不能
只换标签而保留另一条打法作为来源。

`continuation_value` 的构造 case 可另给 `prefix`，先从原 `spec` 精确重放到指定中途局面，
再独立采集续打。收据保留构造、准备前缀与派生 root；轨迹中的 prefix 从派生 root 起算。
同初始化 seed 的准备分支仍归同一 group，不能借准备前缀把它们分到训练和评测两边。

采集可显式使用 `--resource-model model.json`：模型文件只读一次，冻结到本次所有根搜索和
独立续打，搜索选择的实际路径也参与下一批局面采样。续打合同保存权重 SHA-256 与 objective；
无模型默认行为不变。模型推理计入搜索耗时；固定 work 标签若触及十秒保护上限仍报错。
每行目标仍来自该行起点的实际独立续打，不直接复制预测或原根的胜利结果。

```powershell
cargo run --release --locked -p sts_guided_search --example continuation_value -- --input <train-cases.json> --output <fresh-train-directory>
cargo run --release --locked -p sts_guided_search --example continuation_value -- --input <eval-cases.json> --output <fresh-eval-directory>
$trainingInputs = (Get-ChildItem -LiteralPath <train-directory> -Filter '*.json').FullName
$evaluationInputs = (Get-ChildItem -LiteralPath <eval-directory> -Filter '*.json').FullName
.\scripts\py.ps1 tools/guided_search/continuation_learning.py --train $trainingInputs --eval $evaluationInputs --output <fresh-model-directory>
```

[`continuation_iteration.py`](continuation_iteration.py) 顺序连接采集、资源曲线拟合与下一轮
模型辅助采集。每轮训练和验证使用相同冻结教师及独立 seed；各轮数据分开，不混合不同教师
的目标。当前每轮从固定初始化重新拟合，未引入历史回放池或热启动。完整战斗使用第三组
独立 seed，所有轮次完成后才比较无模型、可选初始模型和各轮模型，不根据它挑选训练配置。
输入训练／验证使用上述 case 格式，完整战斗使用 `combat_solver` 的 constructed case 格式。

```powershell
cargo build --release --locked -p sts_guided_search --example continuation_value --example combat_solver
.\scripts\py.ps1 tools/guided_search/continuation_iteration.py --train <train-cases.json> --validation <validation-cases.json> --combat <combat-cases.json> --output <fresh-iteration-directory> --collector target/release/examples/continuation_value.exe --solver target/release/examples/combat_solver.exe --rounds 2 --solver-work 10000 --seconds 0.6
```

`--bootstrap-model` 可指定初始教师模型；默认首轮无模型。`iteration.json` 记录命令、来源摘要、
各轮教师／学生、实际训练结果、采样前缀变化与完整战斗资源。失败保留已完成阶段和日志，
不自动修改合同或恢复运行。预算内未找到胜线的场次单列，不当作已确认死亡；HP 差值只比较
共同找到胜线的场次。同时间对比按方案串行运行，含推理成本，但仍受机器计时波动影响。

收据比较共享手牌网络、线性模型、训练均值和当前血量上界，并单列前三个公开回合与未见卡组。
模型的 `turn` 特征仍使用零起始内部计数／20；前三个公开回合对应内部计数 0、1、2。
包含 `pending` 特征时，另列待完成决策和普通玩家回合的样本数、覆盖 case 数与误差；
只使用已完成续打的目标，避免总体误差掩盖稀少决策阶段的失准。
回报误差包含生死判断，不能换算成 HP 误差。预测测试与实际完整搜索的资源、耗时分别检查；
较弱续打方式的局限、表示丢失的信息与数据覆盖都可能限制模型的用途。

### 具体方案的联合后果

[`plan_consequence_data`](../../crates/sts_guided_search/examples/plan_consequence_data.rs) 从上述
固定续打收据提取一、两回合的具体打法。每个目标向量属于同一次真实重放的同一个终点，
包含 HP、力量、敌人 HP、各卡种消耗堆数量的变化，以及胜负边界；不会逐维拼接最好结果。
提前终局使用实际终点；未到达请求回合且未终局的窗口不提供目标。强制选牌未完成时不算
下一完整玩家回合。每条保留方案从原根重建起点，再独立重放并核对完整终点及联合目标。

输入为既有 Oracle 局面编码、请求 horizon，以及有序的具体动作。动作按真实前状态的
CardLineage 绑定源卡；卡牌数值、所在区域和位置均冻结在方案起点，不输入执行后的费用、
升级、伤害或资源。具体动作本身已经包含未来要打哪张牌的信息，因此该任务是已知具体
方案的条件预测，不是未知牌序下的可执行计划生成。引用源局面尚不存在的生成牌时，
明确排除该窗口并记数。每 case 有界采样优先保留同一起点／horizon 的多个方案，然后按
来源摘要排序；成员排序与取舍不读取后果。收据保存原文件和生产者摘要、重放量及耗时。

[`plan_consequence_learning.py`](plan_consequence_learning.py) 对比只看局面、忽略动作顺序、
使用小型 GRU 编码顺序三种网络；它们预测联合目标，不产生偏好标签。训练与评测按 seed
隔离，同 seed 的卡组干预保持同组。各目标使用训练集标准差缩放损失；恒定目标使用 1。
误差按 case 汇总，另列资源确实发生变化的样本、一／两回合、未见卡组，以及同源不同
方案和相同动作集合不同顺序的覆盖与差异误差。预测仍可能违反物理约束，不作为可达
终点、价值上界或搜索评分，也不代替模拟器。权重仅供 Python 诊断。

```powershell
cargo run --release --locked -p sts_guided_search --example plan_consequence_data -- --input <continuation-case-files...> --output <fresh-data-directory>
.\scripts\py.ps1 tools/guided_search/plan_consequence_learning.py --train <train-data-files...> --eval <eval-data-files...> --output <fresh-model-directory>
```

精确模拟耗时只计给定起点的局部方案；网络同时记录单方案与 128 批量推理的成本。
网络计时从已编码输入开始，不含编码、候选生成或搜索成本，不能将其直接读作搜索加速。

### 保留资源目标的续打预测

[`resource_curve_learning.py`](resource_curve_learning.py) 使用相同的固定续打收据，学习
“指定 executor 获胜且终局至少保留 H 点血”的概率。H＝0 是获胜目标；正整数目标只从
当前物理资源上限内均匀取样，标签来自同一次已完成续打的真实终局，不比较动作偏好。
来源仍等概率选 case，再选该 case 的行；目标取样使用独立 RNG，不改变来源取样。
截断续打不提供失败标签，搜索预算不足不能解释为局面无解。

共享局面／手牌网络产生截距和非负斜率，概率随保血要求单调下降，超过机制上限直接为零。
`resource_goal_probability` 对已观察到的准确胜利或死亡返回实际结果；未终局才请求网络。
只持有编码的调用方使用 `resource_goal_probability_features`，负责保证这是未终局决策。
`resource_curve` 权重头只搭配 `guardian_fixed_executor_resource_curve_v1` objective；旧 scalar
模型不提供目标概率。特征 schema 和卡牌／怪物／药水范围沿用原 Guardian 模型。

`ValueModel` 将整条目标曲线积分为期望回报的连续近似：实际续打死亡的回报仍为 -1，获胜
资源仍用 HP / 75。整数目标间的平滑插值不是精确的离散血量分布。这不是选择固定保血
阈值；预测也不成为胜线或资源界限。Python 与 Rust 共用
这个计算合同，Rust 不运行 Python。启用仍使用既有 `--resource-model <model.json>`。
训练命令的 `--train`、`--eval`、`--output` 与固定续打训练器相同。评测单列获胜目标和
每行全部可行整数保血目标的 Brier 概率误差，再按 case 汇总；实际搜索另比固定工作额度
及包含推理成本的同等时长。概率描述声明的续打方式，不是最优策略或 NoSL 的通关率。

离线 `combat_solver` 同时接收 `plan_proposals` 与 `--resource-model` 时，另存
`plan_value_predictions`：按真实输入边界重放的编码与估值，已确认终局单列实际回报且不调用
网络。`prediction_elapsed_ms` 单独记录离线诊断成本；`--work 0` 也可仅重放给定方案。
给定打法的后果不自动成为指定 executor 的标签，估值沿路径变化也不能直接判定动作优劣。

## 无模型整场求解

[`CombatSolver`](../../crates/sts_guided_search/src/solver.rs) 接受稳定的
`CombatPosition`，直接展开模拟器动作，跨回合保留候选并逐步扩大搜索宽度。
它独立于现存指导树、Atomic 搜索和固定策略续打。状态转换与组合选牌使用现有模拟适配器；
终局资源比较使用共享 `sts_combat_outcome`，不另设一套药水或遗物价值语义。

```rust,ignore
let mut solver = CombatSolver::new(position, SolverConfig::default())?;
solver.advance(50_000, Duration::from_secs(5))?;
let alternatives = solver.plans();
```

`sample_candidates(max_groups, candidates_per_side)` 可在搜索前启用有界观察采集。
它直接采样主搜索真实筛选后的保留／省略两侧，不需要参考胜线，也不增加引擎工作。
组间使用独立于游戏 RNG 的确定性 reservoir；组内每侧只取声明数量。真正的 PendingChoice
可以保留，尚未提交的虚拟选牌组装不能导出为裸局面。`candidate_samples()` 只读，返回
精确局面、根相对动作、已用药、来源筛选池／工作时点及保留状态。离线 `combat_solver`
用 `--candidate-samples N` 写独立的 `case-XXX-candidates.json`，每侧最多四个候选；默认关闭。
续打标签另行使用原整场求解器和显式预算产生，不由保留／省略状态推断优劣。

离线 `combat_solver` 同时在 artifact 中记录 `root_entity_admission` 和
`plan_entity_admission`：用当前实体编码检查根与已找到打法的每个真实稳定决策，
失败保留输入偏移和原因，终局单独计数。检查与重放耗时单独记录，不进入搜索预算，
也不改变候选或阻止无模型搜索。第一幕三种 Boss 已检查其 controller 输入，
包括 Slime Boss 分裂后保留的父实体与 Hexaghost 的点火、Burn 升级及锁定 Divider 伤害。
编码准入不代表旧权重学会了新支持的机制。

`advance` 追加工作，保留尚未完成的动作展开和回放。找到胜线后继续改进；
只有通过独立回放、完整后继相等检查的路线进入 `plans`。候选筛选可以先比较观察到的
终局资源，避免对已经被已验证路线压倒的结果反复回放。搜索与回放共同计入工作预算，
时间预算在操作边界协作检查。完整结果保留不能互相压倒的血量、具体药水及持久资源选择。

启用原有 `refine_potion_plans` 时，所有已保留胜线（包括修改得到的胜线）优先检查已有
弃药动作的删除。沿原路线重放改变后的后缀，再从根独立验证；资源比较仍由共享 outcome
负责，需要为 Entropic Brew 腾槽的弃药不会被一律禁止。检查可暂停，全部转换和重放计入
原预算，不新增配置或额外预算。普通插药、用药删除和出牌换序仍由原改进任务处理。

同一个求解器的宽度轮次和药水／纯卡牌搜索共享有界的精确转换图；完整局面、RNG、
有序选牌前缀及累计显式药水支出都参与身份核对。仅缓存已完成转换，命中仍计一次
`search_transitions` 和原轮次额度，只省去模拟器执行；最终独立回放不使用缓存。
容量从已有最大宽度导出，不增加配置开关；淘汰只丢失复用机会，不产生失败判断。

完整回放通过后，实际终局资源沿仍留存的转换反向传播，每个种子或入边处理计入
`result_backup_work` 和 `stats.work()`，与普通搜索交错、可暂停续接。每个精确局面最多
保留八个实际资源结果，转换、结果记录和传播队列均有容量限制；限制丢失的是指导信息，
不会删除已发布的 `plans`。已传播边记住资源前沿，结果记录淘汰后环也不会无限传播。
这些已验证的可达结果既安排尚未展开的分支，也进入候选保留：仅有实际结果的候选参加
一条领先的资源通道。该通道只提名未被其他已知资源前沿严格覆盖的候选；前沿互相覆盖时
只提名池中第一个候选，避免同一份可达结果沿多个前缀反复争取名额。比较使用完整前沿
及显式支出约束，不把血量、药水或遗物拆开取各自最好值。
被省略的提名仍完整参加原有五条评分通道，精确状态、牌序和未来展开不被合并；已知结果
被覆盖不证明该候选的后续潜力更差。资源通道与原评分通道逐名次交错争取同一份宽度和
上下文名额，不增加保留容量。
没有结果的候选继续参加原有通道；没有可用结果时，保留顺序保持原样。可达结果不证明最优，
领先通道也可能挤掉尚未发现更好后续的候选，首次胜线出现前不能提供这种指导。
纯卡牌搜索不借用后缀还需要显式用药或弃药的结果，被动消耗仍遵循共享资源语义。
`backed_retention_batches`、`backed_retention_candidates` 记录有指导的批次和候选数，
`backed_retention_nominations`、`backed_retention_suppressed_nominations` 记录实际提名及
只从资源通道省略的重复或被覆盖提名数；这些数量不是状态去重或候选删除数。
`backed_retention_selected` 记录经资源通道获得名额的次数，不表示这些候选原本一定会被筛掉。
缓存命中、淘汰、回传更新和分支重排另行计数；子求解器各自拥有图。

同一张图也保留已执行到的、未结束战斗的玩家回合起点，向前缀回传最近两个未来回合的
续接估计。每个估计关联完整真实 endpoint、原根输入轨迹和累计药水支出；实际 HP 与
endpoint 上尚未回应的下一回合压力分别记录，不把局部估计冒充终局资源或最优上界。
每个 horizon 分别保留五条评分通道的实际 endpoint 极值，纯卡牌与自由用药各保留一组，
不把不同 endpoint 的资源拼成一份虚构结果。回传按入边和目标回合合并待处理更新，读取
最新有界集合。一个有界整理批次最多处理五个种子或入边集合，计一次
`boundary_backup_work`，它是 `result_backup_work` 的子集；实际处理次数另计
`boundary_backup_operations`。批次不模拟动作，也不越过队列里的终局回传；暂停续接、
总预算及每批次间的时间检查仍适用。总 work 是确定性工作额度，不是统一 CPU 成本。

这类证据直接修正原五条通道中的相对排名，不新增保留通道、搜索宽度或子求解器：仅在
同源候选都有同一未来回合的观察时比较其完整估计集合，只有一方在全部续接目标及显式
药水支出上覆盖另一方的集合，才调整它们原有的位置。每份覆盖由一个真实 endpoint
承担；血量与输出的真实取舍仍由原有通道分别保留。未观察候选保留原位置。
不同 horizon 不直接比较数值，较深的共同 horizon 可进一步修正排序；同分或不可比保持
所在 Pareto 层内的原顺序。完整估计集合的覆盖仍是启发指导，不是未来潜力的支配证明。
它利用搜索已发现的续接机会，不能替代首次展开前的启发式，也不证明被省略路线更差。
`observed_turn_boundaries`、`boundary_backup_updates`、`boundary_updates_coalesced` 和
`boundary_retention_comparisons/reorders` 分别记录观察、更新、合并及排序使用情况。
离线 retention inspection 的 `observed_boundaries_after_search` 导出搜索结束时仍可用的
endpoint 和可独立重放的原根输入；它不是筛选发生当时的证据快照。

虚拟选牌的开始和逐个成员选择只组装一个真实提交，不改变游戏局面。默认搜索复用
动作完成游标，将这些内部步骤推进到提交后的实际效果，再参与评分保留；不为每个
内部成员额外设置一层分数筛选。可提交的前缀仍保留继续选成员的合法分支，一个结果
完成后其他组合按原队列续接，不先枚举完全部组合。虚拟步骤与真实提交均单独计费，
暂停、截止时间、回合额度、任务容量和独立回放仍生效；真实待选牌界面的准入仍按原
保留路径，因此这不等于启用下方的完整动作实验。

可选 `SolverConfig.shuffle_continuation_work`（默认 `0`，关闭）启用自动调序改进；离线入口用
`--shuffle-work 2000` 设置每个候选的续搜工作上限。它从求解器自己找到并完成独立重放的胜线
提取连续出牌片段，不要求人工提供路线。与下方离线探针共用
[`shuffle_order`](../../crates/sts_guided_search/src/shuffle_order.rs) 的动作追加段、实际洗牌映射与候选逻辑。
每个片段最多六个动作，保留原序作为续搜对照；候选只移动整个出牌动作，不修改牌堆。

有活动调序任务时，普通搜索与调序按工作单位交错服务，共用 `advance` 的总工作量与截止时间。
来源重放、调序前缀、原后缀尝试和子搜索（包括子搜索自己的重放）计入 `shuffle_work`；
最终从原始根独立重放仍计入 `replay_transitions`，`stats.work()` 汇总普通搜索、回放及所有改良工作。暂停保留所在阶段，
`shuffle_progress()` 只读活动任务，不推进工作。子搜索禁止额外用药并关闭自身调序，
新产生的调序胜线不递归创建任务。只保留仍在资源前沿上的待办来源；已开始的任务按原额度继续。

每条来源先检查全部调序前缀和原后缀提案，随后依次续搜已保存的真实洗牌后局面；
不会因第一个候选的长续搜而延后其他候选的低成本检查。只有完整局面（包括 RNG、牌堆顺序）
与从同一根累计的显式药水支出均相同，才共用一次续搜；原后缀提案仍分别执行。
队列增加了保存局面与前缀的内存，但同时只保留一个子求解器，不为每个候选常驻搜索树。
`queued_continuations` 表示当前排队局面数；`shuffle_continuations_queued` 与
`shuffle_duplicate_continuations` 分别累计实际入队数和省去的重复续搜数。
`shuffle_source_work`、`shuffle_prefix_work`、`shuffle_suffix_work`、`shuffle_continuation_work`
是不相交的实际工作量分项，之和等于 `shuffle_work`。这项调度取舍不保证给定总预算下的终局质量。

调序前缀沿用原轨迹的具体药水；整条候选也不能比来源多消耗药水或改用另一瓶起始药水，
包括被动消耗。每条新路线必须完整重放并核对后继，再由同一个资源比较入口保留，不能只按 HP
覆盖原路线。`origin.shuffle` 记录来源胜线的工作时点、可从根重放的原输入和资源结果、
出牌片段、实际排列和后缀生产方式；
此时 origin 的宽度等原搜索字段指向来源胜线。`shuffle_observed_wins` 与 `shuffle_retained_plans`
分别记录提出的完整胜线和通过最终保留的路线。交错分配可能挤掉普通搜索的有效工作；此功能
尚不默认启用，不保证相同总预算下更好。仍是完整状态 Oracle 搜索，不代表通过 SL 学到了映射。

可选 `SolverConfig.order_family_work`（默认 `0`）用短续搜比较临近洗牌的同分候选；
离线入口 `--order-family-work 256` 指定每个候选的子搜索额度。它直接读取实际筛选批次，
不需要参考线或先找到胜线。只有当前没有合法可打牌、抽牌堆空、弃牌堆至少两张的稳定玩家
局面参与；不强制结束回合，也不禁用主搜索里的其他合法动作。

分组要求全部保留通道分数相同、同回合的玩家及敌人 HP/block 相同、累计显式消耗相同，并通过
手牌属性、能力、遗物与存留/消耗牌组成的上下文检查。每组必须同时包含保留代表和被筛变体。
每批由各评分通道提议一个最高组，重复冠军只提议一次；组内先保留代表后被筛变体，最多取
当前 width 个。每个 pass 的待办不超过 `width * 8`，入队时检查待办内的完整状态和支出重复。
组只是预算分配提示，包含牌序、RNG、身份的完整状态始终各自保存。

已经完成额度或自身搜索日程的子根，进入全求解器共享的近期缓存，最多 `max_width * 8` 条。
不同父搜索宽度会给子求解器相同配置和额度；因此完整搜索状态、原根累计显式支出相同，且
旧前缀不比新前缀长时，跳过已经做完的相同续搜，计入 `order_family_cached`。更短的新前缀
仍可竞争等资源路线的动作数。缓存只记已完成的计算，不表示该局面没有更好的打法；暂停中
的子搜索不入缓存，缓存淘汰后允许重做。它不合并不同牌序，也不改变主搜索的状态去重。

全局同时只运行一个子求解器，在各 pass 间轮转取任务，并与普通工作交错。子搜索不新增用药，
也不递归开展调序、同分组续搜或胜线编辑；其搜索与自身回放计入 `order_family_work`，最终
原根回放计入 `replay_transitions`。完整路线按原根重新核算全部消耗，并用共享资源前沿验收。

启用 `tactical_attacks` 时，每个子搜索只在首个宽度实际走到下一回合、首次展开其手牌时，
额外提议一次下述短攻击计划：每个正在进攻的目标至多一个组合。沿用原根和真实抽牌流程，
不另开免费预演；出牌、子回放仍在同一额度内。普通手牌根继续保留，计划执行也沿用原来的
可暂停、逐步验证和回合额度。首次到达的是待选牌画面时不提议，也不延后到别的手牌补做；
后续回合与其他宽度仍使用普通搜索及原有的筛选后战术提议。这只是帮助兑现当前已抽到的
击杀组合，不给未知抽牌或后续手牌组合估值，不证明更早击杀一定更好。

`origin.order_family` 记录实际入队时点、来源前缀长度、组评分、组大小与成员位置；`progress()`
和 `sample_prefixes()` 包含待办来源。未找到胜线不构成负标签，保留代表的续搜收益也不等于
调序收益。这是完整状态 Oracle 实验，可能挤占主搜索预算，尚不默认采用。

真实输入链增量保存共享 outcome owner 的显式药水消耗统计；预筛终局时无需复制和重扫
整条出牌记录。统计包含丢弃和同一槽位的重复使用，被动消耗仍结合起点与终点库存计算。
这个统计服务于终局预筛和下述显式支出上限过滤，不是状态身份或回放证明；选中路线仍完整
重放，并从实际输入重新计算资源。每个真实动作节点多存一小份统计，不另复制整条输入链。

整场求解的 `max_potion_uses` 是最终资源支出的上限。显式喝药和丢弃的累计次数是它的
单调下界；达到上限后，在展开前排除进一步喝药、丢弃的动作，避免把已经无法验收的路线
继续打到终局。`resource_limit_actions_skipped` 记录这种排除；它不消耗模拟转换预算。
仍允许额度内的丢弃。被动消耗继续由共享终局资源投影核验，不把暂时的库存差直接当作
所有情形下的单调支出下界。

`progress()` 只读取各宽度轮次的实际搜索量、主阶段状态与队列计数，不会准备或推进工作。
离线档位记录保存这些数据；胜线的 `origin` 记录产生它的宽度、药水族、是否来自备用续接，
以及独立回放前的观察时点和该轮次工作量。`found_at_work` 仍是回放完成后的总工作量。
这些字段用于诊断预算分配，不参与资源排名或状态身份，也不证明未搜索范围的大小。

诊断时可在开始搜索前调用 `audit_reference(inputs, successor)`，或在离线 case 中增加
`reference: { inputs, successor }`。参考线必须从同一根完整重放到给定胜利后继，并满足同一
耗药约束；它只提供要观察的状态，**不会作为候选送进搜索**。输出 `audit` 按宽度和药水族
统计参考状态何时生成、展开、筛掉、进入备用、因满队丢失或得到续接，同时统计动作类别
及已经超出显式支出上限的前缀占用的搜索量。选牌的内部组装状态也逐步匹配；参考索引
包含这些虚拟步骤，不能当作真实动作编号。`inputs_completed` 给出已完成的真实输入数，
`selection` 保留当前家族和已选成员的 typed 身份，尚未提交时也能区分具体选了哪张牌。
显式提供参考线时，离线入口同时打印各宽度/药水族的简短进度：最大已展开真实输入号、
首次评分筛除的参考步骤及当时容量/各通道名次、该状态是否也曾展开，以及首次回合配额/
备用队列满的位置。参考步骤号可用于 `--inspect-retention`；不是实际动作编号。
生成、保留或排队不计作展开，首次筛除也不等于永久丢失；这些输出不改变搜索或采用参考线。

`recovery` 保留同一节点实际使用的回血/保护评分分量，以及带 lineage、区域、费用和消耗请求的
回血来源。当前手牌的条件保护提示不要求持有回血或复活资源；共用费用、出牌限制、补费付血和
损失的回血储备沿同一回应计算，不借用尚未抽到的牌。它用于生存通道的排序，不是存活证明。
`revivals` 列出共享致死触发 owner 返回的剩余 Fairy/Tail 来源、原始回血请求与
当前修正下从零血恢复的量；`credit.revival_reserve` 单独记录其总储备，不加入当前物理余量
或封顶健康提示。力量准备与回血来源之间的 typed 依赖记录：只改变当前 Strength 请求后，回血请求和
当前缺血容量如何变化、两张牌的合计支出是否缺费、是否都在手里；Flex 的 LoseStrength 单独记录。
这不是模拟后继、完整组合合法性、未来上手或存活预测；不会将这些条件请求加进评分或搜索队列。
该细化表示只在参考观察和候选检查时生成，普通搜索复用其来源与请求 owner，不逐节点收集依赖表。

参考节点与候选检查的 `draw_triggers` 单独记录当前生效的 Evolve／Fire Breathing 与现有
牌来源的关系：每个来源保留卡牌 ID、lineage、牌区、位置，以及共享抽牌触发 owner 生成的
typed 效果请求。手牌来源需要再次回到抽牌堆，弃牌来源需要洗牌；不预设这些过程必然发生。
手牌中的虚无牌、消耗堆与 limbo 不计作后续来源，也不补造未来生成的状态牌。
`draw_blocked_now` 与 `hand_slots_now` 保留当前抽牌限制；伤害请求尚未经过伤害承受机制，
额外抽牌请求尚未变成实际手牌、可支付出牌或后续收益。这些关系仅用于诊断，不加总为
评分，不改变普通候选保留、搜索预算或展开顺序；无对应生效能力时参考字段省略。

其中 `credit.protection_response` 记录耐久提示选中的来源：手牌格挡（含补费牌谱系）、
移除的进攻目标，或具体斩杀配方接格挡。`gross_protection`、`recovery_reserve_lost` 和
`play_hp_cost` 分别表示当前保护请求、损失的回血储备与所选出牌的血量请求成本，包含补费和
效果前的已审阅自伤，以及最终消耗前未被格挡吸收的出牌后伤害。当前已生效能力对打出牌最终
消耗的格挡请求沿共享触发 owner 读取；先检查较早伤害的致死条件，再计入这份格挡。新保护量
扣除已消耗的原有格挡后才按压力封顶，较早扣掉的血量单独保留；净信用仍作为诊断记录。
不借额外减伤、复活、其他牌消耗触发的格挡或未知抽牌后续。复制出牌的耦合时序不领取这份
最终消耗信用；独立多牌回应仍沿既有共用费用、次数和消耗抽牌限制处理。
`requested_hp_after_response` 单独保留未借回血的有符号余量，`conditional_health_hint` 则按
这份余量之后的缺血空间计入剩余回血；`conditional_endurance_hint` 保留可偿还后续战损的
完整条件储备，并用于第五通道。空值只表示未选中已审阅响应，不证明没有存活路线；
这些记录不是引擎后继或存活证书，也不证明任意多个响应能够共用费用一起完成。

匹配检查完整搜索状态，包括 RNG、牌序和选牌进度，不要求动作前缀字符串相同；第一处
筛除另存同批候选数、各评分通道在去重前的名次、同分数量及最多四条保留竞争者的可重放
输入链。`same_context_kept` 另存与被筛状态共用实际多样性分组的首个保留代表、虚拟选牌及评分；
没有这样的代表时为空。分组按当次手牌、效果和牌堆组成开关计算，不是状态等价或后续收益
相等。它用于区分“同一思路换了牌序代表”和“没有同组代表被留下”，不能只凭评分名次
断言某种效果被低估。`backed_returns` 保存当时可用的完整回传资源；`backed_kept` 最多列出
四个带回传结果的保留候选，不表示其名额一定来自资源通道。`kept_without_backed_guidance` 在
同一候选池上只用原评分通道重新筛选，诊断资源通道是否直接影响本次保留；这批对照节点
不进入搜索。启用模型时，`kept_without_resource_model` 在同一候选池中只恢复第四通道的
原评分，检查模型是否直接改变这次保留；现有图回传信息保持原样，不撤销更早的模型影响，
因此它是局部对照，不能解释为整场无模型搜索。只追踪指定参考线和主搜索轮次，不保存
整棵树，也不证明未命中参考线就找不到
另一条好线。`audit()` 只读；观察不改变同工作预算下的搜索，但会增加耗时和临时内存，
因此不能用打开观察后的限时结果冒充原性能。参考重放属于诊断准备，不计入搜索工作量。

要检查一次具体筛除，可在 `audit_reference` 后、搜索前调用
`capture_retention(reference_step, width, card_only)`，再在搜索后调用 `inspect_retention`。
离线入口对应 `--inspect-retention N --inspect-width W`，`--width` 仍只控制搜索最大宽度。
省略 `--inspect-width` 时观察最大宽度轮次；指定较窄轮次不改变其他轮次的启动或预算。
药水族默认自由用药族，
`--inspect-card-only` 改为独立只出牌族。只保存目标参考状态在该轮次首次被筛除时的整批候选；
精确相同且显式药水支出相同的候选去重，虚拟选牌组装候选计数但不续接。
每个候选的 `shares_reference_context` 使用当次真实保留分组判断它是否与参考节点同组；
输出同时记录 `context_effects` 与 `context_card_compositions`，不能从简写牌名反推分组。
同组候选可以再按已有保留通道评分筛出同分变体，用于检查牌序代表的续搜成本；
同组或同分都不是状态等价、价值相同或已穷尽的证明，也不改变生产搜索。
请求的参考步骤必须是实际输入边界。CLI 的参考 `successor` 可省略，届时先完整重建终点；
两种写法都必须通过同一胜利与资源约束校验，并另存可读的参考出牌记录。

检查使用独立预算，不给原搜索反馈：`--inspection-work 64,256,1024,4096` 为每个候选的
累计模拟转换档位，按广度优先枚举到下一次完整玩家回合或终局。沿用合法动作、保守动作等价、
药水限制及引擎，但不用束宽或评分裁剪；状态合并仍要求完整状态和显式支出相等。
新回合强制选牌须完成后才计入边界。输出枚举是否完成、耗时、实际转换数、重放成本、
可达边界的最高血量及对应敌人剩余血量，并从原起点重放代表路线。
最高血量仅描述该回合；不同评分通道的最大值也可能来自不同路线，不构成共同可达的收益。

若候选的旧抽牌堆为空，且最高血量后继只追加了一次 `EndTurn`，检查会另行观察这一次
输入的真实洗牌。`end_turn_shuffle` 返回经共享映射 owner 核对的输入牌、位置映射和已抽
张数，或不适用的具体原因；不猜测回合末弃牌、消耗和敌方生成牌的先后。额外观察单独计入
`shuffle_observation_inputs`，属于离线诊断成本，不进入原搜索预算，也不给搜索反馈。
这是 Oracle 信息；后续牌堆顺序不等于承诺未来按固定五张抽取，额外抽牌和置顶仍会改变窗口。

同一检查另存 `first_action`：只展开第一张牌或起点已有的强制选择，完成它引发的选牌后
即止，不继续利用新抽到的牌。入口排除主动结束回合、用药和弃药；被动药水消耗仍核算。
这让诊断能分开查看当前静态评分、一张牌兑现后的结果、下一回合和整场续搜。
该阶段独立使用 `--inspection-work` 的最大档位与 `--seconds` 限时，转换、引擎步数、

不为每次交换重开搜索。先按预算重建来源各动作前的完整状态，
再从对应前缀真实执行修改及后续；出牌按 lineage 重新定位，选牌要求原选择域不变，
后续药水要求原槽位与物品一致。新发现界面、失去的卡牌或非法后续会中止该候选，
不把旧结果套到新状态上；这不负责为发现类药水重新规划选牌，也不穷举多处联合修改。
提前击杀可截断剩余动作，胜线仍经原根独立回放与完整资源比较后才发布。

改良与原搜索交错执行：每轮药水族调度后给改良一步机会；来源重放和改变后的转换计入
`plan_edit_work`，最终回放计入 `replay_transitions`，共同消耗原有工作/时间预算。
同时只执行一个改良任务，待处理来源随已有资源方案的淘汰而移除；修改所得方案不递归
产生修改任务。`origin.potion_edit` / `origin.order_edit` 保存来源动作与修改位置，计数说明实际成本。
分配给局部改良的工作可能使原搜索错过另一条路线，不能声称结果单调改善。
可用 `--refine-potion-plans false`、`--refine-card-order false` 分别关闭两类修改作同预算对照。

同一改良任务在真实跨入玩家回合后，可以复用已经完成检查的固定后缀。复用要求完整
局面（含 RNG 和牌序）、全部剩余来源动作、显式药水支出一致，且已检查前缀不更长；
不同弃牌顺序不合并。每个来源游标与修改族／药槽只保留一个条目，暂停中的后缀不算
完成。固定提案失败也可省去重复检查，但不禁止普通搜索寻找其他续接；已覆盖的胜线
不重复发布，新资源结果仍从原根独立回放。`plan_edit_suffix_cache_hits` 记录复用次数，
省下的转换仍留在同一总预算中；这不为改后的打法重新规划后续动作。

中途保留仍使用有局限的多路启发评分。带 Fading 的敌人保留击杀进度一路，生存相关的
其他路不奖励削减会自行消失的血量；攻击通过 Shifting 等机制降低当前威胁时仍计入防御收益。
敌人持有 Barricade 时，剩余伤害工作量包含其当前存留格挡；削减护盾能在尚未伤及 HP 时体现进展。
普通会在敌方回合开始清空的格挡不计入这个跨回合工作量。Barricade 按实际能力存在判断，包含负数哨兵。
真实伤害绕过格挡的机制仍由引擎执行；独立生存通道只将伤害进展用于健康与持续能力相同后的比较。
Awakened One 的剩余血量项包含必经的第二阶段：第一阶段保留复活能力时，计当前 HP 加
实际最大 HP；已击杀但等待复活时仍计这份最大 HP；进入第二阶段后只计当前 HP。
复活能力按存在判断，不能把 Unawakened 的负数哨兵当作没有能力；等待复活以 half_dead
覆盖该能力已经被死亡流程移除的边界。不写死难度血量，也不给进入第二阶段另加奖励。
该项只修正四条原通道的剩余伤害工作量；第五条独立健康余量、当前可见攻击、真实状态
和资源比较不变。它不预测第二阶段招式、上手时机或战损，不类推到可反复复活的 Darkling
或血量依赖分裂时点的 Slime Boss，也不保证相同有限预算下所有路线改善。
这不预测长期胜率，也不修改状态等价、终局资源比较或真实游戏机制。

持续准备分中的力量与敏捷先扣除当前已声明的回合末回收量（LoseStrength 与
DexterityDown），下限为零；当前攻击和格挡仍读取完整即时属性。Artifact 在应用时
阻止回收状态，由真实引擎自然留下持续属性。这项准备分不预判后来清除回收状态或
阻止回合末负属性的情况，不改变原权重或给临时药水新增固定惩罚。

默认搜索会结算一种必经的阶段边界：刚生成的同回合局面仍非终局，但场上没有活跃敌人，
且沿共享合法动作表、当前药水族和显式用药额度检查后，只剩 `EndTurn`。此时将该真实输入
交给现有可暂停的动作完成队列，先到达下一阶段，再进入下一回合的评分保留；不在等待复活的
中间状态比较未来价值。结束回合、抽牌、复活和战损都由正常引擎结算，计入同一工作预算，
期限或工作量耗尽时不免费执行。仍有合法卡牌、选牌、用药或弃药选择时不走这条路径；
普通活跃敌人的回合末也不自动延伸。已有 `order_family_work` 实验显式要求保留洗牌前的
比较边界，仍沿该实验的准入路径。这个阶段结算不覆盖所有未来牌序，也不保证相同有限预算下
资源结果单调改善。其工作属于 `pending_action_work`，不算作可选出牌的 `followup_transitions`。

每类搜索都保留尚未完成的宽度轮次。最新轮次结束，或累计完成
`width × transitions_per_width` 次搜索转换后，启动下一个更宽轮次；已有轮次按最近服务
的先后轮流推进。每个轮次保留其部分展开的动作、选牌前缀和下一回合队列，不因升宽重开
或清空旧轮次，也不设置固定战斗回合上限。启动阈值只计搜索转换，内部回放仍计入总预算。
达到最大宽度后继续服务现有轮次。一个轮次完成自己的主搜索后，即可续接其备用工作，
与其他仍在主搜索中的轮次按最近服务时间轮转；不等待所有宽度、药水族的主搜索全部结束。
主轮次和备用工作都结束才返回 `ScheduleComplete`。
多个常驻轮次会增加内存；候选池仍各自按宽度限制，没有保存完整搜索树。

每个宽度轮次共用 `width × 8` 个备用槽位，保存未展开的节点或因回合额度暂停的工作游标。
游标保留普通展开的未执行分支索引、选牌任务的当前成员及祖先栈，或战术计划的执行进度，
恢复后不从源节点重做已执行分支。相同源状态上的不同未执行工作不能按状态去重。
游标优先于未展开的评分落选节点；满时移出最新的备用节点，若槽位已全为游标则拒绝新游标。
两类队列各按进入顺序保存，续接时先取游标，再取节点；节点仍按完整状态去重。
续接重新分配该段的回合额度，所有转换与独立胜线回放共同消耗调用者的原有预算。

续接与主搜索共享服务机会，会改变有限预算内各轮次的进度和资源结果。保存候选不保证
救回某条路线，也不扩大成完整覆盖。槽位上限不等于字节数、祖先栈长度或动作链长度上限。
`recovery_transitions` 是搜索转换的子集；`deferred_nodes`、`resumed_nodes`、
`deferred_limit_dropped` 与 `max_deferred_nodes_per_pass` 分别记录节点累计入队、续接、容量拒绝
或移出，以及单轮次备用节点峰值。`quota_cursors_saved/resumed/dropped` 记录游标的保存、
恢复和容量拒绝；`progress().deferred_cursors` 为当前游标槽数。`beam_dropped` 与
`turn_budget_dropped` 统计移出主队列的候选／游标源，其中一部分仍在备用中。
参考审计的 `work.transitions_by_turn` 按实际源回合计转换；它与 `quotas.by_turn` 使用引擎从零
开始的回合索引，`reference.turn` 使用从一开始的展示回合。每轮次最多保存 32 份 `quotas`，
记录额度截断时各回合的待办节点、战术任务及未执行分支数量。`cursor_saved/resumed/full`
与 `reserve_evicted_for_cursor` 事件定位具体参考前缀，不参与搜索决策。

两类搜索之间，默认优先服务下一次需要较窄宽度的一类，同宽时轮流展开；较复杂的一边
可以获得更多工作量，另一边完成全部轮次后，剩余预算用于仍在运行的一边。
这种宽度协调只决定计算顺序，不改变状态保留分数。
一边等待达到初始宽度的一回合工作额度时，会优先获得一次展开，避免长时间不结束的窄搜索
饿死另一边；这个等待量跨 `advance` 调用保留。
只出牌搜索过滤主动使用和丢弃药水，仍由模拟器结算 Fairy 等被动效果；实际消耗以终局
物化结果为准。`card_only_transitions` 是总搜索工作量的子集，不应重复加总。
这能保护一部分留药探索，也会分走自由用药搜索的预算；相同总预算下不保证所有路线都改善，
尚未分别保护每一种“用一瓶、留另一瓶”的中间选择。
诊断对照可设 `SolverConfig.balance_beam_widths = false`，或向离线示例传
`--balance-beam-widths false`，恢复按工作单元轮流分配，其他搜索规则相同。

`tactical_attacks` 默认开启；`--tactical-attacks false` 可用于对照。普通评分筛选后，求解器
检查保留候选是否已代表某个正在攻击的敌人的击杀机会，或已击倒它。代表须具有相同的完整
玩家能力、药水库存、累计显式支出及剩余回血牌库存；回血牌按谱系、牌种、升级和 misc 值
计数，包含手牌、抽牌堆与弃牌堆。这是配方准入的近似上下文，不是状态等价或长期价值证明。

未被代表的机会可从被筛候选中提出短攻击计划。优先使用当前手牌，每个目标最多提议一个
最省费用、其次最少张数的组合，沿来源手牌顺序尝试。没有直接组合时，另试一次简单抽牌
接攻击：读取末尾单个 `DrawCards`、前面仅有普通伤害或格挡的效果请求，在临时牌面上
核对费用、手牌上限、NoDraw 与剩余出牌次数，并复用同一个攻击组合算法。保留候选也按
这两种方式识别机会，避免重复补已有的抽牌衔接。

抽牌提议使用完整状态 Oracle 信息；旧牌堆抽空时，在私有克隆上调用同一弃牌堆洗牌函数，
抽牌牌本身在其效果完成前不进入弃牌堆。这个临时牌面不是引擎后继或搜索节点，不预测
抽牌触发、反应副作用或随机费用，也不新增免费引擎预演。它不能用作 No SL 的公开信息策略。

静态组合只是待验证的假设，不是击杀证明：攻击组合仅提议固定段数的定向或群体攻击，
不组合随机目标、X 费或新施加的 debuff；一次性伤害加成激活时只提议单张攻击。
每张牌仍按谱系和卡牌身份重新定位、核对真实合法性并调用同一引擎。计划中途不按标量评分
淘汰；击倒目标、需要选牌、自动跨回合或无法继续时，把实际局面交回原搜索。成功只说明
本回合中玩家存活且目标已倒下（含阶段性倒下），不说明整场最优或玩家无损。

短计划与普通展开交替服务，共用总预算和回合额度；每轮次队列上限沿用 `width × 8`。
配方筛选不合并不同 RNG 或牌堆顺序，原被筛候选仍按原规则进入有界备用队列。回合额度耗尽
时把未完成计划连同当前精确前缀交给同一有界游标备用机制。最终胜线仍完整独立重放并比较全部持久资源。
这一算子能保护短期目标，但准入上下文不估价长期准备、遗物计数或药水价值，也可能挤掉
其他好路线；直接组合仍可能挡住资源取舍不同的抽牌组合，未覆盖所有多步衔接。

`attack_plans_started`、`attack_plans_achieved`、`attack_plans_aborted` 和
`attack_plans_quota_stopped` 分别记录已启动、已击倒目标、无法续接和游标备用已满而停止的数量；
余下计划可从 `progress().attack_plans` 查看。`attack_plan_transitions` 是
`search_transitions` 的子集，不重复计费；静态提议的 CPU 时间仍计入实际耗时。
前缀采样包含 `AttackPlan` 队列；参考审计用 `attack_plan_queued`、`draw_attack_plan_queued`
和 `attack_plan_achieved` 定位真实路径，不把静态估算当作已产生的游戏结果。

同一战术队列还给当前回合的双放减伤组合提供执行机会。初始根与下一回合的正式保留批次中，
若实际手牌同时有技能双放、回能抽牌和针对当前攻击者的减力量／虚弱请求，提议两种顺序：
双放后回能抽牌再应对，或先用一次减益再双放、回能抽牌。后续只从实际到达的手牌中选择
减益或直接格挡，始终在同一回合内运行。不读取未来抽牌、预估 Artifact 的最终层数，
或给这些牌固定加分；每张牌都重新按谱系绑定、检查合法动作并计入原搜索预算。
完成既定前缀且没有后续防御请求时，实际局面交回原搜索；选牌、跨回合和失去来源也会结束
这条提议。普通分支保留，既有回合额度及 `width × 8` 队列上限继续生效。
`response_plans_started/completed/aborted/quota_stopped` 记录提议生命周期，
`response_plan_transitions` 属于 `search_transitions`；`progress().response_plans` 只读。
参考审计以 `response_plan_queued/completed` 定位实际路径。完成提议不表示无损或整场获胜，
最终胜线仍从原始根独立回放。`--tactical-attacks false` 同时关闭这些战术提议。

普通搜索遇到单张手牌，且按当前药水约束只有结束回合与一种具体出牌两个合法选择时，
先沿已有动作游标物化这两个分支，再把产生更宽选择的后继交回评分筛选。不强制出牌，
不读取未来牌堆来决定是否放行；不同目标或可用药水构成额外选择时照常筛选。
转换与回放仍计入总预算，回合额度和任务容量保持有效。`narrow_card_choices` 与参考审计
事件 `narrow_card_choice` 记录这种调度，不计作额外免费工作。

另有以下延迟收益实验开关，默认均为 `false`：

- `complete_actions` / `--complete-actions true`：一次出牌或用药引出的选牌由独立任务逐步
  完成，同回合内未完成的效果不参与即时分数筛选。普通出牌与选牌任务交替获得一个转换的
  工作机会；任务之间轮流服务，任务内部用保留游标的深度优先遍历产生完成候选，避免先
  展开整个组合乘积。已完成的候选可以继续出牌，不必等所有选牌任务结束。
- `follow_preparations` / `--follow-preparations true`：包含动作完成，并在实际后继出现新手牌
  选项或新的／增强的玩家能力（含载荷变化）时，延续同一个任务。后续动作若再次打开这些
  机会，就继续；完整动作不再打开机会、跨回合或进入终局时，把实际算出的后继交回主搜索。
  不增加某张牌的评分，也不从根另跑一次预演。它只提供尝试后续动作的机会，不证明下一张
  牌利用了这个效果，也不识别所有需要多步准备的组合。

`follow_preparations` 下，新任务先沿一个分支产生可交回的结果，随后未访问的兄弟分支
轮转服务；打开新机会的子分支沿用同一游标。这样普通出牌不会持续产生任务、让每个任务
都在完成第一个结果之前排很长的队。这里不会先枚举完所有选牌结果或整回合；每个虚拟
选牌步骤和真实输入仍逐一计费，`advance` 的暂停点不变。连续抽牌等机会链仍可能耗尽
回合额度，任务容量、备用限制和原有额度截断行为仍然适用。

`preparation_opportunities` 记录生成并请求续接的机会数；`followup_transitions` 是
`pending_action_work` 中从已经完成的动作后继续出牌的工作子集，两者都不能重复计入总预算。
`followup_transitions` 也包含默认的单牌小分支续接，不能单凭它判断实验开关是否启用。
对应参考审计事件为 `preparation_followup`。完整后继复用已计算的状态与输入链，终局仍独立
回放；既有药水约束和完整资源比较继续生效。开关会重新分配预算，可能牺牲其他出牌顺序、
药水选择或较大预算下的收益，不能把局部改善当作一般优势。

`complete_actions` 替代旧的全局选牌优先开关；旧实现保存在 Git。它仍共用原来的总预算、
回合额度和终局资源比较，每个选牌组装分支都计费。每个宽度轮次最多同时保存 `width × 8`
个选牌任务，满时新任务的精确前缀转入原有备用队列；不按半结算时的分数挑选任务。
任务数上限不是字节或游标栈深度上限。暂停 `advance` 保留分支游标和任务轮转位置；
回合额度耗尽则把尚未完成的任务各游标前缀交给备用队列，恢复时会从该前缀重新枚举，
可能重复部分工作。进入新回合时的强制选牌先跨回合层，使用新回合额度。

`pending_actions_started`、`pending_action_work`、`completed_action_alternatives` 和
`pending_action_limit_dropped` 分别记录任务数、任务消耗的搜索工作子集、已完成候选数及
任务容量拒绝数；`progress()` 包含任务数和保存的选牌前缀数，前缀采样覆盖暂停的普通
展开与任务游标。诊断中的 `action_completed` 标记参考分支已实际完成选牌效果。
完成候选仍由既有评分保留；交错调度本身不估算新手牌或持续能力的未来价值，也不保证
留药前沿或小预算结果改善。此开关默认关闭。

这些实验会改变哪些候选得到继续探索的机会；救回短连招不保证复杂战斗改善，也可能挤掉
已经能找到的胜线或留药选择。评估应固定根状态、预算，分别比较完整结果与行为；不能只看
斩杀例子、最高终局 HP 或是否获胜。没有自动切换、追加试验或合并多次预算的默认行为。

这些是主要面向 Ironclad 的人工调度启发式，不是最优性界限。宽度、回合额度和保留偏好
都可能漏解。

这些实验中，`ScheduleComplete` 仅表示本次配置的搜索轮次已结束。
没有找到胜线是
Unknown；已找到的完整胜线也只说明当前完整状态已知条件下的局部可达性。
新宽度从根开始探索，旧宽度的未完成前沿继续保留。轮次间的工作分配本身也是有限预算
下的取舍；不能保证每次加预算都改善结果，也不保证所有战斗都因及时升宽受益。

离线样本入口：

```powershell
.\scripts\py.ps1 tools/guided_search/solver_cases.py --seeds 73 211 --output .oracle-lab/solver/cases.json
cargo run --release --locked -p sts_guided_search --example combat_solver -- --input .oracle-lab/solver/cases.json --output .oracle-lab/solver/results --work 2000,10000,50000 --seconds 12
```

生成器声明的是正常规模的构造卡组，不是自然跑局存档。先指定样本再观察结果，开发与
保留 seed 分开使用。示例也接受带 `producer` 的 `snapshot` 输入；它只是显式 Rust
根状态，没有历史恢复或 Java 执行权限。输入形式由
[`combat_solver.rs`](../../crates/sts_guided_search/examples/combat_solver.rs) 的 `Source` 定义。

当前 `run-play export-combat-case` 导出的根可直接作为文件来源：
`{"label":"current combat","source":"combat_case","path":"original.json","max_potion_uses":null}`。
`path` 相对输入清单所在目录解析，也接受绝对路径。Rust 直接读取原始文件、核对来源身份，
并在结果的 `source_combat_case` 保留其来源及完整根；清单只传路径和诊断设置。
精确快照含 64 位 RNG 整数，用 JavaScript `JSON.parse` 后重新编码会舍入这些数值，
从而改变发现选项和战斗随机结果。使用文件来源可保留原始整数。

每个 case 可另给 `prefix: [ClientInput, ...]`：先从声明的来源重放这些输入，再以得到的
精确局面开始一场独立诊断。`reference.inputs`、药水消耗限额和搜索预算都相对这个新根；
前缀重放属于准备成本，不计入搜索工作量与计时。artifact 同时保留来源、前缀和新根，
这类派生局面不冒充自然实际走过的节点，也不继承前一场搜索的展开预算或证据。

同一入口接受 `plan_proposals`，每项包含 `label`、具体 `ClientInput` 数组 `inputs`、
从该根起算的正递增回合偏移 `player_turns`，以及可选 `milestones`。后果投影由
[`observation::consequences`](../../crates/sts_guided_search/src/observation/consequences.rs)
复用真实重放和状态观察；每个 `frame` 保留同一条轨迹的血量、费用、能力、敌方意图与
typed controller facts、全部有序牌堆和资源消耗。`player_turn_frames` 指向指定回合首次
完整玩家控制；回合开始的待选牌窗口不算到达，强制结束回合也由实际状态识别。
胜利、死亡和逃跑单列，未达到的回合只列在 `unreached_player_turns`，不补动作或贴失败标签。
`establish_player_power` 观察指定 power 是否存在；`change_monster_fact` 观察指定实体的
fact 是否不同于源值；里程碑值 0 表示源上已存在，空值表示所给轨迹未观察到。

`--work 0` 要求每个 case 提供方案，且只执行这些预演；正工作量则另做原有搜索。
手工方案的具体动作和后果写入 `case-*.json`，不参与搜索排名。这里使用固定完整状态的 Oracle
信息，不是学习预测。拿 `run-play compare --artifact` 的 `combat_replay`
作为来源时，保留原文件、来源身份与生产者，直接使用已解析输入，不按牌名重新绑定实例。

现有 `tactical_attacks` 同时管理短斩杀和根上的效果顺序假设，没有新增开关。
[`tactics::effects`](../../crates/sts_guided_search/src/solver/tactics/effects.rs) 在根有
`ModeShift`、`SharpHide` 或 `Thorns` 时，对相应实体提出少量短方案：先准备再放大攻击，
在伤害切阶段机制下延后易伤来源，以及遇到攻击反伤时保留攻击牌。升级、力量、敏捷、
金属化、壁垒和条件力量请求是当前支持的准备效果；这些是候选配方，不是通用评分或
所有增益都值得打出的结论。每步从该真实后继的合法动作选择，费用、抽牌、hooks、
弃牌顺序和 RNG 都由引擎处理。药水不属于这些配方，普通搜索仍遵守原资源准入。

每个 beam 的首轮只生成一次，宽度扩大不重复生成。配方到第二个完整玩家回合边界
就交回普通搜索；待选牌、目标消失、终局、未处理的卡牌机会或回合额度也会交回精确
前缀。跨回合的候选按实际玩家回合分批保留，较远回合的配方后继不会混入较早回合的
评分批次。所有配方转换共享 `advance` 的工作量和 deadline；统计在 `effect_plan_*` /
`effect_plans_*`，与原斩杀计数分开。`sample_prefixes` 的 `EffectPlan` 池可只读检查待执行
前缀，`effect_plan_proposals()` 读取已交回的配方，不执行引擎，也不授予胜线采用权限。

正工作量的离线入口自动重放这些前缀，保存 `generated_plan_proposals`、
`generated_plan_consequences` 和独立的 `generated_consequence_elapsed_ms`。
该重放是搜索后的诊断成本，搜索中的首次执行已经计入工作量；未完成的配方同样保留
已执行前缀和未到达回合。普通搜索仍用已有评价选择后续，短期血量或里程碑不能替代
完整胜线和资源结果，也没有为每个配方自动启动一场独立续搜。

药水机制与库存对照使用 `solver_cases.py --suite potions`。同一敌人和 seed 的各组保持
卡组、遗物、起始血量与初始化 RNG 一致，只改变药水栏；各组包括空槽对照。早期样本覆盖
即时伤害、防御与力量，后期样本覆盖能力生成、复制、抽牌、选牌回收与被动复活，并保留
库存不理想的情形。`inventory_context` 记录样本的构造理由，只进入 artifact，求解器不读取。
这些组合是条件假设，不是自然留药分布或整局药水排名。比较收益前需确认根状态差异，
必要时跨库存回放同一出牌路线，避免把搜索漏路误认为某种药水的价值或代价。

独立的 Block Potion 时机试点由 [`potion_timing.py`](potion_timing.py) 拥有。它只有
两个 HP 收益预测头：当前使用，以及已观测的自由择时方案组合；不输出打牌或 EndTurn
概率，不定价消耗的药水，也不接入搜索准入。输入沿用当前实体 schema 与选定药水行。
`encode_source` 只需实际根状态即可推理，不读取药水续搜结果或伪造训练标签。
收益参照共用 `never` 和 `flexible` 中已验证的留药打法，防止把更好的出牌路线计成药水
收益。`now` 的药水消耗在前缀里，后续报告的零消耗不能计成留药。择时组合保留已有的
`never`、`now` 和 `flexible` 胜线；它是实际方案组合，不是最优时机或未知牌序胜率。
缺少可比较的实际资源结果时，对应预测头不训练死亡或零收益。

[`potion_timing_trial.py`](potion_timing_trial.py) 从明确输入重新采集、训练并评测：

```powershell
.\scripts\py.ps1 tools/guided_search/potion_timing_trial.py --input <fresh-triples.json> --solver target/dev-opt/examples/combat_solver.exe --output <fresh-directory> --work 8000 --seconds 0.5
```

输入是 `snapshot` case 三元组，依次命名为 `train/SEED/never`、`train/SEED/now`、
`train/SEED/flexible`，或使用 `evaluation` 分区；两个分区的显式 seed 不得重叠。
三个 case 具有相同来源；`now` 前缀为使用唯一的 Block Potion，`never` 和 `now`
续打限额为零，`flexible` 无用药限额。输出保存新搜索记录、模型、输入、生产者与
收益预测。离线固定查询预算按预测排序，与当前攻击防御缺口和随机选取的期望对照。
查询收益只读取实际选中的续打结果，不能借用未查询的另一分支胜线；这些查询统计不表示
生产搜索已减少开销，也不决定整局是否该交药。

同场节点使用 `train/SEED/NODE/arm` 或 `evaluation/SEED/NODE/arm`；本试点每个
SEED 表示一场独立战斗。允许同分区多节点，按整场划分训练与评测。`node_replay_cases`
从新搜索的留药胜线生成有界、间隔采样的精确前缀与已知留药后缀；通过 `combat_solver
--work 0` 实际重放，再由 `node_intervention_cases` 提取节点三元组，不改中间状态。
三元组中的 `known_no_use` 用 `plan_proposals` 提供，只有真实 Victory 后果可补充
收益参照，不要求续搜重新找到同一条路线。

`timing_query_indices` 只读取输入与预测，按每场固定查询预算提名一个当前防御缺口
候选和一个模型候选；重合时只查询一次，剩余名额按模型排序补足。它不指定喝药动作，
后续卡牌动作由搜索处理。`battle_timing_selection` 每场只取一个实际终局，分别比较
全部候选、模型、当前防御缺口和组合方案，不能累加同一场各节点的 HP 收益。这是固定
完整状态下沿已知留药战术的离线时机试验，不表示 NoSL 玩家能先观察未来节点。
每次新试验在采集前保存本次 Python 生产者源码与摘要，避免开发中的文件变化污染版本记录。

`SolverStats.potion_search` 分别记录普通搜索喝药、弃药转换及其中的缓存命中；
`after_expenditure_*` 记录已经明确耗药的前缀后续工作，包含打牌，不等于可删除的浪费。
`plan_edit_source_work`、`plan_edit_potion_work`、`plan_edit_order_work` 是
`plan_edit_work` 的三个不重叠子集；源路线重放是共享成本，不全归给药水。

输出包含根状态、生产者、预算档位、终局资源和逐步路线；最低血量只统计动作之间的
稳定边界。结束 HP 包含已经结算的战后回血。另存一条到达较后回合的失败样本，帮助诊断，
不把它当作根状态无解的证据。耗时不含构建、构造根状态和搜索结束后的文本导出。
每个预算档的 `outcomes[].outcome` 保留当时完整的物化资源，便于比较药水、遗物计数等
状态；后续找到更好路线不会擦掉早期档位的资源事实。
这些输出不产生 Java parity、自然 A20H 成绩或未知牌序下的策略能力结论。

### 固定洗牌映射的调序诊断

[`shuffle_order_probe`](../../crates/sts_guided_search/examples/shuffle_order_probe.rs)
读取 `combat_solver` case artifact，或新导出的 `run-play compare --artifact` 中的
`combat_replay`，精确重放一条完成战斗的轨迹。连续片段中的动作不能抽牌或移动其他手牌，
但可向弃牌堆追加本体和生成牌（例如 Anger）。候选移动整个出牌动作，不直接编辑牌堆。
通过显式 Oracle 观察入口，在引擎真正洗弃牌堆时记录输入牌、输出顺序及 RNG；
用克隆的 RNG 和共享洗牌函数取得位置映射，并以洗牌输出和后续抽牌记录核对整个映射。
记录覆盖洗牌前已经发生的消耗抽牌、保留手牌和敌方生成牌，不重建或猜测回合结算顺序；
普通公开观察接口不携带这些私有信息，诊断邮箱不参与存档、状态相等或克隆。
原轨迹实际抽牌批次用于提出跨批次的动作移位候选，遇到置顶等牌堆改动便停止沿用批次。
候选可能牺牲当前伤害或防御，仍需重放。当前调序提案只覆盖一次输入内的一次洗牌，
且要求洗牌时旧抽牌堆已抽空、转换中没有其他洗牌 RNG 消耗；多次洗牌、提前洗牌或
其他牌堆变更记录具体跳过原因。私有收据只记录弃牌堆洗入抽牌堆，不声称覆盖其他洗牌。

```powershell
cargo run --release --locked -p sts_guided_search --example shuffle_order_probe -- --input target/solver/results/case-000.json --output target/shuffle-probe.json --work 10000
```

输出文件必须不存在。默认只运行映射提出的动作移位及原序，最多六个连续动作；显式加
`--exhaustive-reference` 才枚举片段全部排列作参考。这是实验候选范围，并非状态等价声明。
允许根状态持有药水，保留原前缀的用药动作与具体药水；续搜禁止额外消耗药水。
每个合法后继用相同工作额度、至多十秒续搜；精确相同的后继共享续搜。
每个后继还尝试重新执行原轨迹的后半段输入；编号可能指向不同卡牌，只有逐步合法且
实际完成胜利才采纳这条新路线，不复用原终局或推断状态等价。该尝试同样禁止额外用药；
输出分别记录小预算续搜与原输入重新执行的结果，防止把漏搜误当成调序损失。
所有新胜线连同前缀从原根独立重放。输出保留候选、
实际洗牌收据、位置映射、整体与候选耗时、续搜工作、独立重放的完整输入及资源结果；HP 是诊断量，
不代替其他持久资源的价值。续搜工作统计不包含前缀分析与完整轨迹复验，整体耗时包含它们。

这是读取私有 RNG 的 **Oracle 实验**，尚未实现通过 SL 试探学习映射。此入口用于固定完成路线
的离线诊断；求解器的可选自动改进使用同一个候选核心，并逐步计费，不调用这个批处理 CLI。
未考察的排列仍是不同的精确状态；No SL 下未知均匀洗牌的同分布抽象是另一个问题。
比较调序收益须同时查看原序的续搜结果，不能把小预算漏路当成原序不可达。

## 后继局面的距离启发试验

[`distance_search`](../../crates/sts_guided_search/src/distance_search.rs) 是显式实验核心。
它用真实转换产生后继，按 `已用 ClientInput 数 + 后继距离预测` 排列一个常驻队列，
不调用动作 prior。选牌组装的虚拟步骤不计真实输入数；一次输入的引擎步骤另计。
每个来源逐项结算直接后继，保留中断游标，不预先枚举整回合或所有多选排列。

模型目标是达到固定最低终局 HP／保留原瓶条件的截断操作距离 `min(D,H+1)`。
H 是预测量程，与搜索深度和计算限额独立；H+1 包括较长解和无解，不能用于剪枝。
网络不是严格距离下界，`g+h` 不提供最短解保证，也不决定 HP 与药水的战略兑换价值。
完整合格胜线独立重放后保留资源前沿；中途低 HP、预算停止和缺失后继不变成失败。

这个距离是探索提示，不是搜索耗时、终局资源价值或胜率。达到最低资源要求与在所有
合格打法中尽量保留资源是两个不同问题；缩短操作数不能替代后者。已见路线长度通常
只提供距离上界，也不能据此把别的可行长路线训练成坏打法。不同来源和未探索后续的
标签限制，以及模型参与搜索的验收目标，见[指导信号说明](../../docs/architecture/model-guided-search.md#指导信号与验收目标)。

`ordering="total_inputs"` 默认保持上述 `g+h` 顺序。显式 `"remaining_inputs"` 使用
greedy best-first：只按剩余距离排队，相等时先取已用真实输入较少的来源，再按生成顺序。
它允许更长前缀因剩余距离较小而先探索，没有手写 HP／牌值权重；现有核验模式中的事实
下界仍约束预测下限。两者只改变探索顺序，不改变输入距离、模型目标、预算、资源前沿
或回放。剩余距离也可能错误地吸引搜索深入无用分支，不保证节省计算；配置须在开始前固定。

可选 `factual_bounds=True`（默认 False）让完整后继集的事实距离下界无条件传播并参与
排序：队列优先级取预测与事实下界的较大者，来源弹出时惰性重排。已在图中精确
（传播下界与已验证胜线上界相等）的来源跳过模型估值请求，直接按精确值入队
（`exact_estimate_skips` 记录次数）。它不启用短程核验或即时探针，不合并状态、
不改变输入距离、资源要求、预算或回放；事实只向上顶掉过于乐观的预测，不能替代
未探索分支的 Unknown。这是把"已知事实先于模型估计"单独拿出来对照的候选，
默认关闭，结果须按完整资源与成本比较。

可选 `lookahead_inputs=k`（默认 0）在同一搜索图内核验短程预测：当普通队列选中的来源
预测距离不超过 k，且事实下界未排除该范围时，逐层结算至多 k 个真实输入内的全部
准入选择。虚拟选牌不消耗此深度；全局工作、存储、语法深度和时间限额仍可随时中断，
保留核验队列和已算后继。更长分支继续留在普通队列，核验不到胜线不等于整场无解。

启用时，完整后继集提供的距离下界也沿已观察图传播；排序取预测与事实下界的较大者，
不会把预测写成事实。尚未结束的稳定选择至少需要一次真实输入；H+1 仍只表示截断距离。
短程核验与在线下界排序共同构成此候选，不保证最短解或资源最优。生成的后继继续使用
相同冻结模型和独立胜线回放。`short_checks` 保存完成核验及其当时下界，
`short_check_pending` 单独标明未完成工作。`short_transitions` 是总 transitions 的子集；
下界传播和队列维护的成本计入实测时间，不重复计为模拟器转换。

可选 `advance_forced=True`（默认 False）在来源只有一个准入选择时直接执行该选择，
不请求该来源的模型估值；再次出现多个选择才回到普通估值队列。准入仍由相同资源要求
和合法动作 owner 决定，不因某张牌看起来更好而排除其他动作。来源、真实输入、选牌
组装、后继和支出账本都保留在同一图内，没有合并状态或缩短输入距离。
原来正在展开的其他来源继续保留。强制推进仍受工作、节点、深度、引擎和时限约束；
深度受限的来源保留等待更高限额。与短程核验同时启用时，不跨过核验的输入边界；
边界上的强制动作在该核验结束后另计推进。`forced_transitions` 是总转换尝试的子集，
`forced_prepared` 记录无需估值的来源，`forced_pending` 记录尚未推进的此类来源。
它省去部分估值并改变展开位置，也可能让差分支占用更多计算，不保证完整结果改善。

可选 `probe_immediate=True`（默认 False）在来源估值前检查一次真实 ClientInput 的全部
准入选择，包含为该输入组装选牌的零成本步骤。斩杀按相同资源要求独立回放；普通后继
作为精确边界暂存，不递归准备或继续试演。核验完成后，来源才进入原估值队列；来源
获得继续机会时，逐项打开已存边界，不重新执行父动作。直接选择覆盖完整与后继是否
已打开分别记录，不能把已完整试过一步误作整场已搜索完。尚未打开的边界没有编码特征，
导出保留缺失值。新增事实下界参与排队的下限，模型不成为证明或剪枝依据。
它支持唯一动作直接推进，但暂不与 `lookahead_inputs>0` 同时启用；两种核验是不同模式。
同一预算可中断试演、回放或打开边界，保留游标。`immediate_checks` 记录完成来源与实际
下界／见证，`immediate_pending` 表示未结束；`immediate_transitions` 是总转换的子集。
提前试一步可能挤占更远的搜索，需要比较完整资源结果和成本，不能只看斩杀正例。

实验选项 `probe_forced_boundaries=True` 要求同时开启 immediate probe 与 forced advance。
第一输入之后也准备真实准入动作，只在来源恰有一个选择时继续结算；再次遇到多个选择时
保留边界，不提前递归展开。虚拟选牌、跨回合输入和支出仍逐项记账，这一模式的停止范围
因此超出严格的一输入核验。它不根据费用、牌名或预测猜测某动作是否唯一。
边界准备计入原work并在后续打开时复用；所有中间节点、深度、引擎和时间限额照常保留。
`probe_forced_transitions` 单独统计越过第一输入后的唯一选择转换尝试，是
`immediate_transitions` 和总transitions的子集，零时省略。它不与普通forced队列的
`forced_transitions` 重复计数。多选边界仍由父来源获得继续机会后逐项打开。
这个候选可能推动有用后继，也增加准备和存储成本；默认关闭，结果须按完整资源及成本比较。

可再显式开启 `estimate_probe_boundaries=True`（要求 `probe_forced_boundaries=True`），
让已准备好的多选后继直接按自身状态估值入队，完成的父来源不再估值或控制它们的入场。
后继被队列选中时才开始它自己的 probe；入队本身不展开下一层。最初来源仍在首次估值前
完成 probe；已入队的后继尚未检查自己的出边，不能声称每个估值状态都先核验过一步。
所选 probe 中实际找到的合格胜线仍先独立回放，再请求下一批估值。所有边、中间状态、
实际输入距离、资源要求和预算照常保留，已准备状态不重复收费；估值不进入事实下界。
这改变继续搜索的分配位置，不改变训练目标，也不保证省血、留药或计算成本改善。

`DistanceCombatSearch` 是现有 Python bridge 的薄适配：

```python
from sts_learning_bridge import DistanceCombatSearch

search = DistanceCombatSearch(task_json, horizon=96, model_revision="frozen-revision")
stop = search.advance(work=1000, max_nodes=2000, max_depth=128, seconds=1.0)
if stop == "NeedsEvaluation":
    frame = search.evaluations()  # NumPy entity/action columns; resource kinds 16,17
    estimates = frozen_local_model(frame)
    search.accept_estimates(frame["token"], "frozen-revision", estimates)
```

评估批次绑定会话与代次，发出后锁定；重读不推进，过期／跨会话／换版本／非有限预测
原子拒绝。模型应在整次搜索内冻结。接收预测逐状态计入 work；调用方必须连同原生转换、
批次预测和传输，共用一个总时间／工作限额。原生单次 advance 的 seconds 仅限制该次调用。
`distance_learning.solve` 已实现此总限额；最后一批同步推理可能使时间稍超，实际成本保留。

work 是准备状态、转换尝试、独立回放尝试和接受预测的状态数之和；节点限额包含终局，
不是字节限额，不与其他搜索器的 work／节点统计直接等同。状态读取用
`report_json(False)`；完整计划与原始数据只在导出时读取。

`distance_route_data` 重新核验显式完整路线，导出每个参考决策及其真实一步替代后继。
参考中已选后继直接作为下一决策的来源，核对完整状态、输入位置和资源账本后续接；
不按特征相似性合并其他分支。其他未展开的替代后继仍保留部分覆盖。
原根、输入链、typed 分支、父节点／参考决策坐标与 producer 由调用方保留；它们不进入
模型特征。`data_json()` 可导出本次搜索已计算的同格式证据，部分后继集保留未完成状态。
真实终局和完整后继覆盖可收紧事实距离区间；已验证打法只提供剩余长度上界。

[`distance_learning.py`](distance_learning.py) 使用同一实体／关系编码，增加资源查询行，
训练本地小型 attention 网络的单个距离输出，没有动作头。冻结后继网络的一步最小值是
bootstrap 估计，与事实区间、完整性和原始证据分开。未完成且无有效区间的记录不拟合；
只有事实区间的记录没有点目标，在区间内损失为零，越界才纠正；不锚定上一次预测，
也不强制预测等于示范长度。整个来源家族及派生邻域必须留在同一个数据划分。
Python 的数值实体装箱支持显式 kind_count=18，其他既有调用保持原来的 16 类默认合同。

`fit(..., bootstrap=False)` 可单独检验事实监督：只拟合 Rust 证据中的精确值和有约束区间，
不运行目标网络、不用后继预测生成点目标。已有直接后继覆盖仍原样保留，未知区间不拟合。
这不补全未搜过的结果，也不保证学到充分的远期判断；默认仍包含冻结后继 bootstrap。
收据记录此选项；事实监督的 `target_revision` 为 None，因为没有产生目标预测的网络。

`fit` 默认按完整 epochs 训练。比较不同大小的数据时，可显式设置 `epochs=None` 与
`steps_per_update`，每次冻结目标更新后执行固定数量、固定 batch 大小的梯度步骤。
此模式从合格特征行中有放回取样，保持原来源家族权重；Unknown 不进入取样。
训练收据分别记录合格行、实际见过的独立行、重复计数的样本数和优化步骤。
相同梯度步数不等于相同总耗时：后继目标计算仍须读取各自数据，采集成本也另计。

固定步数拟合可显式指定 `sampling="source_fact"`：先给来源家族相同的概率，
再平分该家族实际存在的三类事实：有限胜线给出的上界、下界到达 H+1、只有部分下界。
类内按记录出现次数抽取，Unknown 不入选；H+1 仍不代表无限范围无解。
此时不再叠加原来源权重，收据保留每个来源／事实类的概率和实际抽取次数。
这是改变训练分布的候选，不是战术评分或改善保证；默认 `uniform` 仍沿用原来的
均匀抽取和来源权重。该选项不适用于完整 epoch 模式。

`source_fact` 可与 `bootstrap=True` 配合：采样资格与分层仍只依据事实区间，完整直接
后继集的冻结网络估计则可提供区间内的近似点目标。缺乏事实约束的行，即使能产生
bootstrap 目标，也不会因此获得采样资格。预测、真实边的0／1输入成本与事实界限分别
保留；参考路线只是上界，不被改成精确最短距离。收据同时记录目标类型、冻结网络版本
和事实采样类，不能把近似目标的拟合改善解释为距离已获证明。

这是可测量的候选，不是合格自动控制器。训练损失、局部距离变化和少量已教战斗的胜线
不能单独证明节省搜索；仍须检查未参与训练的完整根、具体资源、成本和 Unknown。

### 后继图中的资源证据

`DistanceSearch::data_with_outcomes()`、bridge 的 `data_json(include_outcomes=True)`，
或 Python `solve(..., export_data=True, include_outcomes=True)`，可在同一图的每行附加
`outcome_evidence`。默认导出保持原样；这项读取不准备动作、不推演或回放，也不改变队列。
Python 调用另报 `outcome_export_seconds`，包含导出和 JSON 解析，未包含调用方写盘成本。

证据分别记录战斗目标是否结束、Smoke 逃跑、原瓶实际消耗、是否违反留药要求、终点资源、
终点是否符合查询及完整输入链是否已经独立回放。尚未结束的局面不投影成“终局 HP”；
瓶中精灵触发可以违反留药要求而仍未结束战斗。胜利但 HP 不达标也有自己的实际资源，
不被混为死亡。未回放终点保持未回放；距离到达 H+1 不会据此获得无解或死亡标签。

回放通过后，即使某条打法被其他完整资源更好的打法移出 `plans`，该终点仍保留回放标记。
这不是为每个祖先保存一份结果；消费者可沿已有的真实父子关系引用终点，避免重复存储。
默认路线邻域导出尚不附加这项证据；缺少字段不等于空结果或负例。

这些字段在证据层，现有距离网络、数值列和训练目标均不读取它们。某个后继已知可通向
60HP、另一个暂时只见48HP，是已见打法的比较，不是两个状态最佳后续的确定排序。
新学习器须先定义监督含义，不能直接按各分支已见最高HP制作“最优动作”标签。

### 资源区间的本地学习试验

[`resource_learning.py`](resource_learning.py) 读取带资源证据的后继图，试验固定原瓶保留
条件下的终局HP范围。`hp_intervals(data, cap)` 只沿图中的真实父子关系传播：已独立回放的
胜局提供下界；模拟器终点及完整准入子树提供上界；未物化的选择使上界保持开放。
上界的模拟事实不自动获得完整路线回放认证，非终局HP和距离区间不参与资源界限计算。
不接受另一个留药条件；修改留药条件后必须重新取得相应动作覆盖证据。

坐标0表示没有符合留药条件的胜局；完整区间`[0, cap]`表示Unknown，训练损失及梯度为零。
最高坐标表示至少达到`cap`，不声称游戏HP不能更高。实际48HP胜线不会被改成“最佳只能48”。
`ResourceNetwork`输出这些坐标的分类logits，以区间内总质量的负对数作为约束拟合目标；
各HP门槛的尾部和保持单调，但不是经过校准的胜率，也不因此成为可采纳的搜索界限。

`state_input`共用于训练与推理：复制既有实体数值，仅清除资源实体16的最低HP字段，
因为HP门槛已成为输出坐标；其余局面及原瓶关系保留。它仍使用既有实体context编码，
没有增加源动作与后继的联合编码。终局证据、区间、来源ID及路线位置不进入模型输入。
原始RNG仍不进入网络，同一输入表示未必具有唯一的固定世界最佳HP。

`ResourceDataset`保留整根及来源家族，拒绝重复根／留药查询被默默重复加权。`fit`使用明确的
固定步数，均匀抽取有事实的查询，再抽其中合格区间；不使用模型bootstrap目标或按评测集
挑选检查点。此采样分布不代表自然游戏出现频率。来源身份与整根划分仍由实验调用方核验。

此模块尚未接入全局搜索排序。血量预测不能作为操作距离传给原距离搜索；区间误差或局部
比较改善也不证明节省搜索或留下更好资源。完整药水、遗物及持久资源取舍继续由原证据保留。

## 固定条件的路径搜索

[`path_search::PathSearch`](../../crates/sts_guided_search/src/path_search.rs) 是独立的进程内
实验核心：任务条件、prior 和探索顺序在会话内固定，默认按
`log(depth) - log(path_probability)` 展开具体选择。它不调用旧求解器的战术评分、
后继策略或前缀预算分配。
深度包含虚拟选牌步骤，排序值是搜索代理，不是 HP 估值或实测耗时。

`PathSearch::with_order(..., PathOrder::RelativePrior)` 或 CLI 的
`--order relative-prior` 可显式选择另一种实验顺序：沿路径累加
`max(log p) - log p(action)`，较小者先试；累计值相同时优先较深的路径，最后按原入队顺序。
继续选择当前首选动作时不增加排序代价，具体的其他动作仍独立保留，失败后可以回溯。
相对差值不是胜率或终局评分，也不继承原 `C/P` 训练目标的搜索量解释。未经训练的 prior、
错误的高置信首选或大量同分分支都可能使这种顺序效率很差；它不是默认自动控制器。

`ResourceRequirement` 声明最低终局 HP 和需要保留的原始药水。显式用药／丢弃在展开前
按原瓶身份排除；真实后继仍检查被动消费。中途 HP 低于目标不会剪枝。
胜线经过原始根独立回放和完整资源投影才进入结果集；搜索继续寻找其他合格资源结果。

`PathPrior` 返回全部已准入具体选择的规范化对数概率。版本固定，异常概率会停止实验。
`PathContext` 提供固定根／资源目标和实际前缀消耗，供 encoder 解析原瓶关系；不把根的
原始 RNG 或身份编码给模型。默认使用未训练的 `GroupedNeutralPrior`：同 CardId 的打牌动作共享组概率，
组内实例／目标仍独立；同 PotionId 的使用与丢弃分别成组，其他选择各自成组。
`path --model model.json` 可显式载入下述本地线性 prior；权重随结果保存，搜索内保持冻结。
没有接入价值头、实时更新或默认自动 A20H 控制器。

节点保留完整战斗状态；准备新的非终局节点时，对当前准入动作重新计算概率，权重保持
冻结。当前队列代价在执行候选边之前，由父节点代价和该动作的概率确定。模拟后的状态会
影响下一步动作概率及终局／资源检查，但不会产生独立的局面估值，也不回传更新祖先或其他
待选边的代价。因此“输入含敌人 HP、费用和意图”与“拥有后继局面评价”是不同的能力。

```powershell
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- path --roots roots.json --output .oracle-lab/path-search/measured --work 500,2500,10000 --max-nodes 2000 --max-edges 12000
```

使用下节同格式的任务路径索引，每项 `prefix` 必须为空。原始状态、来源、条件、producer、
prior 版本、工作与时间、完整已验证路线均写入新的输出目录；不会读取参考后续。
CLI 的累计工作里程碑共用每个根的一次会话及一个时间截止点。

工作计数是“准备状态 + 转换尝试 + 回放尝试”，包含未完成尝试，不等于旧求解器的计数。
实际引擎步数、虚拟选择、准备与 prior 调用、回放另列。初始化耗时单列；文件导出不计搜索
时间。上限与超时在操作之间检查，单次同步 prior／投影可能使时间略超；prior 应是快速本地计算。
`first_verified_win_work` 记录首次独立回放通过的合格胜线时的总工作量，即使后来被更好的
结果替换也保留。每条现存计划的 `found_at_work` 则属于该计划；两者都不是首次获胜的墙钟时间。

暂停保留队列、部分入队游标及未完成回放。节点、队列或深度限额可通过后续 `advance` 提高；
引擎单步限额不足时，原限额不会反复重试扣费。存储限制是对象数量，不是严格字节上限；
首版保留已到达状态，不做淘汰或近似合并。没有合格结果是 Unknown，不能把存储停止当无解。
目前没有改目标、跨进程恢复或不同祖先间的转换缓存。

`relative-prior` 达到深度上限时将该边暂存，继续处理尚在上限内的其他边；所有可推进边均
结束而仍有暂存边时才返回 `DepthLimit`。提高深度上限会唤回适用的边，共用原来的来源、
概率和祖先。暂存边计入同一个队列限额，CLI 另列 `depth_deferred_edges`；它们仍是 Unknown。
默认 `path-probability` 保持在首个深度受限边暂停。两种顺序都保留独立回放和完整资源比较，
节点与队列上限均可能先于深度上限停止搜索。

`PathSearch::inspect_route(&CompleteRoute)` 可在暂停处对独立重建的完整打法做只读检查。
它要求同一完整根和资源查询，按真实祖先与具体语法选择定位已走到的前缀；重复卡牌、
虚拟选牌步骤和不同随机状态保持区分。返回下一步是否尚待准备、入队、正在队列中、
因深度暂存，或整条路线已经到达。已到达仍区分等待回放与当前结果集是否保留该计划。

队列中的下一步按现有 comparator 统计前方候选，包括深度和入队顺序的并列规则；另列
成本更低及相同的候选数（相同成本计数包含参照边自身）。存储节点与排在前方的候选按
离开参照路线的位置分组，便于定位早期选择如何占据后续搜索。被丢弃的死亡后继不在
存储节点计数中。检查不推进模拟、不调用 prior、不修改队列或授予预算，临时开销随
现存树与参照路线长度增长；这些快照计数不等于未来工作量、覆盖证明或其他路线的负例。

相对代价的绝对大小也不是搜索量：在实数运算下，将每个局部分布改为与 `p(action)^alpha`
成正比（全局同一 `alpha > 0`），会将全部相对路径代价同比例缩放，而队列顺序保持不变。
所以训练效果还须检查真实分支竞争与完整打法；不能只由一个参照代价降低推断搜索更快。

### 完整路线重建

[`path_search::routes`](../../crates/sts_guided_search/src/path_search/routes.rs) 从显式根状态、
固定资源条件、完整真实输入和预期终点重建搜索选择。先独立回放原始输入，再按当前准入
逐项重建；每个真实后继均须与回放相等。组合选牌按 typed 身份／当前 Scry 域还原有序
`BeginSelection → SelectMember → FinishSelection`，保留重复牌的具体实例，不枚举排列。

导出包含每步来源观察、完整准入选项、选中索引、共享概率分组和原瓶消耗账本；根、条件、
真实输入及完整终局资源另存。选项与 `PathSearch` 共用准入，分组与未训练 prior 共用
`choice_groups`。`CompleteRoute::log_probability` 仅计算给定冻结 prior 下的整条路径对数
概率，检查全部选项的概率归一化；它不是训练损失，也不表示该路线最优。

```powershell
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- routes --manifest routes.json --output .oracle-lab/path-search/routes
```

清单是 `{"artifact":"measured/result-000.json","witness_indices":[0,1],"qualification":"declared source qualification"}`
条目的数组。路径相对清单；读取 `continuation_tasks` 结果内的 `task_input`、`producer`、
`witnesses`（或 `path` 的 `plans`），要求空 `prefix`。来源说明仍须交代根是否为自然开局；
空前缀本身不能证明自然性。忽略旧合格标志，重新回放并检查当前资源条件和原记录的 outcome。
不读取旧树、评分或指导概率，不切出成功后缀。
清单条目可显式增加 `requirement`，以同一未修改根和打法证据建立新资源查询；原 artifact
保持不变，新条件照常回放核验，不会因旧合格标志而自动达标。

输出目录必须新建。生产者、来源摘要、家族分组和显式索引随结果保存；只有通过核验的路线
才导出。`summary.json` 记录每条是否导出及原因；未完成、无法重建或不满足条件都不能被
转换为“该状态无解”的训练负例。`--max-decisions` 包含虚拟选择，`--seconds-per-route`
同时约束重建与回放；数量限额不是字节上限，结构化观察在调用边界协作检查超时。

既有 `entities` schema 4 本身不含完整的新目标及原瓶关系；`routes --features` 使用下述
扩展 encoder 另存数值文件和 `features.json` 索引。`routes --model model.json` 可按原始
根重新计算整条路线概率，核对训练器与 Rust 的数值结果。模型观察不得混入选中标签、
来源 ID、输入序号、最终资源或剩余路线；数据划分须保留完整根和来源家族。

### 本地线性路径模型

[`linear`](../../crates/sts_guided_search/src/path_search/linear.rs) 在 Rust 中执行冻结推理，
[`path_learning.py`](path_learning.py) 使用 NumPy／SciPy 离线拟合两个长度为 16384 的权重
数组。权重从零开始；零模型与中性 prior 的概率一致。模型不直接选择游戏动作，只为同一
路径队列的准入选择提供概率。schema、维数、有限性和概率归一化均受检查。

encoder 复用实体 schema 4 的事实和引用，增加最低终局 HP、起始 HP、留药条件及原瓶到
当前药水槽的身份关系。模板包括全场实体分类统计、动作引用的对象及邻接关系、按动作类型／
卡牌类型／对象类别条件化的全场事实，以及源对象数值与玩家／目标数值的乘积。
数值使用有符号 `log1p` 压缩；固定 FNV-1a 哈希映射到 16384 维，碰撞求和。
这些是明示的表示先验，系数和偏好由训练学习；池化与哈希是有损的，不是完整状态身份或
状态合并依据。encoder 不传 seed、原始 RNG、UUID 或路线答案；超出实体支持范围时显式报错。

每个具体选择拥有同一份稀疏特征。组 logit 是组内特征对应的组权重分数均值；成员 logit
来自独立成员权重。先对组归一化，再在组内归一化，两项对数概率相加。
完整路径概率是全部语法步骤概率的乘积，强制步骤仍计深度但不增加选择不确定性。

```powershell
.\scripts\py.ps1 tools/guided_search/path_learning.py --index .oracle-lab/path-search/routes/features.json --output .oracle-lab/path-search/training --steps 120 --learning-rate 0.01
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- path --roots roots.json --output .oracle-lab/path-search/learned --model .oracle-lab/path-search/training/model.json
```

训练目标是 `log(mean_root mean_query min_known_route C/P)`，`C` 为完整路线语法边数。
这是完整正目标的全局单调 log 变换，不是逐步交叉熵或逐根 log 的均值。每个根与根内
查询分别等权，重复同一根／查询／输入链不增权；没有已知合格解的任务由核验收据保留，
不以零损失混入分母。路线 min 在并列时按声明顺序取一个梯度，不具有一般凸性保证。
Adam 从零权重拟合，导出训练目标最低的检查点；不读取评测根来选权重。

训练收据保存来源摘要、encoder 生产者、参数、损失轨迹和各完整路线预测。
必须同时检查训练根与独立家族的完整搜索：资源质量、首次合格打法所需工作、总耗时和
存储停止都要报告。概率拟合改善本身不证明搜索更快，推理成本也可能抵消搜索节省。

### 完整打法的资源偏好实验

同一导出器的 `routes --comparisons pairs.json --features` 显式启用观察胜局模式。
`pairs.json` 只列需要比较的两条路线，例如 `[[[0,0],[1,0]]]` 表示清单第 0、1 个
来源各自的第 0 条 witness；不自动展开所有路线的两两组合。每条路线仍独立回放并按
当前准入重建，允许最终 HP 低于查询目标，原瓶保留条件仍在动作和实际后继上强制检查。
默认 `routes` 保持只导出合格示范的合同。

Rust 要求比较双方完整根（含 RNG、实例）和查询相等，沿用共享 outcome 的严格资源
支配比较，不给 HP 和药水定兑换比例。资源相等或不可比时不产生偏好；路线无法重建或
跨根／跨查询则不发布偏好索引。`preferences.json` 保存明确方向及参与比较的数值文件，
`comparisons.json` 保存每项比较结果；它们与正例 `features.json` 分开。观察路线标明
`goal_satisfied`，即使两条都未达标也可比较，但不能由此标记中间动作错误或状态无解。

```powershell
.\scripts\py.ps1 tools/guided_search/path_learning.py --objective preference --index .oracle-lab/path-search/compared/preferences.json --initial-model baseline/model.json --output .oracle-lab/path-search/preference-training --steps 60 --learning-rate 0.001
```

偏好目标是 `mean_root mean_query mean_pair softplus(C(better) - C(worse))`，
`C(route) = sum(max(log p) - log p(selected))` 与 `relative-prior` 队列使用相同成本。
重复路线和偏好对不增权，根及根内查询分别等权。每步最大概率并列时，取第一个准入项
的梯度；强制步骤的成本与梯度均为零。两种学习目标共享概率前向和反向计算，`--initial-model`
可显式指定起始权重，否则仍从零开始。选择训练目标最低的检查点，搜索中保持冻结。

这是候选排序目标，不能保证合格打法更早被找到：仅推迟较差路线也能降低损失，甚至可能
同时推迟较好路线。必须检查好路线自身成本、完整终局资源和实际搜索开销，单看偏好命中
或新增一个胜局不能作为替换基线的依据。终局资源与偏好方向只作标签，不进入模型特征。

### 已知完整打法的队列学习实验

[`PathSearch::witnessed_queue`](../../crates/sts_guided_search/src/path_search/queue_data.rs)
从暂停的 `relative-prior` 队列导出前 K 条实际待选边，以及独立重建的合格打法尚未走到的
下一条边。先按完整资源剔除被严格支配的参考；若其余参考已有一条到达，或正在准备／回放，
则不产生样本。导出保留来源祖先、具体选择、深度及入队序号，共同祖先只编码一次。
调用方保存完整根、参考来源和 producer；导出只读，不推进模拟或改变搜索预算。

[`queue_learning.py`](queue_learning.py) 与路径学习器共用概率计算。样本集合 F、其中已有
完整打法证明可续接的子集 G，对应目标为 `logsumexp(-C(F)) - logsumexp(-C(G))`，C 按整个
前缀累加相对代价。其余边的终局质量仍为 Unknown；这是优先探索已知可行续接的候选目标，
不将其他边标成无解。快照去重后按根、查询、快照分层平均，检查点按训练样本中首条见证边
的平均名次选择，损失只用于同名次比较。名次遵循实际代价、深度、入队顺序。

```powershell
.\scripts\py.ps1 tools/guided_search/path_learning.py --objective queue --index sampled/index.json --initial-model baseline/model.json --output .oracle-lab/path-search/queue-training --steps 60 --learning-rate 0.001
```

索引使用 `{"schema":1,"label":"witnessed_queue","features":["sample.json"]}`，旁置
`producer.json`。每份样本补充稳定 `snapshot_id` 和来源家族 `family`。来源代价只用于
核对 Rust／Python，参考编号、队列名次和来源身份不进入模型。样本截取会遗漏其他实际及
未来竞争者，样本名次不代表完整队列名次或搜索工作界限；必须从完整起点重新运行冻结模型，
检查终局 HP、原始药水、持久资源、首次合格工作量和停止原因。此入口保持显式启用。

## 有预算记录的战斗续搜任务

[`continuation`](../../crates/sts_guided_search/src/continuation.rs) 接受带来源与分组的战斗起点、
已执行前缀，以及最低终局 HP／保留原始药水槽要求。先按模拟器重放前缀，得到实际续搜起点；
相同来源家族的不同战斗、不同切点应保持同一 `group`，以后划分训练与评测集时一起划分。

`ContinuationExperiment` 目前固定使用上面的 `CombatSolver` 生成候选。没有新增战术评分，
也没有模型或学习调度器；原求解器仍有人工保留偏好和覆盖限制。要求只过滤已验证结果，
不会改变其展开顺序；`SolverConfig.max_potion_uses` 仍以续搜起点计数，不能当成整场用药上限。

每次 `advance` 续接同一内存中的搜索和待完成回放，工作额度同时支付求解器工作与额外的
原始战斗起点回放。只有完整的“前缀＋新后续”合法、后继完全相等且确实获胜，才发布结果。
资源由共享 outcome owner 从原始起点计算；前缀已损失的 HP、消耗或丢弃的药水不因切点重置。
同槽后来生成一瓶药也不算保留原来那瓶。保留所有已验证候选，并另列满足要求的资源前沿。

回执记录每次追加和累计工作量、引擎步数、耗时、待回放状态与完整资源结果。
初始化的前缀校验工作和时间单列，不藏进免费准备。超时的未完成转换不计完成工作，
其实际引擎步数与耗时仍记录；时间限制沿用模拟器的协作检查，单次调用可能稍超时。
未观察到合格路线和搜索轮次结束都不证明无解。执行／回放出错后该实验停止，之前的证据仍可读取。

离线入口将参考答案处理与运行分成两个命令：

```powershell
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- prepare --manifest references.json --output .oracle-lab/continuations/prepared
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- run --tasks .oracle-lab/continuations/prepared/tasks.json --output .oracle-lab/continuations/measured --work 2000,10000,50000
```

`prepare` 只读取显式指定的 `combat_solver` 结果文件。清单是以下条目的数组；路径相对清单，
`turn_counts` 是从零开始的实际战斗回合数，在该回合首次普通玩家决策边界切开：

```json
[
  {
    "artifact": "solver-results/case-000.json",
    "plan_index": 0,
    "group": "source-family",
    "qualification": "explicit source qualification",
    "turn_counts": [0, 1, 2],
    "requirement": {"min_final_hp": 1, "preserve_starting_potion_slots": 0}
  }
]
```

全部参考动作先重放核验，缺失回合或后继不符就报错。`task-*.json` 只含来源、原始状态、
过去动作和要求；参考后续及终点另存 `evaluation.json`。`run` 仅读任务索引和任务文件，
不读取参考答案；生产者二进制摘要、相关编译时源码摘要、配置、预算与逐次回执进入结果文件。
两个命令都要求新的输出目录，不能覆盖已有实验。

这些是完整状态已知条件下的局部续搜记录。沿已知胜线切片带有成功路线的选择偏差；
给定前缀后的成功不是从战斗开场自动求解，参考答案只证明路线存在，不提供最优标签。
具体资源结果应逐项比较，不能把切片命中率当作自然战斗胜率。这项接口尚不证明模型能
节省搜索，也没有把“预算内未找到”写成训练负例；学习目标与无参考前缀的验证仍须另行设计。

`CombatSolver::sample_prefixes(limit)` 可以只读抽取当前搜索仍保存的真实动作前缀。
它在各轮次的展开中、待展开、选牌、下一动作、下一回合和备用队列之间轮流取样，
不修改队列或推进工作。同一根的完全相同动作链只保留一次；不同动作链即使立即效果相同，
仍保持独立。尚未提交的虚拟选牌组合不导出，已经实际进入的 `PendingChoice` 可以导出。
这些是按当前队列顺序取得的有偏候选，不是所有合法前缀的均匀样本。

离线 `sample` 命令仅读取无前缀的原始任务文件索引，先进行声明预算的开场搜索，再导出
有界数量的候选，每条都重放验证完整后继。它不读取参考路线，也不要求开场搜索已经获胜：

```powershell
cargo run --release --locked -p sts_guided_search --example continuation_tasks -- sample --roots roots.json --output .oracle-lab/continuations/sampled --work 2500 --count 8 --width 32
```

`roots.json` 与 `tasks.json` 同为任务文件路径数组，路径相对索引；所有源任务的 `prefix`
必须为空。输出的 `tasks.json` 可直接交给 `run`。`sampling.json` 保留原始来源、采样执行器、
预算、实际工作、已有胜线、队列来源及逐条前缀校验成本；导出任务的生产者标识更新为采样器。
`run` 重新校验前缀的成本也保留。比较总体计算时，必须合计开场搜索、导出校验、加载校验和
所有续搜工作，并计入开场搜索已有成果；未用完的额度单列，不能称作已花费。

每个导出任务从该实际状态另起续搜，展开完整合法动作空间，不继承原轮次已探索的边或
虚拟选择进度。不同任务的后续可能大量重叠；固定分配额度会割裂长搜索。这个接口提供测量
材料，尚无自动分配器，不改变普通搜索调度，也不保证分割后优于把预算持续投入开场搜索。

## 部分牌序观察与规划约束

[`DrawOrderKnowledge`](../../src/agent/information/draw_order.rs) 从公共快照与真实转换回执维护
已知前缀、后缀、相对顺序和牌堆组成。它记录卡牌种类与升级，不绑定同名牌的私有实例，
也不把当前费用冻结为未来费用。模拟器的 `apply_combat_input_to_stable_observed_v1` 提供
有序的置顶、置底、抽取、移除、随机插入和弃牌洗入记录；普通搜索转换不开启此观察。
观察用的临时邮箱不进入模拟状态身份或存档，克隆状态时也不携带邮箱内容。

[`CombatBeliefEnvironmentV1`](../../src/agent/belief/environment.rs) 在连续推进时使用这些
记录维护历史知识，并拒绝与知识矛盾的候选局面。新分支依据可见后继与已覆盖的中途观察
划分；内部覆盖标记不用于识别隐藏世界。任一候选缺少完整观察时，本次展开统一退回
最终公共快照，不能把缺记录误解成没有发生事件。旧历史缺少回执时采用同样的保守解释。

未知的整堆替换或可变访问会使顺序知识失效，即使最终排列碰巧没变；公开的 Frozen Eye
观察可以重新确定当前顺序。

[`IndependentStreamsCombatBeliefSamplerV1`](../../src/agent/belief/combat.rs) 默认只按当前快照
取样，遇到额外记住的牌序会拒绝重采样。显式调用 `.with_draw_order_knowledge(max_states)`
后，可通过 `CombatBeliefEnvironmentV1::from_history_and_sampler` 在已有历史节点补充候选，
再用同一个环境的 `step` 继续推进。新候选保留已知前缀、后缀与相对顺序，并带独立的来源
标记。Frozen Eye 当前公开的完整排列和卡牌属性直接保留。

此模式假设所有满足牌种顺序约束的排列等概率。生成器用记忆子序列的匹配进度与剩余数量
计算条件概率，重复牌的多种匹配方式不会让同一排列重复计权；没有顺序要求的牌种共享
一个计数桶。同次取样共享计算表，表的状态数受 `max_states` 限制，牌堆最多 128 张。
超限明确返回错误，可能后续仍是 Unknown，不能悄悄放弃约束。概率使用浮点计算，有限
样本不保证覆盖所有结果。取样不改动实战 RNG 或牌堆，也不按源状态的隐藏位置选择牌种。

这仍是独立 RNG 流的条件假设，**不是完整行动历史或 run seed 的后验分布**。例如随机插入
重复牌时，真实经历可能让若干相容排列具有不同概率，仅有相对顺序事实不足以还原这些权重。
源状态中的其他隐藏控制器事实仍被保留；此模式不能替代对整段历史一致性的校验。
记忆涉及的同种同升级牌若有不同费用等公开属性，目前拒绝补充候选；仅凭牌种不能猜测
记住的是哪种属性实例。已有候选仍可按真实转换继续，不要求每步重新取样。

此组件尚无跨不同 SL 路径复用证据的条件分析，也未接入上面的 Oracle 整场求解器；
不据此声明有限信息下的整场规划或策略质量。

## 有限候选上的条件分支搜索

[`information_search::lookahead`](../../crates/sts_guided_search/src/information_search.rs) 接受已有
`CombatBeliefEnvironmentV1`，返回带观察分支的多步策略。一个信息节点只选择一个公共动作，
所有候选共同执行；可见后继及中途观察区分它们后才分别选择。候选及其权重沿真实转换传播，
不调用 Oracle 求解器替各个隐藏世界寻找不同的最佳续打。可选的历史重放补充见下文。

调用方提供仅依赖公共信息的叶节点评估；闭包也不得捕获私有状态。它是候选估值，不是胜率
或质量界限。根节点的所有保留动作获得继续探索的预算份额；更深处按一层估值挑选至多
`width` 个动作深入。输入深度、预算和候选裁剪都可能漏掉连招；动作数相同也不代表到达
相同的战斗进度。当前没有搜索树续接或策略质量保证。

按同一公开卡牌属性和目标保留一张重复牌代表，省略的实例不留延期队列。这是近似取舍，
不证明后续弃牌或洗牌相同。组合选牌按公共候选序号有界生成；药水由调用方按槽位允许，
不内置 HP 换药价格；丢弃药水不展开。逃跑尚缺独立公共终局分类，遇到时明确报错，
不会记成击杀胜利。

工作量按候选状态与输入计数，节点要能完成全部保留动作的一层比较才开始展开；时间在
动作批次和整次历史补充之间检查。死亡、已结束与未算完的候选质量分别保留，`mean_boundary_hp` 包含
活跃叶节点，不能叫作终局 HP。`replay_policy` 用公共观察与回执重放所有已选分支，
重放工作另记；成功重放不使一个尚未完成的策略变成完整胜线。

### 按历史重放补充候选

`LookaheadConfig.rejuvenation` 默认为调用方显式选择，`None` 保留固定候选诊断。
启用后，当信息节点的候选数至多为 `target_particles / 2` 时，
[`rejuvenate_history`](../../src/agent/belief/rejuvenation.rs) 对每个来源生成相同数量的副本，
总数不超过目标上限。每个副本执行固定次数的提案：交换起点抽牌堆中的两张完整实例，
或替换起点八种战斗 RNG 流中的一种，然后重放全部已记录输入。起点、每个公共后继和
覆盖完整的中途抽牌记录都必须一致；观察不完整或转换失败是错误，不计为随机提案被否决。
旧历史缺少的观察只按实际记录约束，不能补写成已知事实。

重建起点由根部采样器保存并沿真实转换传递。仅在后续边界取样的候选不具备这个来源，
补充时会拒绝；每个来源也先重放核对完整终点。相容的新候选保留真实实例和机械状态，
不会直接改写当前牌堆、忘记 Headbutt 置顶或根据真实执行世界选择未来。

这是**有相关性的候选扩展，不是经过校准的完整历史后验**。每个来源的总权重按副本数平分，
有限步变换会保留来源偏差；独立 RNG 假设仍不等于原游戏的同 seed 相关性。报告区分提案
接受数、历史矛盾数、改变的副本数、不同完整终点数和不同牌种顺序数。不同终点可能只差
暂时无关的 RNG，副本数和接受数都不等于独立证据量，也不表示下一次观察已被充分覆盖。

补充同时发生在假想观察分支中。整批重放工作和全部动作的一层比较预算必须同时足够，
否则返回 `PopulationWork` 叶节点，不默默退回单候选继续深搜。重放计入同一个搜索预算；
策略节点保留确定的提案配置及回执，`policy_successors` 与 `replay_policy` 据此重建候选，
不靠时间截止点猜测当时补充了哪些内容。完整历史重放的成本会随路径长度增长。

离线执行发现真实的新**公开观察**没有候选分支时，实验调用方可另用
`rescue_observed_successor`：它只接收该公开后继、旧候选与独立的工作／时间限额，
从旧候选起点提案，每步先核对既有公开历史，再核对新画面；不接收真实的精确后继。
固定提案日程未找到相容结果或时间耗尽时返回 Unknown，时间耗尽不发布局部已找到的候选。
结果保留尝试数、相容数、重放工作与来源；`--rescue-retained` 限定在完整日程里抽样保留
的候选数量，避免相容结果多时无限占用内存。这仍是相关提案，不是完整历史后验；
尤其只有一两个相容候选时，不能把归一化权重解释为真实概率或策略质量。

离线演示会重复规划并执行到终局或预算停止，保存第一棵条件策略和完整出牌记录：

```powershell
cargo run --locked -p sts_guided_search --example information_lookahead -- --output .oracle-lab/information-demo --allow-potions
```

默认两组构造卡组通过正常战斗初始化进入 Jaw Worm / Gremlin Nob；也可用 `--input` 提供
`ConstructedCombat` JSON 数组，其药水计数限制须为 `None`，允许槽位由本演示单独声明。
`--production-case <case.json>` 可改用带精确生产上下文、通过恢复校验的战斗 case；
它与 `--input` 互斥。演示从恢复后的公开观察取得 run context，精确根只交给候选采样和
独立执行，动作选择仍按候选共享的公开边界进行。是否经过自然前序到达，须另由采集收据证明。
`--particles N` 控制独立流候选数
（1–256，默认 8），并写入收据。自然 case 来源不意味着候选符合完整历史后验。
`--rescue-attempts-per-donor N --rescue-moves-per-attempt M --rescue-work W` 可为未覆盖的
真实公开后继启用上述有界离线诊断；默认关闭，`W` 与普通搜索工作分开记账。
演示的公开估值为 `HP - 0.5 × enemy HP + 0.7 × 有效 Block`，胜利取当前 HP，死亡取
明确低值。它只是可检查的占位估值，不能作为通用战术或训练标签。

执行世界来自构造配方，与八个初始候选分别持有。演示默认启用历史补充，
`--fixed-population` 可关闭。`CombatPublicHistoryV1::advance_exact` 与候选推进使用同一
观察实现；执行分支只按公共后继和观察记录匹配。真实观察未被候选覆盖时明确停止，
保留已执行输入与实际终点，不把真实隐藏状态塞回候选。结尾独立重放实际输入并检查完整
后继相等，完整策略的重建与执行匹配工作分别记录。

**这不是自然 NoSL 评测**：默认卡组是显式构造的；即使用自然 case，源状态仍保留未建模的隐藏控制器事实，
候选权重、公开估值和有限探索均未经策略质量校准。整场完成也不能作为真实胜率、自然
卡组质量或随机分布校准的证据；观察覆盖不足仍是需要单独处理的停止原因。

## 自动自然前序诊断

[`early_run_audit`](../../crates/sts_guided_search/examples/early_run_audit.rs) 从新 seed 的 Neow
开始，用显式发育规则选择路线、奖励、商店和营火，将自然获得的战斗状态交给上面的
`CombatSolver`，并把选中的完整路线逐步提交给共享 run loop。它在自然 F6–F8 地图精英
击败并结算后停止，尚未领取该精英奖励。无需人工选择或外部模型。

```powershell
cargo run --locked -p sts_guided_search --example early_run_audit -- --output .oracle-lab/early-run-audit
```

默认声明三个 seed；`--seeds` 可指定 1–16 个不重复 seed。输出目录必须新建或为空。
`manifest.json` 在任何试跑前记录全体 seed、预算及生产者；每个 seed 保存完整输入、
各步后继摘要、各场搜索根状态与资源备选、发育候选分数和实际终点，`summary.json` 逐局更新，
并直接列出当前 HP、金币、具体药水及已结算战斗的实际进出血量和用药次数；未完成者的资源只是停止时状态。
失败或 Unknown 也保留。程序从同一个新 seed 独立重放实际输入，逐步核对快照及完整终点；
重放不重新调用选择规则，也不导入预测状态。

默认每场搜索 30,000 工作单元、每局 180,000，搜索内部核验计入工作量。每局 20 秒的
协作时间预算覆盖决策与实际推进，在操作边界检查；单个操作可能超出截止点。
新局初始化、最后的整段轨迹重放与文件导出不计入该时间，实际动作数另限 1,024。
分别用 `--work-per-combat`、`--work-per-run`、`--seconds-per-run`、`--max-actions` 调整。
当前战斗尚未开始搜索、整局工作额度已经用尽时，停在 `RunSearchBudgetBeforeCombat`；
已经搜索但没有找到完整胜线时，停在 `CombatSearchUnknown`，同时保留搜索自身的停止原因。
各场记录保留宽度分配和备选路线来源；未开始的下一场不会产生一条假的搜索记录。
这两种停止都不表示死亡或无解。

此诊断的资格是 `oracle_combat_search_visible_setup_rules`：战斗搜索读取完整状态，
发育规则只使用当前可见内容；它没有 Seed-SL 的观察、回退与知识管理。
[`policy.rs`](../../crates/sts_guided_search/src/natural/audit/policy.rs) 中的分数是临时偏好，
并非学到的牌值。未列名卡牌使用按牌型的粗略分数，记录明确标为具体机制未评价；
事件只处理离开或单一继续等窄范围，无法选择时显式停止。

药水采用规则也只是占位：普通战斗若有不耗药、净掉血至多为最大 HP 的 1/8 且剩余至少
一半 HP 的胜线，就选其中剩血最多的；否则优先剩血，再以耗药数及动作数打破平分。
完整资源备选仍留在记录中，不能把这一取舍解释成药水的长期价值。

这只接通了自动自然前序及其复盘，尚未达到 [早期精英质量检查点](EARLY_ELITE.md)。
它缺少完整的战略评价、全事件支持及地图无目标分类，不作为自动整局、训练教师或
Java parity 的资格证据。评估须检查实际战损、具体药水和卡组选择；开发样例不能用少量
通关次数宣称稳定能力。人工示范入口继续保持独立。

## 跨场景公开策略搜索试片

[`task_information_search`](../../crates/sts_guided_search/src/task_information_search.rs)
对调用方提供的整局候选状态执行同一个公开动作，并按下一次公开观察分组，继续比较
战斗、奖励、地图等场景中的条件策略。它只把公开决策与历史交给动作枚举和叶节点评价；
候选状态由模拟端持有。候选世界及其权重、条件转移权重和叶值由调用方提供，来源类别随
搜索结果返回；任一后继缺失、
预算不足或叶值 Unknown 时，本次不发布部分推荐。`Complete` 只表示给定候选动作、
候选状态和深度内的比较已完成，不表示全局最优或真实胜率。
试算产生的公开历史另用 `Hypothetical` 标记，不写入任务的已提交轨迹。

除受控的跨场景合同测试外，现有一项仅限诊断的真实 Rust 转换测试：从 seed 1 的自然
开局打到首战，用精确试探选出可结算的战斗局面；搜索比较该局面的全部顶层动作，
沿真实转换进入奖励，并在奖励页观察到通往地图的后继。它使用单份真实精确状态、
人工叶值和很短的深度；遇到未展开的组合选牌家族便返回 Unknown。这个测试只核对
转换接线和来源标记，不评估路线质量、胜率或 bot 能力。当前仍没有能从公开整局历史
生成可信后验的采样器，也没有接入自然跑局 actor。精确当前 checkpoint 不能冒充普通玩家的候选分布；
使用该试片研究 Seed-SL 时须另行标记试探权限和来源。组合选牌家族的完整成员枚举
仍由调用方负责，不能凭一个顶层候选序号声称已覆盖全部合法输入。
