# dsh 游戏插件

在 DeepSeek Harness 的原生会话中操作 Rust 模拟器。官方界面负责模型运行、会话历史、
工具展示、取消和继续；插件通过共享游戏工作台提供 `sts` 和 `sts_feedback`。

当前依赖 DeepSeek Harness `0.2.1-rc.2`。宿主和插件应使用同一组 dsh 版本；
升级后重启本地服务，再新建聊天试跑。已有聊天和游戏保留，升级不会自动恢复运行。

## 在官方界面使用

先按 [RUNBOOK](../../docs/RUNBOOK.md) 构建游戏程序。在 dsh 的“插件”页选择“添加插件”，
安装本地的 `tools/dsh_player` 包。需要完整路径时，在仓库根目录运行：

```powershell
(Resolve-Path ./tools/dsh_player).Path
```

安装后应出现“杀戮尖塔”。新建会话时选择“杀戮尖塔 A20H”预设，并把本仓库选作工作区。
模型在 dsh 中选择 Flash，首次短段试跑建议将思考强度设为 Off；思考强度与输出上限仍由 dsh 管理。
API 密钥使用 dsh 自己的模型配置。
纯跑局预设只提供 `sts` 和 `sts_feedback`，不加载文件操作与待办工具。
它使用专用游戏系统提示；宿主的源码维护、网页构建和文件交付说明不进入游戏提示。
可以先发送：

> 请从 Neow 开始打这局 A20H，打赢第一只精英后停在奖励页。遇到工具问题如实记录。

首次游戏工具调用为该会话创建一局 Ironclad A20H，`sts read` 是默认起手，用来取得初始局面。
已有游戏时，`read` 只查看它的实际进度。每个会话有独立的游戏和 seed，
恢复同一会话时打开原游戏。仅安装、启用或选择预设不会启动模型或创建游戏。
游戏位于 `.oracle-lab/run-play/dsh-native-<会话摘要>`；目录中的 `dsh-native.json` 保存绑定。

原生插件支持 `manual: true` 配置；维护者预先准备的隔离交接局也可以在绑定中声明该模式。
会话创建时按绑定选择系统提示和 Rust 工作台权限，恢复与回退重连保持原模式。
手动模式只使用公开信息、真实执行和保留范围内的返回，不提供搜索、私下预演、
`deck-lab` 或精确隐蔽牌序；提示中也不再要求使用这些入口。
它允许观察实际结果后回退，不等同于原游戏 SL 或 NoSL。切换玩法请新建会话，原聊天不迁移。
`piles` 查看本战抽牌、弃牌和消耗堆的无序清单；`inventory` 保留永久卡组，不能据此判断已消耗技能还能重抽。

### 查看地图

点击聊天标题旁的“地图”，在 dsh 右侧查看当前幕的 ASCII 地图。
地图从下向上行进，圆圈标出当前位置，房间字母保持原样。
亮色突出沿普通连线可达的后路，其余淡化显示，但保留房间和连接。
精英统一显示 `E`，绿色表示携带绿钥匙；悬停顶部 `B` 可看首领名称。
图例在右侧单列显示，窄面板中移到地图下方。左侧是本幕行号，下方是列号；
悬停图例可高亮同类型房间，移开后恢复；也可用 Tab 聚焦图例。
悬停普通房间或连线可看具体坐标。
字符排布参考 [sts_map_oracle](https://github.com/Ru5ty0ne/sts_map_oracle)，内容来自当前游戏的公开地图。
工具返回后自动更新，也可以点“刷新地图”。地图不会进入模型的提示，不消耗模型调用。

地图读取当前聊天绑定的实际游戏。未开始的聊天显示“还没有游戏”，不会因为打开地图创建一局。
战斗、商店、营火和奖励页都能查看；没有公开地图时明确说明不可用。
目前显示完整公开拓扑和当前位置，不根据过去的层数猜已经走过的路线。

### 查看玩家操作

点击聊天标题旁的“对局”，在右侧打开对局工作台，查看这段聊天的步骤列表与详情。
列表显示实际命令、工具名和返回状态，可搜索命令或工具名，也可筛选“仅报错”。
默认跟随最新步骤；选中旧步骤后保持在该处，点击“回到最新”恢复跟随。
前后步按钮沿当前筛选结果导航。窄面板上下排列，较宽时列表与详情并排。

详情分别查看完整返回、模型输出和输入，支持复制正在查看的内容。
输入仅在打开该页时读取，按日志中已记录的交付边界还原；消息按角色逐项展开，
原始请求 JSON 和工具定义保留在折叠项里，也可单独复制一条消息。没有交付边界时明确显示不可用。
已读取的本步输入在页签切换时复用，步骤记录更新后重新读取。
累计 token 统计到所选轮次，包含历史的反复传入；最后一次已报告输入单独显示，不当作当前上下文长度。
本步耗时从已记录的步骤起止时间计算，未结束时不推算；本步输入量取该步最后一次已报告请求。
本步用量分别显示总输入、未缓存输入、缓存读取和输出；有缓存写入时单独显示。
总输入包含反复传入的历史，未缓存输入不等同于本步新增文字。服务商没有报告的项显示“未报告”。

日志里的返回与当前游戏分别读取。点击“当前游戏”可只读查看实际局面和库存；
游戏结束后只显示终局结果，不查询已不存在的当前库存决策。
核对期间状态变化会报错，核对后有新游戏调用记录时提示重新核对。
查看记录、当前游戏和返回点不调用模型、不推进游戏、不向聊天插入消息；未开始的聊天不会因此创建游戏。
地图与观察都使用官方只读会话检查接口，服务重启后可直接读取记录，无需先恢复玩家。

### 暂停与返回

工作台中的“暂停”停止模型并等待在途游戏操作落稳。此后发送的新消息保留在官方队列，
不会启动模型；点击“继续运行”才交付核对过的实际局面、新的返回事实和待处理消息。
单纯暂停不使同一局面下的已存胜线失效；继续时显示的胜线仍经过当前根的校验。
已成功排队交付的返回收据不在下一次继续时重复附上。暂停状态保存在
官方会话记录中，重启后仍然有效。官方销毁 Agent 时会清空未处理队列，插件不重新创建被丢弃的消息；
重开后先核对等待消息，再补发缺失的指令。聊天原有的取消按钮只取消当前活动，与持续暂停不同。
暂停后的操作落稳即释放游戏进程；查看或恢复时由同一 owner 重新打开精确存档。
暂停聊天不会持续占用旧游戏程序，从而阻止编译更新。
`deck-lab` 诊断异步运行，期间服务仍可处理暂停。取消会终止本次诊断子进程并等待它退出，
不推进游戏；同一局的其他操作仍须等它结束，已经完成的游戏动作不会撤销或重试。

点击“返回点”查看仍保留的近期提交、楼层落点和具名点，每项列出位置、血量、金币和药水。
“返回这里”先暂停模型，再由该聊天正在使用的游戏 owner 恢复精确状态与 RNG；返回后保持暂停。
“回到刚才”返回自动保留的原终点。这个自动点只有一个，再次返回会替换；具名点独立保留。
选点后游戏若已变化，旧请求被拒绝，请重新读取返回点再选择，不会自动换成另一个目标。

人工操作追加在“最近人工操作”中，旧模型步骤保持原样，不把日志步骤编号当作存档。
没有保留的历史只能查看。返回已经提交但后续核对失败时，面板保留实际收据并显示原因，
不要重复提交同一动作；先核对当前游戏。尚未提供从每个旧模型步骤直接返回的按钮。
职责和后续范围见 [原生玩家回溯设计](../../docs/architecture/native-player-workspace.md)。

### 限制实验运行

玩家空闲或暂停时，可在聊天里设置本次实验的运行上限：

```text
/sts-budget {"maxRequests":24,"maxTokensPerRequest":2048,"maxReportedTokens":20000}
```

`maxRequests` 限制从设置后开始的模型请求，重试也计数；`maxTokensPerRequest` 设置单次输出上限，
调整后下一请求使用新值，不被之前实验写入请求历史的小上限锁住。
`maxReportedTokens` 按官方用量统计非缓存输入加输出，达到阈值后不再发下一请求，
不预测当前请求的输入费用，也不是严格总量或金额上限。模型回复或不明中断缺少用量时停止该实验。
明确的 HTTP 服务错误或限流、且尚未产生任何模型内容时，允许官方重试继续；失败尝试仍占请求次数，
其未报告用量单列为未知，不当作零。已经产生部分文本、思考或工具调用后缺少用量仍会停止。
可加带时区的 ISO 时间 `deadlineAt`；到时取消活动并通过工作台的暂停 owner 等待在途操作落稳。
停止原因保留在暂停记录中。预算设置保存在官方命令记录，重新挂载时保守计入已经开始的步骤。
`/sts-budget null` 清除上限，不恢复玩家。设置上限也不创建游戏；正常跑局没有默认实验上限。

### 压缩长对话

预设提供官方 `/compact` 命令。先等模型结束，或在“对局”工作台暂停并等在途操作结束，
再在聊天输入框发送 `/compact`。它调用摘要模型，将早期对话替换为后续请求使用的摘要，
完整日志仍然保留，游戏存档不受压缩影响。压缩本身有模型用量，查看日志没有。

摘要可能记错地图或带回历史版本的命令。恢复运行前可通过“当前游戏”核对，
局面与操作以游戏实际返回为准。手动压缩不会改变自动压缩的触发设置。

### 启动和更新本地服务

已配置的工作区可以在仓库根目录运行：

```powershell
.\dsh.ps1
.\dsh.ps1 status
.\dsh.ps1 restart
```

启动器在后台运行服务，并打印可直接打开的地址。要重新试跑，新建聊天；重启服务保留聊天和游戏。
第一次启用新入口需要重启一次服务。此后修改游戏工具的 Node 代码，可以打开“地图”面板，
展开面板底部的“工具更新”，点击“更新工具”。显示“新版工具已就绪”后，新建聊天试跑；现有聊天不自动切换预设，
已经打开的游戏连接保留原实例。
代码还在加载或更新失败时，面板会显示原因，不把它报告为成功。这个操作不调用模型，也不推进游戏。

本机配置保存在 `.oracle-lab/dsh-web.json`，包含 dsh 的 `home` 数据目录、`cli` 程序路径和
`port`。路径可相对仓库填写；启动器不重新安装 dsh，也不改密钥配置。端口由其他程序占用时拒绝停止它。
启动器默认以仓库根目录为热重载基准，仅监视 `tools/dsh_player` 和 `tools/run_play`。
配置 `hotReload: false` 可关闭这项源码监视；前端内容热更新仍由官方服务处理。

展开聊天中的 `sts` 调用可看命令和完整返回。运行时可以取消本轮，随后在同一会话发送继续或纠正；
需要持续暂停或返回时使用对局工作台。正在执行的游戏动作可能在取消前完成，接续时先核对实际局面。
原生版使用 dsh 的常规历史和压缩，不在每个房间清空上下文；它不加载脚本里的分类实验或复核循环。
原生工具不编辑源码；维护者可独立修改工具，模型选择是否可靠仍需实际观察。

选项的 `|` 左侧是完整命令，直接放进 `sts` 的 `command` 字段，例如 `event:Neow:0`。
`act` 和 `preview` 的动作可用空格或逗号加空格连接；例如
`preview play:Inflame#0, play:ShrugItOff#0` 只预演整串，不会执行第二张牌。
`read`、`info` 等新命令，或显式的另一个 `act`/`preview`，会结束前一动作串。
发现牌使用 `choose:<牌名>`，牌堆选牌使用 `act select:<牌名>`，按页面显示的完整写法执行。
`inventory [effects]` 查看永久库存，`info` 展开当前事件，战斗中可用 `info M0` 查实际敌人。
`info keys` 查看已拿到的钥匙和获取条件；类别不确定时可用 `info <名字>` 查询。
`go x,y` 选择实际可达的房间，普通战与精英使用相同语法；从奖励页明确前往该坐标会放弃未领取奖励。
同样的坐标写法可用于 `act go x,y` 或 `preview go x,y`；动作串内不自动完成前一房间的选择。
第三幕相关决策会简短标出仍缺的心脏钥匙；缺钥匙时，击败双 Boss 也只结束于第三幕。
`preview event:Neow:3` 私下预演对应选项，并显示实际变化的牌和遗物，原局保持不变。
`research`、`plans`、`review`、`commit` 用于战斗；`plans` 读取已有结果，`review <方案 ID>` 与 `commit <方案 ID>` 使用显示的完整候选标识，包括 `@` 后的报告标识。
保留的胜线已从本次搜索的精确局面和 RNG 重放，包括药水生成的选择。
`commit <方案 ID>` 执行整条已保存战斗线并返回实际结果，不只执行第一回合，不重新搜索或重抽随机结果。
重新搜索后使用新报告中的 ID；旧报告的 ID 会被拒绝，不会按相同编号采用另一条路线。
手动推进后不能再采用旧搜索根的候选。搜索时间为 1–20000 毫秒，whole_combat 工作量为 1–1000000。

非战斗时可用 `deck-lab list` 查看遭遇，或用
`deck-lab Hexaghost scenarios 2 work 200000 ms 8000 potions 2` 检查当前资源。
追加 `after <当前合法的准备动作>` 可比较升级、休息、购买或抓牌后的表现。
基线和候选使用相同遭遇、诊断 seed、搜索预算和药水上限；诊断不推进原局。
结果来自固定诊断牌序，不是实际未来或自然胜率；没找到胜线也不证明必败。
默认显示开局能力覆盖、各情景的胜线资源与失败样本摘要。
每种起始药水消耗组合和总支出次数只列找到的最高结算血量，附同一条线的最低血量和回合数。
胜线总数保留在详细输出和完整记录中，不用来比较胜率或稳定性。
在 `after` 前加 `details` 会在本次诊断中输出完整逐回合信息，完整 JSON 仍保存在磁盘。

安装通过官方 bundle 合同 `dsh.bundle.patch` 和 Agent 预设声明完成，
参照 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的插件管理与预设实现。
插件注册归所属预设拥有，游戏连接归各会话拥有；启停 bundle 后已有会话的预设保留规则由 dsh 管理。

## 观察原生玩家

维护者可在仓库根目录读取官方会话日志，无需逐个展开界面中的工具调用。首次选择 dsh
数据目录和会话；`--home` 可用相对路径，`--chat` 可用唯一的会话 ID 片段：

```powershell
node .\p observe list --home <dsh 数据目录>
node .\p observe --home <dsh 数据目录> --chat <会话 ID 片段>
```

选定后只需以下短命令。这份观察来源单独保存，不切换命令行的默认游戏。

| 要看什么 | 命令 |
| --- | --- |
| 最近一轮的停点、错误和 token 用量 | `node .\p observe` |
| 第 28 步的输出、命令、完整返回及紧接着的模型回应 | `node .\p observe 28` |
| 还原第 28 步的模型输入 | `node .\p observe 28 input` |
| 核对当前游戏和完整库存 | `node .\p observe live` |

默认查询和逐步展开只读日志，不连接游戏、不调用模型，也不推进游戏。
预设要求模型在影响决策的事实或命令含义不清时，先简述疑问，再查询并使用答案。
逐步观察把本次返回与同一轮紧接着的模型输出、命令放在一起；尚无后续时直接显示记录状态。
核对查询时，结合本步 `input` 查看此前实际供应了什么，再看下一步怎样使用答案。
`live` 通过共享工作台读取实际局面和库存，前后核对状态一致，再关闭连接；它也不执行游戏动作。
运行中的日志可能尚未写入最新结果，查询失败也可能发生在部分动作完成之后，所以记录中的最后画面
与当前游戏分开显示。查看较早的一轮可追加 `--turn N`；步号属于选定的那一轮。

输入根据官方日志中的交付边界还原。原生记录没有 SDK 请求校验摘要或服务商 HTTP 请求，
因此这里明确标为日志还原；没有交付边界时不猜输入。累计 token 是截至选定轮末尾的会话用量，
包括反复传入的缓存历史，不代表单次上下文长度；同时显示最后报告的一次请求输入量。

## 脚本诊断与复核

以下是仓库内的诊断入口，使用专用 dsh 循环和按决策刷新上下文的策略。
它与原生入口的会话供应不同，结果不能直接当作原生版表现。
复核模式由高级模型或使用者检查待执行操作，接受、改选或补充指导。

在仓库目录操作。先按 [RUNBOOK](../../docs/RUNBOOK.md) 构建游戏程序并创建一局游戏，
在调用模型的终端环境中配置 `DEEPSEEK_API_KEY`。

在仓库根目录安装依赖：

```powershell
npm --prefix ./tools/dsh_player ci --ignore-scripts --no-audit --no-fund
```

查看当前局面，再继续运行复核玩家：

```powershell
node .\p player
node .\p player next
```

`player` 显示局面、卡组和待执行操作。`player next` 启动或恢复模型的工具调用循环，
运行到复核停点、终局或本次运行结束。默认玩家模型为 Flash，使用 low 推理，单次模型运行设有 90 秒时限。
首次运行会建立模型对话，后续继续使用这局游戏关联的对话。

暂停前，模型可以查询局面和机制、搜索战斗方案、进行预演，也可以领取金币或打开选牌页。
复核对象可以是一次抓牌、一组购物操作，也可以是搜索得到的整场战斗方案。
购买、抓牌、出牌、采用战斗方案、路线选择等操作会先停下来等待复核，例如：

```text
Pending proposal (not executed): take:Disarm#0
```

这表示模型计划领取 Disarm，正在等待复核。确认选择合适后执行：

```powershell
node .\p player accept
```

`accept` 执行后保持暂停。要执行后接着运行，使用 `node .\p player accept --continue`；
玩家会运行到下一复核停点或本次运行结束。改选或补充指导的命令如下：

| 想做什么 | 命令 |
| --- | --- |
| 换成自己选的动作 | `node .\p player replace <命令>` |
| 改选后继续运行 | `node .\p player replace --continue <命令>` |
| 让玩家根据纠正重新决策 | `node .\p player reject <指导>` |
| 为当前选择补充指导 | `node .\p player coach <指导>` |

`replace` 会执行改选的动作；`reject` 和 `coach` 保存指导。指导作用于当前商店、战斗或其他正在处理的选择。
已有待复核操作时，先接受、改选或拒绝，再继续运行。

当前复核范围较广，连前往房间、离开商店等推进动作也会暂停。
`--continue` 在执行成功并关闭执行连接后恢复玩家；执行出错时停下供审阅者检查。
复核停点的粒度会决定高级模型需要介入的频率。

要换一局，可以用 `node .\p <游戏短名> player` 选中它，之后继续使用上面的短命令。

## 查看最近一次调用

```powershell
node .\p player inspect
node .\p player inspect 1
node .\p player inspect 1 input
```

`inspect` 汇总最近一次运行的供应局面、工具调用、返回和记录中的最终停点，合并没有变化的输入。
`inspect 1` 展开这次运行的第一步，显示完整供应内容、模型输出和工具返回。
`inspect 1 input` 展示完整 dsh SDK 请求，包括当时的消息、工具定义和模型配置。
有失败重试时，用 `inspect 1.2 input` 指定第一步的第二次请求。

这些查询只读记录，不连接游戏，也不调用模型。查看同一玩家的其他运行，可追加
`--run <运行目录名>`；显式查看另一局也不会切换默认游戏。

新运行在 SDK 请求入口记录日志位置和输入摘要，检查时按当时的上下文边界还原并校验。
旧记录缺少入口标记时明确标为日志还原；缺失或校验失败的输入不会冒充完整输入。
这里展示的是 dsh SDK 输入，服务商适配器的后续转换和原始 HTTP 请求不在此范围内。

## 出错后怎样继续

先用 `node .\p player` 查看实际局面，再决定下一步。组合命令逐项执行，前面已经完成的动作会保留。
确认哪些动作已经生效后，用 `player reject <纠正>` 说明该如何接续，再继续运行。
如果玩家仍在运行，先等它停下。

待执行操作对应提出它时的游戏状态。期间游戏发生变化时，需要根据新局面重新决策。
停止或恢复模型对话后，插件会重新供应当前局面，让 Flash 从实际进度继续。
中断后的接续也先由宿主核对局面；已经供应的信息可以直接使用，缺信息或恢复连接时再查询。
已执行操作和当前指导随模型首次请求前核对的读数一起供应；它们按当前来源和任务决定是否仍然适用。
执行理由与仍有效的指导相同时只供应一次；不同的执行理由仍单独保留。
同一任务接续时，宿主会刷新已成功查询的具体机制和路线，再与最新局面一起供应。
旧推理、库存、预演和搜索结果不会加入这份接续信息；离开任务或显式回退后清掉查询引用。
某项查询刷新失败时标明不可用，不沿用旧答案。早期记录没有查询标记时不猜测其适用范围。

## 游戏存档、模型对话和 Node

这里有两种需要保存的东西：

- **游戏存档**：血量、卡组、地图位置、随机数状态等，保存在 `.oracle-lab/run-play/<局名>`，由 Rust 游戏程序读取和更新。
- **模型对话**：Flash 的消息、工具调用和运行记录，默认保存在 `.oracle-lab/dsh-player`，由 dsh 管理。每个玩家对话关联一局游戏。

代码中把这种支持回退、适合试跑的本地游戏存档称为 `scratch`。日常使用时把它理解为“试跑存档”即可。
回退可恢复的范围见 [run-play 使用说明](../run_play/README.md)。

一次工具调用经过这些组件：

| 组件 | 做什么 |
| --- | --- |
| dsh 玩家插件 | 给 Flash 提供 `sts` 工具、游戏读数和机制说明，保存它提出的选择 |
| Node 命令处理模块 | 解析命令、从当前选项绑定动作、排队调用并管理 Rust 连接 |
| Rust 游戏程序 | 执行游戏规则、搜索战斗路线、保存进度并返回结果 |

[workbench.mjs](../run_play/workbench.mjs) 就是中间的 Node 命令处理模块，命令行和 Flash 共用它。
Flash 给 `sts` 提交的是一条短命令。Node 解析它，按当前合法选项绑定动作，再通过结构化请求调用 Rust。
Rust 返回的选项带有来源，执行时会核对对应的游戏状态。

玩家模型调用 `sts` 操作游戏；高级模型或使用者通过 `player` 入口复核和接续运行。
Flash 实际收到的提示、工具定义和读数由 [index.mjs](index.mjs) 与 [context.mjs](context.mjs) 组织。
常驻规则使用 `info rules preparation` 的运行约束和公开威胁准备摘要；当前敌人的完整机制随战斗读数提供。
需要其他遭遇的具体机制时可查询 `info encounter <名称>`，`info rules` 仍可展开完整规则。

## 维护入口

脚本诊断入口每次启动都重新加载 Node 源码。官方 Web 服务常驻运行，更新范围有所不同：

| 修改内容 | 加载更新的范围 |
| --- | --- |
| 地图前端 `client.js` | 官方客户端 HMR 监视执行产物并推送给浏览器；通常不需要刷新或重启服务 |
| profile 配置 | 官方配置监视器重新应用变更；已挂载预设的 Agent 不自动切换到新版本 |
| 普通后端插件及静态依赖 | 需要在官方 `hmr` 配置中启用对应源码目录；重载会重新创建插件的局部内存 |
| 原生工具 `native.mjs` | 源码更新后还需要重新加载预设声明，新建聊天才使用新版本；普通模块 HMR 不负责更新已有预设的工具组合 |
| 共享工作台 `tools/run_play` | 原生插件的静态包依赖，随同一模块树重载；新预设绑定新的工作台函数，已有玩家保留原先的绑定 |
| `package.json` 的客户端声明、核心依赖 | 客户端包元数据有加载期缓存，可能需要重启服务；不能视为普通前端内容更新 |
| Rust 游戏程序 | 按 RUNBOOK 重建；已有游戏连接仍持有原进程，需要关闭后重新连接 |

官方后端 HMR 默认只监视配置，源码目录 `root` 为空。`dsh.ps1` 启动时通过官方 `--patch`
叠加本仓库的两个源码目录，不改 dsh 的用户配置文件。关闭源码监视后，后端更新仍使用
`dsh.ps1 restart`；浏览器刷新不会更新后端工具。

面板的“更新工具”通过 [updates.mjs](updates.mjs) 接入官方 `hmr.runExclusive` 和预设声明的
`fiber.restart()`。它等待官方源码处理，先检查包含工作台的静态模块树能否导入，再重新注册预设并核对加载结果。
发布版本归预设声明的 Loader entry 持有，重载面板服务不会丢失尚未发布的更新。
客户端包声明变化或源码文件丢失时要求检查后重启；Rust 二进制和核心依赖仍按各自边界更新。

共享工作台作为 `@sts-simulator/run-play` 随插件包提供，没有另一份需要手工同步的源码。
本地依赖指向 `tools/run_play`，因此这个目录中的命令修改也属于原生插件的静态依赖链。

这里重载的是预设声明，已挂载的 Agent 保留原版本；它不迁移旧工作台或模型上下文，
也不取消正在执行的游戏动作。需要让已有聊天换工具时，先停止模型并核对实际进度。
当前推荐用新聊天验收新版，不在持续跑局中强行替换已有工具。

依赖版本记录在 `package.json` 和 lockfile 中，升级时核对整组版本并运行插件测试：

```powershell
node --test tools/dsh_player/*.test.mjs
```

自定义任务、运行时限和其他启动参数见：

```powershell
node tools/dsh_player/launch.mjs --help
```

维护者复核由 [supervision.mjs](supervision.mjs) 处理；独立 dsh 宿主加载本包时还需挂载 `context` 后端。
显式准备实验的入口及参数也在启动器帮助中，相关实现从 [preparation.mjs](preparation.mjs) 查看。
