# Rust 对象式交互

`client.mjs` 通过 stdin/stdout 直连 `run_play.exe agent-shell`，没有 PTY 标题序列和命令回显。
Rust 拥有状态、来源检查、真实执行和提交；客户端只保存返回对象和传输记录。

`observe()` 的战略观察另含 `preparation_reading`（`sts-preparation-reading-v1`），与 `position.public_snapshot_id` 绑定同一公开帧。它提供概要、选项、选牌提示、库存、商店商品和路线的文字块。候选通过完整命令定位，卡牌规则通过稳定 ID 和升级等级定位，遗物通过稳定 ID 定位；商品包含 typed action、槽位和价格，买不起或其他受阻商品的 `command` 为 `null`。`card_rules.available` 来自源端规则覆盖。消费者按这些字段选择完整文字，不解析展示标题或译名。战斗和终局不提供这份战略准备投影；普通 `read` 和 `inventory effects` 的文字仍由原有 renderer 输出。

从源码使用 Node 工作台前，在 `tools/presentation` 与 `tools/run_play` 各执行一次 `npm ci`。工作台通过正式依赖消费共用语言资源；[分发构建](../../docs/runbooks/release.md)捆绑该依赖及其运行库，并用离线安装检查实际中英文读数；开发源码链接保持不动。

`workbench.mjs` 是命令行与 [dsh 玩家插件](../dsh_player/README.md) 共用的命令 owner。
`openWorkbench` 固定绑定一个会话，`execute` 接收短命令并返回 `{ text }`，输出不写到全局 stdout。
本次返回实际展示了当前读数时，结果另带 `currentReading: { control, summary, text }`：摘要来自 Rust，文字是本次返回中保留的最后一份实际局面读数，使用同样的命令前缀。私下预演和纯规则查询不生成它，失败调用也不借早先的读数生成当前边界。此数据用于日志与上下文压缩，不应重复渲染到模型消息。
命令逐条排队；部分成功后的错误保留前面的收据。回退先关闭连接再恢复、重连，关闭等待进行中的命令。
新连接始终使用新的记录目录，不改变共享 CLI 焦点。直接使用时传绝对路径的 `repository`、`session`；
可指定 `binary` 和一个尚不存在的 `recordDirectory`。

公开信息手打使用 `openWorkbench({ repository, session, manual: true })`。该连接的 Rust
协议只开放读取公开状态、机制查询和真实执行；不开放搜索、已有方案、私下预演或精确隐蔽牌序，
工作台也关闭 `deck-lab`。`back`、`undo`、`jump` 和具名点仍使用现有保留范围，恢复原有随机数状态。
这是允许实际尝试后回退的玩法，不能标作 NoSL 或原游戏 SL；返回范围也不等于永久保存全部历史。
`manual` 约束该工作台及其重连，不给底层存档加锁，也不改变其他 CLI 或 dsh 连接的模式。
`piles` 按牌名合并显示当前抽牌堆、弃牌堆和消耗堆，来自公开观测并隐藏排列顺序；
已消耗的技能不会因仍在永久卡组中而回到本战循环。`piles sl` 仍是显式的精确牌序入口，手动模式禁用。
战斗简版列出当前可用的出牌和药水命令，相同属性的副本按目标合并；`options` 展开每个副本及弃药等辅助操作。
`Invincible` 显示当前剩余伤害额度与重置上限。`info card BodySlam+` 按升级版查询定义，
不带后缀时查询基础版；多次升级使用 `+N`，当前战斗实例的费用和伤害仍以手牌为准。

`info card <稳定 ID>[+N]` 使用原版中英文牌面资源，按工作台的 `agentLocale` 显示名称、类型、牌面基础数值与攻击目标，保留稳定 ID。升级模板由卡牌 owner 按实际升级行为选择，数值来自同一份永久卡牌定义；战斗中的附加伤害提示不用于定义查询。原有完整机制详解继续保留，中文查询将其标为英文补充。

战斗 `read/options` 的手牌、当前费用、逐目标伤害、格挡、敌人意图、状态计数和选牌提示已随连接语言呈现。它们使用同一份公开事实，不因语言重新计算伤害或读取隐藏意图；M 槽位、选牌 token、选择范围、快照与命令保持不变。完整战斗读数复用原版牌面、药水和共用规则；尚未迁移的卡牌、遗物与敌人机制长文在对应段落标明英文。候选卡牌与准备投影的卡牌规则沿同一原版定义牌面 owner 呈现；战略概览、资源摘要、奖励与商店标签、营火升级差异、钥匙状态、完整钥匙查询和跨幕提示也使用连接语言。地图路线、精英比较和准备路径共用原生本地化 renderer；事件名称、已接入的正文与按钮使用原版语言资源，候选中的原始事件标签保持源端文字；结构化效果、概率、牌池和后续阶段随连接语言呈现，其余机制正文继续迁移。

每个工作台的记录目录保存 `workbench.json`（绑定、模式、打开时间）、`commands.jsonl`
（命令开始、完成或失败、返回内容、耗时和分支变化），以及各连接的原始传输记录。
失败和回退保留在同一记录中；这里的耗时是工具执行耗时，不包括玩家思考时间。

指导 dsh 玩家时，`node .\scripts\p.mjs player` 显示当前局面和未执行提议，`player next` 调查到下一次提议，
`player accept` 或 `player replace <命令>` 由维护者复核后执行。玩家绑定保存在当前游戏目录，
无需反复写玩家 ID 和 home。安装、纠正与恢复合同见 [dsh 插件](../dsh_player/README.md)。
执行后接续到下一复核停点可用 `player accept --continue` 或 `player replace --continue <命令>`。
`player inspect` 只读最近一次运行的输入、工具调用和停点；`player inspect 1 input` 展开当时的 dsh SDK 输入。

奖励页标明剩余奖励数量，全部处理完后显示 `Rewards complete`，`proceed` 的说明为离开奖励页。
选项行左侧是可执行命令，右侧的 `Effect:` 是该命令的说明。
地图选择的 `Next rooms` 标明当前合法路线选项的数量；关闭地图和药水管理不计入房间数量。
简版末尾的辅助命令提示 只列尚未展开的辅助操作类型；药槽满时仍直接显示待领取药水和替换操作。
抓牌、商店、营火、事件、遗物和牌选择页附当前永久卡组计数与遗物的紧凑清单。
营火升级每次只升级一张；相同副本合并显示时明确标明从这些副本中选择一张。

`inventory` 按永久卡组统计副本和遗物；`inventory effects` 另列包含永久改值的费用与原版牌面、基础抽牌和普通打出一次的固定格挡请求，以及已持有遗物与各药水槽的规则（是否可用仍以当页合法选项为准）。库存沿工作台的 `agentLocale` 呈现，CLI 可用 `run_play inventory --session <path> --effects --locale zh-CN`。卡牌按稳定 ID 和全部永久实例字段分组；同名不同 ID 不合并，显示名相同时附 ID。战斗中读取 master-deck snapshot，不用临时生成牌或战斗升级替代永久卡组。牌面保留成长值与伤害/格挡改值；基础请求另行标明其定义范围，随后仍受实例和战斗修正影响。完整卡牌与遗物机制补充仍为英文，中文库存明确标注。
机制摘要位于卡组清单之后，引用的是同一批已持有卡牌，不增加卡组副本。
`deck-lab list` 或 `deck-lab TheHeart scenarios 3 work 200000 ms 8000 potions 2` 在非战斗时
调用同一 Rust 当前资源诊断；默认药水支出为 0，`full-hp` 显式改为满血。使用固定诊断 RNG，
不推进游戏、不读真实未来，不估计自然胜率。完整结果自动保存在本次传输记录目录。
`list` 同时给出调用格式和 `after` 的私下准备方式，比较前不必实际执行准备再回退。
选择前追加 `after <准备动作...>` 可测试当前合法升级、抓牌、购买或其他准备后的实际资源，
例如 `deck-lab Collector after smith:PommelStrike#0`。附带选牌一并写在动作链中；原局不变。
默认返回准备比较所需的资源、开局能力覆盖、胜线和失败样本摘要。
每种起始药水消耗组合和总支出次数只列找到的最高结算血量；最低血量和回合数取自同一条线。
这不是对其他线路的优劣排序。胜线数量只在详细输出和完整记录中显示，不作为成功率。
`details` 可在本次诊断中加入逐回合轨迹，放在 `after` 前；它重新运行当前资源的诊断。
基线与候选使用相同遭遇、预算、血量策略和药水上限。随机准备只展示一个精确实现结果。
`map elites` 调用 Rust 的公开路线分析；有不同精英数量的分支同时显示
最大与最少精英路径，作为可核对的实际连线，不推断战损或推荐走法。商店和篝火的 `read full`
按当前房间的实际出口展开准备路径，排除当前房间和其他分支的商店。
地图页默认读数与 `map` 显示当前地图的 Boss 和分组路线。每条路线均沿地图的实际房间连接。
下一间只有 Boss 时，直接显示其名字与坐标；其余局面展示分组路线，符号说明标为 `Legend`。
按首个精英前营火/商店有无、是否经过绿钥匙精英、终点是否已公开分组，
各组列出最少/最多精英的路线；同数量按坐标稳定选择。`map full` 展开全部公开节点和连接。
Boss 身份未公开时显示 `Boss not revealed`；问号房间的类型在进入时揭晓。
普通房间连写成 `MM?`；商店、营火、精英、宝箱和每个岔口选中的出口保留坐标，
坐标保留圆括号，路线分支用 `[A | B]`，分叉房间与合流房间均标坐标。
方括号合并共享前缀与合流节点的两条路线，不嵌套；
分歧段包含多只精英或只在 Boss 汇合时分行显示完整路线。
共同后路较长时，按同一个真实房间拆成 `Approaches to` 和 `After`，入口概览仍来自全部普通后路。
列出的每条前路都能接该房间后的任意一条路线；不经过该房间的路线单列。
仅当这样确实缩短输出时使用，保留原先选出的全部完整路径，不按字母相似猜合流。
多个入口共用一行表示各入口均有该显示序列的真实路径，不表示它们已经合流。
已知断点或未公开端点保留 Unknown；营火、商店和战斗中查询从当前房间的出口开始。
`map full` 展开全部节点和连接；`map flip` / `map normal` 也显示全图，`map set flip|normal`
只改变全图的方向偏好。网格用 `M(1,4)->(1,5)/(2,5)` 明确分隔目的地。
路线和文字全图均由 Rust 随连接语言绘制，Node 只传方向偏好。全图默认大 y 在上，`flip` 则小 y 在上；宝箱层与 Boss 前全营火层保留行标记。CLI 可用 `run_play map --session <path> --locale zh-CN full --flipped`。
`map route X Y` 显示从指定房间离开后的完整连通路线，查询起点不计作未来房间。
单出口走廊保留在路线里；各出口附所有普通后路的精英数量范围、绿钥匙是否必经和商店可达性。
随后列出会改变精英数量、绿钥匙、首精英前准备类型或商店可达性的后续岔口。
这些范围和必经关系按全部普通后路计算；尚未公开的后路标为 Unknown。
查询不可达节点时明确提示，但不会执行路线选择；同类路线的其他连接仍可用 `map full` 查看。
`map elites` 与 `read full` 保留详细诊断，未知地图命令直接报错。

```javascript
const { openRunPlay, getRunPlay } = await import('./client.mjs');
const game = await openRunPlay({ repository, session, recordDirectory });
const reading = await game.decision();
// Read reading.view, then select an object from this same reading.
const next = await reading.options[index].choose();
// Typed facts stay inside the adapter; show concise mechanics text to a player.
const facts = await game.gameFacts([{ kind: 'card', card: 'Dropkick' }]);
const mechanics = await game.info('card Dropkick'); // concise text in mechanics.view
await game.close();
```

三个路径参数使用绝对路径，`session` 必须存在且与当前来源匹配，`recordDirectory` 必须是新目录。
默认二进制为 `target/dev-opt/run_play.exe`，可显式传 `binary`。同一 Node host 中每个会话只开
一个连接；已打开的连接用 `getRunPlay(session)` 取回。关闭连接不自动关闭 Java 或删除会话。

## 单命令工作台

[`play.mjs`](play.mjs) 把上面的连接封装成每次决策一条短命令，[`scripts/p.mjs`](../../scripts/p.mjs) 是命令行入口；自动创建全新的传输记录目录。本地也可按[开发脚本说明](../../scripts/README.md#optional-local-shortcuts)创建根目录短命令。

```bash
node scripts/p.mjs <会话短名或路径>           # 开工时选中会话并读取状态，此后成为默认会话
node scripts/p.mjs                           # 重读默认会话，默认简洁读数
node scripts/p.mjs help                      # 显示短命令帮助，不连接游戏或检查构建
node scripts/p.mjs read full                 # 展开背景机制、钥匙教程与准备路线示例
node scripts/p.mjs read brief                # 与 read 相同：当前资源、选择和候选效果
node scripts/p.mjs 0                         # 选择一个当帧选项（奖励页使用下面的名称命令）
node scripts/p.mjs 0 1                       # 仅用于同一张选牌界面内的多选，不跨页面链选
node scripts/p.mjs claim:BagOfPreparation#0   # 领取指定遗物；直接复制奖励页显示的命令
node scripts/p.mjs claim:SapphireKey#0        # 选择蓝钥匙，不受金币领取后的行号变化影响
node scripts/p.mjs act <动作...>              # act CLI 同款语义动作串
node scripts/p.mjs preview <动作...>          # 私有分支预演，不移动正式进度
node scripts/p.mjs loot                      # 领金币；药水全能装下时自动领，容量冲突留给玩家选；其余奖励处理完才打开选卡
node scripts/p.mjs map                       # 从当前出口到 Boss/公开端点的压缩路线样例
node scripts/p.mjs map route 5 8             # 从指定房间离开后的路线样例与后续岔口取舍
node scripts/p.mjs map full                  # 全部公开节点和连接
node scripts/p.mjs info                      # 当前原生选项与效果详情，使用连接语言
node scripts/p.mjs info SporeCloud            # 按完整状态名或 ID 查定义，战斗外也可查
node scripts/p.mjs info FungiBeast            # 当前难度下的敌人招式定义，不预测未来随机招式
node scripts/p.mjs info M0                   # 当前敌人的可见意图、状态、机制
node scripts/p.mjs info player               # 玩家当前状态的含义与剩余量
node scripts/p.mjs info powers               # 展开玩家和场上敌人的状态说明
node scripts/p.mjs info transition 25        # 假设幕间恢复前存活血量为 25，按当前上限和难度计算恢复后血量
node scripts/p.mjs piles sl                  # 显式读取当前战斗的精确牌堆；SL 内部信息
node scripts/p.mjs info card Dazed           # 卡牌基础属性与已覆盖的效果说明
node scripts/p.mjs info card Uppercut        # 明确查询卡牌，避免与同名状态混淆
node scripts/p.mjs exe history --journey --last 1           # 最近一段正式轨迹的事实摘要
node scripts/p.mjs exe history --journey --last 1 --detail  # 逐动作展开记录中的血量、格挡和状态变化
node scripts/p.mjs options                   # 展开当前页面的全部选项，包括战斗外用药、弃药和移除
node scripts/p.mjs research [毫秒] [work 转换次数]  # 默认 whole_combat；也可显式写档位
node scripts/p.mjs plans [full]              # 重读保存的报告；full 展开诊断，不重新搜索
node scripts/p.mjs commit <方案ID> [预期档位]
node scripts/p.mjs review <方案ID> [回合]
node scripts/p.mjs undo                      # 回退最后一次公开动作，显示简洁后继读数
node scripts/p.mjs jump                      # 只读当前局面，并打印可复制的返回命令
node scripts/p.mjs jump nNODE                # 直接跳到本会话已保留的决策点；复制实际返回命令
node scripts/p.mjs refresh <新会话名>        # 来源变化时核验当前精确状态，建立并选中新会话；不写中间胶囊
node scripts/p.mjs exe <参数...>             # exe 子命令透传（status/history/...）
node scripts/p.mjs new <会话> <seed> [--ascension N] [--goal heart-victory]
```

`research` 和 `plans` 默认只标出搜索起点的回合、血量、完整候选数与停止原因。
每条候选本行显示战后血量、最低观测血量、额外药水支出和采用命令；已消耗的起点药水附槽位与药名。
存在不同药水支出时，简洁页按支出数量和具体起点槽位分组，保药组先显示，组内保留原顺序。
交药候选附相对本报告中最高战后血量保药胜线的血量差；这是结局差值，不是药水的价格或因果收益。
没有保药胜线时明确限定为本报告未找到；逃跑结局不作为胜线比较基准。
各 `cN` 与采用命令保持原绑定，分组不删除候选，其他资源差异仍在各方案下展开。
支出包含使用、弃药和被动消耗，从搜索起点计；中途续搜之前的支出不计入新候选。
共同模拟药水奖励只显示一次，并标明尚未领取；金币追回差异单独显示，不重复整份共同奖励。
非金币奖励确实不同则逐候选保留，完整待领奖清单也可用 `plans full` 展开。
战后血量包含战斗结算与回复，最低观测血量读取重放的公开动作边界。
候选编号及诊断页顺序只是展示：先列战后血量较高、药水支出较少的方案；两项相同时，
先列未被盗走金币、待领取金币更多的方案，最后才比较动作数。顺序不定价药水、
香炉计数或其他跨战资源，也不表示推荐采用第一条。
持久遗物计数、永久成长、诅咒等卡组变化、遗物失效和生成药水继续展示。
共同持久计数与永久成长只显示一次，差异保留在各 `cN` 下；共同普通金币不在默认面重复显示，
盗窃或候选金币不同仍显示。`plans full` 展开起点手牌、能量、能力、药水，搜索目标、预算、
各通道工作量和开局动作，读取同一份保存报告，候选与报告身份保持一致。
香炉计数附下一战触发回合，由遗物 owner 投影。战斗内会重置的计数按遗物 owner 分类省略。
`review` 沿同一动作线核对，战后血量包含结算与回复。每条 T 行给出回合开始的血量、格挡和能力，
以及本回合观测到的血量变化；`Block before End Turn` 尚未包含回合末触发，
血量变化包含回合末结算与敌方动作，后续回合行显示实际保留的格挡。
`review <方案ID> <回合>` 展开该回合的手牌、可见意图与变化。
方案 ID 包括 `@` 后的报告标识，直接复制报告中的完整 ID。重新搜索会生成另一份报告；
旧 ID 被拒绝，不会按相同候选编号采用新报告中的另一条路线。
Rust 报告渲染器直接生成完整 ID、候选比较引用和复盘分页命令；对象 API 通过 `candidate.planId` 返回同一 ID。客户端不解析标题或改写报告文字，原生程序和客户端须一起更新。
旧报告缺少最低血量时显示 Unknown，展开 `review` 可从重放核对。

`loot` 自动领取金币，并在所有待领奖药水均能装下时领取药水。待领奖药水多于空槽时停在奖励页，
由玩家选择领取或换药；卡牌、遗物与钥匙保持显式选择。容量冲突的奖励读数直接展示合法用药和
弃药命令，释放槽位后从新读数领取。Sozu 的获取限制也在奖励页显示；其药水领取动作清掉奖励，
保持持有药水不变，`loot` 沿这一实际效果处理。
`preview` 的假设后继沿用正式决策读数：发现、消耗或弃牌的附带选择与牌面规则同时展示，
原局仍停在预演之前。可把后续选择接进更长的预演动作串，也可采用动作后在正式页完成选择。

在 PowerShell 中用 `node .\scripts\p.mjs ...` 调用这个无扩展名的 Node 入口；`node scripts/p.mjs` 适用于支持 shebang 的 shell。
`act`/`preview` 内的动作可用空格或逗号加空格分隔。例如
`preview play:Inflame#0, play:ShrugItOff#0` 会一起预演两张牌，不执行第二张。
`read`、`info`、`inventory` 等明确的新命令会结束动作串；
`preview event:CursedTome:0, act event:CursedTome:0` 表示先预演，再实际采用。
分号始终开始另一条命令。普通奖励链如 `claim:Gold#0, open-card#0` 保持逐项执行。
地图显示的 `go x,y` 也可放进 `act` 或 `preview`，例如 `preview go 1,0`。
动作串中的 `go` 必须给出坐标，按当前阶段的合法路线验证，不自动完成奖励或营火选择。
第三幕的地图和钥匙选择机会简短显示仍缺的心脏钥匙；集齐后不再显示。
发现牌用 `choose:<牌>`，消耗、升级等手牌选择用 `select:<牌>`；例如
`preview use-potion:PowerPotion#0 choose:DarkEmbrace play:DarkEmbrace`。
实际提交成功后显示后继局面，输入由调用本身表达，不再重复回显。
串联的 `read`、`options`、`board` 和地图查询用所请求的当前页替代此前自动显示的同局面读数，
避免简洁页和展开页重复；显式查询结果仍保留，查询失败也保留已执行动作的后继读数。
预演标为 `Preview result`，并说明正式位置未改变。因战斗提前结束而裁掉的尾部
不计入已执行动作。`client.mjs` 的对象接口与短入口均保留完整 JSONL 请求。

工作台的普通读取、执行后读数与预演默认使用 Rust 的 `brief` 投影；当前资源、候选效果、
附带选牌规则和药槽冲突提示保留，背景说明按需用 `read full` 展开。
`options` 展开所有当前合法操作，`map` 展开公开路线；这些查询不推进局面。
普通战斗默认只额外列出有差异的同名卡牌副本与需要指定敌人的药水命令；
无需指定敌人的药水保留在药槽行，完整使用、弃药命令按需用 `options` 展开。
执行后的简洁读数直接来自同一次提交响应，不为缩短输出另发一次读取，也不按文字标记裁剪。

开工选中后先核对局面，此后不必每步重复路径。默认会话是仓库内共享的便利指针；切换操作者
或任务时重新核对，同一时段由一个操作者推进。任何命令仍可显式传会话以指定目标。
省略会话时使用默认会话；已有默认会话也可以显式传短名。会话完整名称优先于唯一片段匹配，
多个匹配会报错。固定命令和选项编号优先作用于默认会话，其余参数优先匹配已有会话，再作为
选项名称。遇到重名，用会话路径明确区分，例如 `node scripts/p.mjs ./路径/map` 读取名为 map 的会话，
`node scripts/p.mjs ./路径/当前会话 Bash` 选择该会话中的 Bash，不受另一个名为 Bash 的会话影响。

act 的糖：`play:X@1*3` 展开为三张同名连打，Rust 逐后继解析等价副本和唯一合法目标，
客户端不猜 `#0` 或 `@0`。费用不足、牌不在手中或真实歧义会原样报错，不改写动作重试。
回溯后想控制具体副本的弃牌顺序时，写显式 `#序号`（如 `play:Strike#1@0`）。仅当引擎
明确报告前缀已结束战斗，且末尾只剩出牌或 end 时，裁剪末尾并重试一次。出牌名尽量短：`play:Strike`
优先匹配基础版；没有基础版且仅有一种升级等级时匹配该升级版。显式写升级版 `play:Strike+`、
基础版 `play:Strike+0` 或更高等级 `play:SearingBlow+2`；一级升级也接受 `play:Strike+1`。
不要写 `Strike++`。`@0` 仅用于以敌人 M0 为目标的动作，不给 Defend、Shrug It Off 等无目标牌添加。
若升级、费用或目标等差异
导致歧义，从错误列出的精确动作中选择。`act` 在同一响应中返回已提交的后继读数；多动作自动带
`one_public_action`，仍为整串原子提交。战斗读数省略静态牌组/Boss 行，保留遗物与动态计数。
动作串逐步作用于前一步产生的局面。若出牌触发自动结束回合（如 Time Warp 达到 12），
其后的 `end` 会结束新回合；它不会因前一回合已经结束而被忽略。手动出牌时先检查触发后的
回合和手牌，再决定后续动作。
地图选项直接显示可复制的坐标命令，例如 `go 6,8`；精英房使用相同语法 `go 1,7`。
房间类型显示在命令说明中，不改变输入语法。
当前地图只有一个合法出口时，可用 `go` 省略坐标；有多个出口时显示当前地图供选择，停留在岔口。
奖励已全部处理时，带坐标和省略坐标的 `go` 都会退出空奖励页。
剩余奖励可以逐项处理或用明确坐标离开；省略坐标的 `go` 不替玩家决定放弃奖励，也不自动跳过正在打开的选牌页。
省略坐标不自动退出其他尚未完成的房间。
停在岔口时也停止当前逗号命令串，后面的搜索或动作不会执行；明确选好路线后再继续。
`go` 也会跨过事件的唯一无效果结束或叙述页，例如 Neow 的变牌后离开页和第三幕 Heart 叙述。
仅采用引擎提供的空效果列表，不凭按钮文字判断；有成本、未知效果或多个选择时仍停留。
默认读数区分房间动作与选择下一房间：普通地图标明当前已完成节点；地图覆盖层标明当前节点，
并说明 `cancel` 返回房间画面。入口没有当前节点时不补写完成状态。
局内战斗与战斗外读数共用当前钥匙状态；`info keys` 同时显示已取得、尚缺的钥匙和获取规则。
独立战斗没有跑局上下文时，查询明确说明当前钥匙状态不可用。
`scout`（fork 探针侦察房间）已按所有人要求禁用：未知的房间与看过的房间是两种决策，剧透本身改变了选择；
需要房间情报时用 `map`/`info` 只看公开状态。`exe`/`undo`/`new` 直接运行
`target/dev-opt/run_play.exe`（含其自带的新鲜度校验），与 `run-play.ps1` 指向同一 owner。
普通编号一次只选当前一项，多编号仅用于同一选牌界面的多选。奖励页不接受裸编号，
而是显示 Rust 返回的语义动作短命令，例如 `node scripts/p.mjs claim:BagOfPreparation#0`、`node scripts/p.mjs open-card#0`、
`node scripts/p.mjs proceed`。领金币、领遗物和选钥匙后即使行号变化，名称也不会被解释为另一个奖励。
`#0` 是同名选项的实例序号，不是页面行号；命令不存在时原样报错，不猜另一个选项。
既有唯一名称选择如 `node scripts/p.mjs "Bag of Preparation"` 仍可用。串联操作时使用名称命令，不预写后继编号。
选牌页的 `skip-card` 返回奖励页，保留重新打开选牌的机会。决定离开时用 `proceed`，
或 `go 4,2` 离开奖励页并前往指定坐标，尚未领取的奖励随之放弃。
从商店或显式放弃奖励后前往指定坐标时，离开和旅行由 Rust 一起准备、一次提交；
目的地不合法时整条线不提交，保留当前房间和奖励。

`node .\scripts\p.mjs exe compare --artifact <新文件.json> '<动作/动作/...>'` 可保存只读试演。
若所有动作都属于战斗，磁盘 artifact 另含 `combat_replay`：精确根状态、已解析的输入与
后继状态，供离线工具直接重放；其中包含隐藏信息，不是公开玩家观察。普通返回读数不展开
该数据。含战斗外动作的轨迹只保留原有公开投影；旧 artifact 不会自动补写私有重放数据。

选卡、发现、移除和升级的普通选项行直接显示可复制的准确命令，例如
`node scripts/p.mjs take:Armaments#0`；战斗选牌显示 `node scripts/p.mjs act select:<卡牌>`，发现牌显示 `choose:<卡牌>`。
战斗外多选（例如 Empty Cage 移除两张牌）同样使用 `act select:`，按当页 `Input` 一次提交所需卡牌，
例如 `node scripts/p.mjs act select:Parasite+0#0,Strike+0#0`；卡牌 token 之间的逗号不加空格。
这些语义动作也能接在同一条 `preview` 或 `act` 的中途。原有同页编号选择仍可用。
所见命令、奖励说明、升级说明及多选 `Input` 均由 Rust 从当前 typed choice 生成。Node 原样显示，不解析英文行号、动词或标签；显示战斗外读数不再补取观察。预演沿相同公开事实展示选择和规则，保留假设读数，不添加当前操作前缀。

命令替换原有选项行，不附加第二套列表。较长的营火升级列表默认按牌名汇总，`node scripts/p.mjs options`
展开每个实例的命令。战斗默认读数仅为费用、升级等属性不同的同名手牌补充当前合法的准确命令
及费用；等价副本不重复列出。战斗默认读数同时列出合法用药、弃药命令及对应槽位，
药水命令里的 `#序号` 是同名药水的出现序号，槽位 `P1` 可以对应 `PowerPotion#0`。
卡牌的 `#序号` 是该名称/升级态的出现序号，不是手牌位置，并且出牌后会变化；
需要区分时复制当帧命令，不预写后继序号。`options` 额外列出当前合法的出牌、结束回合、
用药和弃药命令，药水实例与目标由引擎提供，不按 P0/P1 槽位猜 `#序号`。

对象接口的 `reading.view` 与命令行共用 Rust 的手牌读数，无需另取数组补数值。例如
`Cleave[1c M0:12d M1:8d all]` 表示对两个目标的伤害不同，只有数值相同时才合并。
`Twin Strike[1c 10dx2]` 表示两段各 10；`Fiend Fire[2c 7d/hit]` 表示每段 7，段数随结算时手牌变化。
`all` 为全体，`random` 为各段随机目标，`b` 为当前格挡。`d` 是每段、扣格挡前的当前伤害，
也不预先计入本回合尚未打出的增益、减益或后续手牌变化。`board` 的目标命令使用对应目标的数值；
手牌格挡总和只是各牌当前投影之和，未计费用、出牌顺序和次数限制，不表示本回合可获得的格挡。
普通读数保留遗物计数，并显示当回合已打牌数与攻击牌数。卡牌有数值不代表当前一定可打；
准确合法命令仍由 `options` 提供。宝箱页同时提供开箱和 `proceed` 离开未开宝箱，两者均需明确选择。

模型工具读数通过连接的 `locale` 选择语言，当前覆盖范围见本文末的语言说明；`P_DISPLAY` 和 `display-prefs` 不提供语言设置。
事件标题显示当前 `Event screen N`；连续相同的 `Continue` 标签可能推进到不同对话阶段，
直到真实流程返回地图。阶段号来自当前 typed 事件状态，不依赖剧情文本判断。
普通读数由 Rust 将当前页面选择排在前面，战斗外用药、弃药及移除目标收起。`options` 展开时
保留前面选项的编号，再追加管理操作；药水库存始终可见。显示编号绑定原始选择对象，不等于
底层引擎候选编号。按名称选项也沿这个绑定解析，重名或歧义报错。

成功动作只显示后继局面；逗号分组及 `loot` 的中间页面合并为最终页面，不重复回显输入或动作。
变牌、事件与遗物带来的实际牌组变化另显示一行，包括 Pandora 换牌和随机升级；
这条结果在后继页面合并和显式读取时保留。没有牌组变化时不添加空回显。
商店简洁页仅为可买物品与可通过换药领取的药水展开效果；买不起的库存仍保留名称、价格与原因，
需要其完整规则时用 `read full`。
各步仍从新读数绑定新对象，查询命令的输出独立保留。后续失败时列出已确认执行的动作和最近读数；
传输结果不确定时仍需重连核对，不能据此重试。完整请求与返回留在连接记录中。
`preview` 明确标明正式位置未改变。`loot` 只自动领取 typed 合法金币与药水，不代选卡或用药。
遗物、钥匙或不可领取的药水仍待处理时保留奖励页，避免开牌后遮住这些选项。
可以明确调用 `open-card` 延后其他奖励；一旦进入选牌页，需拿牌或跳过才能回到剩余奖励。

`exe status` 是诊断面；旧证据会话可见来源信息，日常 scratch 只显示当前局面。
不要用诊断面的**引擎**候选编号调用 `node scripts/p.mjs N`。
其中 `Route via ordinary connections` 只表示下一个岔路前的普通连线路段，不锁定路线计划。
飞行靴的实际可选节点仍以当前地图选择为准，单一路段摘要不排除飞行。
`hN` 是会话修订号，`n...` 是历史节点摘要，`last ... anchor-line` 表示上次提交了多步动作；
日常读局、选择、预演无需复制这些标识。恢复与历史诊断才使用其完整、带来源的对象。

`info` 不带参数仍展开当前决定的机制详情；带参数查询状态、敌人或卡牌说明。名称使用完整显示名或
稳定 ID，忽略空格与大小写，不猜相近拼写。`info help` 说明查询形式；`M0`、`player`、
`powers` 仅用于当前战斗，按词条名则可在奖励等页面查询。
`info rules` 说明当前难度下的跨幕回血、商店删牌价格累进和 A20 连续 Boss 规则。
`info rules preparation` 使用同一机制来源，供应准备规则、钥匙时机、公开遭遇的状态牌与开场能力关系摘要。
完整敌人招式仍由 `info rules` 或具体遭遇查询展开。
仅含 `info` 的调用（包括逗号分隔的多次查询）直接运行只读查询，不额外启动交互连接。

说明来自 Rust content owner；敌人数值复用执行时的招式构造函数，按当前难度输出基础值，
与当前可见意图区分。当前伤害仍以带状态修正的可见读数为准。查询不运行敌人 AI 或 RNG，
不猜隐藏意图，不写入游戏进度。持续时间类状态显示剩余回合，不能将其当成最初施加量。

说明覆盖由各 content owner 定义，包含状态、敌人招式、卡牌、遗物和药水；
`info card` 包含 Warcry、Rampage、Blood for Blood、Dropkick、Havoc、Dual Wield、Exhume
的条件、实例变化及选择效果。基础属性不替代当前手牌的升级、费用和逐目标伤害读数。
名字有冲突时默认状态优先，如 `info Anger` 是状态，`info card Anger` 才是卡牌。
其他已知词条缺少说明时明确显示该缺口，未知名字报错；不把缺少说明解释为不能执行或效果为零。
遗物查询还显示当前是否持有，以及适用的计数和 `used_up` 标记；当前观察不可用时只给定义，不将缺少上下文解释为未持有。
依赖未覆盖机制才能确定的决策应报告疑点，不以记忆补写成工具事实。

`game.gameFacts(entities)` 在原连接内批量读取卡牌当前/升级后、遗物和药水的 typed 机制事实。
战略 `game.observe()` 的 `deck_evidence` 从公开永久库存和共享卡牌实例读数生成，绑定
`public_snapshot_id`。每组保留完整永久属性、数量、定义机制和实例费用/伤害/格挡；
卡组变化后以新观察重建，定义参数与实际效果请求按各自机制区分。该字段供适配器整理构筑比较，
完整结构留在磁盘，模型接收按需渲染的文字。
`game.info(query)` 在同一连接内返回与 CLI `info` 共用的简洁说明，不推进游戏。
旧战略黑名单及其统一判罚已删除；条件返费/抽牌、实例成长、复制和消耗牌回收分别表达。
事实接口不返回笼统的全覆盖标签，也不保证长期估值准确；适配器按需渲染文本，不直接倾倒完整 JSON。

Rust 返回的命令错误以 `RunPlayCommandError` 保留 `code`、`command`、`requestId`
及 `recordDirectory`；短命令入口同时打印错误码。连接失败保留原系统错误码或客户端错误码，
`outcomeUncertain` 表示已发送但未确认的请求，必须重连读取实际状态后再决定是否重试。
收到命令错误不自动断开连接；超时会关闭连接，客户端不自动重发动作。
战斗搜索的传输等待额外包含请求的计算时间，再保留普通响应等待时间供终局重放、报告保存与返回；
搜索自身的计算预算不变。resident workbench 遇到传输故障后释放失效连接，下一条 `read` 会重连并
读取实际保存状态，不需要靠回退修复连接，不会自动重试游戏动作。分组命令错误保留原错误码、
请求身份、记录目录及结果不确定标记，同时列出前面已执行的动作。
进程意外退出时，短错误附带最多 1024 字符的 stderr 尾部，错误对象保留 `exitCode` 和
`stderrTail`，完整接收记录写入 `stderr.txt`，不将实际原因替换成笼统的连接关闭。

日常 scratch 不保留逐动作归档，`back list` 显示最多十二个近期回退点的回合、血量和药水，
对应可直接使用的 `back N`；查询不恢复 checkpoint 或改变进度。楼层落点与主动命名的 mark 同页保留。
`exe history --journey` 用于有归档的证据会话，读取当前已采用路径的正式记录，不回放战斗、不包含私下预演。
`--last 1` 是最近一段行程，在战后奖励未领取时就是刚结束的战斗；领取奖励后最近一段可能
已是奖励操作，可用 `--last 3` 等扩大范围。战斗摘要的 `chosen-card-plays` 统计实际选择的
出牌动作，不将 Double Tap 等自动重复计入，不能等同于所有触发次数。
血量下降/上升是公开边界间的观察净变化，同一动作内伤害与治疗可能抵消；完成边界的
回血单独列出，不凭摘要归因。`--detail` 的状态变化明确标注 `1 -> absent` 等差异，
只说明记录中发生的变化，不推断触发原因。历史节点只用于定位，日常复盘无需复制它们。

## 模型工具读数语言

`openWorkbench({ ..., agentLocale: 'zh-CN' })` 为该工作台选择文字语言，默认 `en`，重连保持不变。直连客户端使用 `openRunPlay({ ..., locale: 'zh-CN' })`；它将选择传给 `agent-shell --locale`，原生查询、普通读数、动作后的返回、私下预演和准备投影共享该连接的呈现参数。战斗、战略概览、选项、准备和地图按实际 renderer 使用连接语言；语言选择不写入游戏状态。

`game.info('potion SteroidPotion')` 默认使用连接语言，也可用 `{ locale: 'en' }` 单独覆盖这次定义查询。CLI 使用 `run_play info --session <path> --locale zh-CN potion SteroidPotion`。原生协议的 `info.locale` 接受 `en` / `zh-CN`，省略时继承连接设置；连接默认英语。上下文省略用的 `known_context` 引用按语言区分，英语资源的确认不会使中文读数漏掉同一批库存；游戏快照、动作身份与来源绑定不随语言变化。

`info rules`、`info rules preparation`、`info transition <HP>`、`info help` 和机制查询错误均使用连接语言。回血查询按当前对局的生命上限和进阶调用实际跨幕计算；它是只读假设，不推进对局。规则页区分当前幕与待进入幕，精英池、Boss 和初始阵容显示原版名称并保留稳定 ID；随机成员权重来自同一阵容定义，敌人完整机制补充保留英文并标明。名称查询接受完整英文名或稳定 ID，卡牌升级继续使用半角 `+` 或 `+N`。

当前药水机制查询支持全部 42 种药水的中英文名称、规则、基础药效、稀有度和目标要求；其他读数仍使用各自原有渲染。命令与查询中的稳定 ID 保持原样，语言不参与游戏状态、动作、RNG、训练词表或 parity 比较。记录保存实际查询时的语言和返回原文。

## 返回决策点与比较分支

供界面和驻留调用者使用的结构化返回接口沿同一 Rust owner：
`run_play back --session <path> --list --json` 只读列出近期点、楼层落点、具名点和上次离开的终点，
同一个状态的多个来源合并展示。列表携带会话、读取时的 head，以及各目标的精确身份；
不会从文字摘要或模型步骤号推算目标。

列表使用 `run-play-return-points-v2`：`resources.potions` 按槽位提供 `PotionId` 稳定 ID 或 `null`，终局的 `location.outcome` 原样提供 `TaskEpisodeOutcomeV1`。调用者在显示时取词，不从药水显示名或终局句子反推身份。Rust 程序与插件一起更新，工作台拒绝不同版本的列表。

`run_play back --session <path> --request <request.json>` 读取 `run-play-return-request-v1`：
`source` 原样取自列表，`target` 原样取自所选目标的 `identity`。位置变化、会话不同、目标失效
或身份不匹配时不发布恢复。正常恢复在同一次 head 发布中保留一个被离开的终点，返回结构化收据；
查询后的 `previous_endpoint` 来源可用于回到刚才，包含终局。再次恢复替换这个自动点，具名点独立保留。
请求恢复后的状态与 RNG，不重新抽取随机结果。

驻留 `workbench.returnPoints()` 返回同一结构化列表；`workbench.restorePoint(request)` 在原有串行
队列中先关闭旧连接，再调用 Rust 恢复并重连，返回 `{ receipt, points }`。失败也重连，不重发恢复；
`points` 是重连后的实际列表，`receipt.to` 是这次恢复提交的位置，两者应分别读取。
请求与已确认收据写入该工作台的记录目录；恢复已提交后重连失败时，错误对象仍携带收据和 `branchChanged`。
调用者负责按任务取得修改权；这个接口本身不会取消模型，也不会改写 dsh 历史。

决策历史由执行过程保留，**不需要先调用 `jump` 才能保存**。需要多步试打时可执行 `node scripts/p.mjs jump`，
记下它打印的 `Return point` 命令；这一步只读，不创建另一个存档。试打到 A 的终点后再记一个返回命令，就可以一条命令回起点试 B，再直接切回
保留的 A 或 B 终点继续，无需数 undo 次数或重新执行整条 A。只做局部计算时仍可用 `preview`。

`node scripts/p.mjs jump <选择器>` 直接调用 Rust 现有的 jump owner，关闭旧连接语义，恢复后从新连接读取
当前手牌、能量、HP、状态与选项；不会自动出牌。可用引擎给出的 `nNODE`，或显式
`source:hN`（该次操作前）、`target:hN`（该次操作记录的目标）。裸 `hN` 含义不明确，会报错。
无参数时从 `status` 获取节点，并与新读数的公开快照核对后显示返回命令；正常战斗没有选择
对象时也可使用。不匹配、找不到节点或节点歧义均报错，不猜替代目标。短节点由 Rust 解析验证。

跳转只限当前会话已有且可恢复的公开决策，包括被撤销的分支；不能跳到未走过的未来或私下
preview 的假想终点。终局自身没有可返回的决策点，但此前保留的决策仍可使用。
若没记下返回命令，用 `node scripts/p.mjs exe history --limit 20 --combat-detail` 核对历史动作与 `from=n...` 节点，
再在本轮授权范围内 `node scripts/p.mjs jump n...`；忘记复制命令不等于丢失存档，找不到明确节点时也不能猜。
每次跳转增加 `h` 修订号，保留原轨迹与跳转事件；它不会把已看过的未来信息变回未知。
旧选项和搜索对象失效，采用路径的 `history --journey` 不代替被撤销尝试的记录。

`jump` 必须单独调用，不与逗号/分号命令组混用；不合法的混用在任何前置动作执行前拒绝。
返回命令使用当前 focus 会话，换操作者或会话时先重新核对。具体试探范围与预算由本轮任务约定，
工具不把一次回退权限解释为整局重选权限。

`research` 显式请求一次搜索，不因未解自动加档。默认 `whole_combat` 使用当前整场
`CombatSolver`，与离线 `combat_solver` 以及学习端 `WholeCombat` 共享搜索 owner。
它默认请求 30,000 次转换（包括终局回放），至少 512 个引擎步骤/输入。命令默认总时间为
2000 毫秒；显式 `research whole_combat 15000` 会把内层时间上限也设为当前总期限的剩余时间，
不会仍被默认 2000 毫秒截断。转换次数上限仍独立存在；仅 `whole_combat` 可显式请求
`research whole_combat 15000 work 100000`，转换次数范围为 1..1000000，省略时仍默认至少 30000。
对象 API 使用 `maxGenerationWork`。报告记录实际请求的转换上限，`plans full` 显示该预算，缓存身份包含它；
同根、同档位和同预算会重用结果。增加时间不增加转换上限，增加转换上限也不延长时间，
两者都不保证找到更好路线。
允许探索当前合法药水，并独立保护只出牌搜索。
返回多个完整资源方案，操作者按后续路线选择；不会自动采用最高血量方案。
默认方案摘要只列从搜索起点新用尽的遗物；`plans full` 和 `review` 保留战后完整可用性。
`whole_combat` / `fast_witness` / `standard` / `expanded` 的客户端默认总时间预算为
2000 / 2000 / 5000 / 20000 毫秒。后三种仍是旧研究组合，供显式诊断比较。
可指定 1..20000 毫秒。`plans`、`review`、`commit` 使用 Rust 保存的同一份报告，不重跑搜索。
`commit` 的可选档位仅核对保存的报告。想换档位或预算时显式调用 `research`，再看新报告。

## 读取和选择

- 默认读数展示当前决定所需的游戏信息。`details: ['map', 'options', 'state']` 按需展开。
  `details: ['brief']`（工作台默认，以及 `board`）保留当前血量、金币、药槽、卡组张数、候选效果
  和合法选择。卡牌显示当前升级态的费用、基础数值及简短规则；完整卡组、战略遗物清单、
  钥匙状态与教程由 `inventory`、`read full` 或 `info` 按需展开。战斗保留遗物计数。
  选择来源和对象保持同一合同；默认面不从文字过滤选项。
  营火的升级变化直接放在选择行，只列改变的费用、数值或效果；同效果普通副本合并显示数量，
  瓶装副本和永久属性不同的副本单列。代表行仍可直接选择，`options` 展开每个确切副本。
  瓶装标记由遗物 owner 的 typed 卡牌身份投影。未命名的升级效果保留规则原文，完整规则也可用 `read full` 展开。
  事件的单张或多张升级选择也显示同一份实例升级变化；每个选择仍绑定原来的确切副本。
  `choose`、`select`、`collectRewards`、`act`、`commit` 的后继及 `preview` 默认返回简洁读数；
  对象调用者需背景说明时再用 `decision()` 明确读取。
- `reading.control` 区分 `strategic`、`combat`、`terminal`；不要解析标题猜阶段。
  `reading.summary` 是源端从同一份公开状态生成的位置摘要，与正文共用渲染器，不含选项和展开规则；预演用执行前的这份摘要区分实际局面和假设后继，不从正文标题截取。
  战斗观察的 `turn.player_escaping` 表示已采用逃跑、尚待结算；读数直接给出 `act end`，
  不再展示无法执行的战术手牌与敌人意图。此输入完成既有逃跑结算，不是继续搜索胜局。
- `options[i].choose()` 执行当前对象；多选用 `selection.select([selection.members[i], ...])`，
  顺序与同名实例身份均保留。
- 奖励组合用 `reading.collectRewards([option, ...])`，最多八项，最后一项为打开卡牌奖励。
  前缀仅接受金币、追回金币、药水；整段在私下验证成功后提交，不自动拿遗物、丢药或选牌。
- 商店显示完整当前库存及不可购买原因；Courier 补货后使用新对象。低频弃药、删牌目标按需展开。
- 默认战略读数展示当前命令及其效果；准备窗口、钥匙时限与完整路线通过 `read full` 展开。
  完整永久卡组机制由 `inventory effects` 提供，`decision({ details: ['state'] })` 也保留扩展规则。
  事件选项旁按持有的 Ectoplasm／Sozu 显示金币获取、支付与药水获取修正；基础分布继续保留。
  诅咒钥匙开箱后直接显示实际新增的诅咒，与事件和遗物造成的卡组变化共用结果读数。
  涉及失去限制遗物的选项保留基础条件，需结合遗物实际去留判断。
- `knownContext` 或 `retainContext` 只确认当前上下文仍保留背景，不能替代动作来源。
  上下文丢失后清空确认，重新取完整读数。

选择、购买、弃药、回退和提交后使用新返回的对象。显示编号仅定位当次读数，不能跨状态复用。
连接超时或回复丢失时先核对保存的状态与记录，避免重复提交。

## 现存战斗工具

允许精确信息的会话中，普通 `read` 会显示已保存、仍与当前状态及生产者版本绑定的重放胜线摘要。
它只读取已有结果，不追加搜索或代选；`plans`、`review` 和 `commit` 继续使用同一报告。
普通读数中的摘要已经包含完整方案 ID，工作台显示时不再额外请求 `plans`。
出牌或回退后不再展示旧根上的胜线。损坏的可选缓存会说明无法读取，实际游戏局面仍正常显示。

`game.research({ effort: 'whole_combat' })` 调用整场求解器。返回 `candidates`，每项可
`review()`、`review({ turn: 2 })` 或 `commit()`。候选是重放过的完整打法，不代表最优；
`plans full` 展示每条胜线从当前位置到首次 `end` 的开局动作（过长时截断），完整过程用
`review()` 看；预算内没有找到胜线时保留 Unknown。对象 API 的默认 `maxSearchMs` 为 10000，
可显式指定。

`game.research({ maxPotionsUsed: 0 })` 要求保留药水；该次请求的上限同时约束搜索与
复活储备估值，包括显式使用、丢弃和入场药水的被动消耗。非零上限允许相应总支出，
不能放宽会话已有的限制；省略时沿用原策略。不同药水上限不会复用同一份搜索缓存。

Rust 在会话目录保存当前报告、动作线和重放证据。关闭连接后，用 `game.plans()` 取回保存的
候选对象，`game.plans({ diagnostics: true })` 展开诊断；查看和采用都携带同一报告身份。
复盘会重放原动作线，提交会核验原动作线再事务性
采用，两者都有执行开销，但不会重新搜索。来源不匹配、正式进度改变（包括 undo），或报告
已被另一份内容替换时，旧对象报错；客户端不会改用新报告中的同号候选。
保存或删除 mark 只改变元数据；游戏状态版本、会话、精确节点、公开 snapshot 与生产者仍匹配时，
原报告继续可供 `plans`、`review`、`commit` 使用，报告内容和身份保持原样；重连后用 `plans` 取得新连接的候选对象。
复盘的敌方变化沿同一执行分支中的真实实体身份配对；召唤后的 M 编号只定位当时的敌人。
逐动作摘要给出原目标的编号、名字和变化，完整敌方名单仍随各回合读数展示。

CLI `combat-trace --artifact <report> --candidate N` 按 artifact 的完整节点身份只读定位历史根。
scratch 根可从尚保留的 mark、楼层落点或近期回退状态读取，通关终局无需先回退；重放仍核验
同一会话、公开 snapshot 和 artifact 携带的精确状态身份。已裁掉的根不会被恢复，查看不写正式 head。

```javascript
const plans = await game.plans();
const candidate = plans.candidates[index];
const reviewed = await candidate.review({ compact: true });
// Read reviewed.view before adopting this same candidate.
const next = await candidate.commit();
```

`game.preview(['play:Offering', 'play:Strike', 'end'])` 在私有分支逐步验证动作线，返回
假想后继的 `view`、结构化 `endpoint` 和 `stop`。它不提交，也不调用 undo；成功、非法动作或显示
异常都不会因预演而移动正式进度。假想后继不提供可直接采用的选项对象。预演可利用固定状态
中的抽牌和 RNG 信息，属于 SL 条件下的局部试算。

抽牌后出牌、动态费用和主动保留费用结束回合交给引擎验证；客户端不按初始手牌或费用总和
拒绝整条线。`end!` 仍接受为 `end`，不再需要强制标记。药水名称解析只绑定合法动作，
抽牌与手牌上限由引擎按整条动作线的实际顺序处理；要求精确实例时使用明确选择器。
每次 preview 都从正式当前位置出发，不接续上次预演
的假想后继；想继续试算时，提供从正式位置开始的完整动作线。

`piles sl` / `game.slPiles()` 只读当前精确战斗根，不执行动作、不抽牌或消耗 RNG，也不移动
正式 head。抽牌堆按下一张到最后一张显示；弃牌堆按底到顶显示，保留引擎洗牌输入顺序。
它只列当前牌的身份和升级，不预测后续洗牌、抽牌触发或上手后的费用变化；抽牌后仍需读新手牌。
这是显式的 SL 内部查询，要求 privileged exact 权限，不混入公开 `info` 或普通观察。
`preview` 与 `act` 的单线长度均为 1..256 个动作（重复糖展开后计数），允许跨回合、抽牌
与洗牌。整线在同一个私有分支内验证。`preview` 遇到无法解析的动作时返回已模拟前缀的
私有局面，包括当前手牌、费用和可选动作；`stop.kind=unresolved` 标出失败步和未模拟动作数。
若某次操作直接触发新回合，预演会标出对应动作和回合变化。
提前到达终局时返回真实终局，`stop.kind=terminal` 标出未执行尾部；完整非终局线为 `complete`。
这些后继没有成为正式位置，下一次预演仍从正式根开始。修正失败步和后缀后再采用；
正式 `act` 和完整前缀证据仍要求所提交的线全部合法，不把局部预演当作整线通过。
引擎执行和传输故障仍报错。底层 `probe` 每次最多比较四条这样的动作线。

`game.draft()` 打开连接内的私下回合草稿。`advance()` 追加一次计算预算，`options[i].review()`
检查回合，`choose()` 采用草稿分支，`undo()` 回到父节点。草稿抵达完整胜局并通过精确重放后
才提供 `commit()`。关闭连接不会持久化未提交草稿。
从候选打开 `draft()` 仍需原先的搜索连接；重连取得的保存候选支持复盘和提交，不隐式重搜来恢复草稿。

草稿选牌通过 `selections()`、来源的 `open()`、家族的 `prefer(members)` 和 `advance()` 操作。
偏好只调整计算，不是动作提交；生成和偏好修改后重新读取对象。大结果集按返回的 `next()` 分页。

搜索、草稿和复盘共用既有 Rust owner；新搜索研究不必沿用它们的评分、调度或结果。
