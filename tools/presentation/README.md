# SpireSim 展示语言与共用名称

这个模块提供中英文游戏名称、原版卡牌文本和消息格式化。它不读取游戏存档、执行动作或修改模型请求。`replay/` 拥有离线演示的模板、样式和渲染代码；实际模型记录、素材整理和构建结果保存在 artifact。dsh 地图与工作台使用宿主语言服务，领域名称消费共用词典；Rust 卡牌、药水查询和战斗读数也从这里取名称、牌面与消息。

演示中的涅奥选项从导入的原版按钮片段取文字与颜色标记，数值来自记录的公开效果，以四行列表呈现。[neow-option.mjs](replay/neow-option.mjs) 绑定当前记录的四种选项组合，保留原版的代价与收益顺序，不以选项序号推断奖励，也不改写原始记录。

战斗展示沿用原游戏的位置关系：顶部资源、中央角色与敌人、敌人上方的意图、角色下方的血条与状态，以及左下能量和底部手牌。主战斗区显示记录中的回合开始快照，实际出牌和结算变化放在区外的折叠记录中；切换语言保留展开状态，切换场景收起。能量只显示记录中的当前值。

## 项目中的职责

项目本地化覆盖游戏内容、界面和模型工具读数。共用的是领域名称与术语，各功能拥有自己的消息，各运行端使用适合其环境的格式化入口。当前消费者包括离线演示、Rust 游戏读数和机制查询、Node 工作台与命令行、dsh 地图和观察界面，以及原生、脚本玩家的工具与策略提示。

| 层 | 负责什么 | 接入约定 |
| --- | --- | --- |
| Rust 游戏核心 | 稳定身份、规则数值、公开状态、合法动作 | 沿用 [identity](../../src/content/identity.rs) 的稳定 ID，不从译名构造身份；语言选择不参与 RNG、游戏状态、动作身份、数值训练词表或 parity 判定 |
| 领域资源 | 卡牌、遗物、敌人、遭遇、状态、房间等名称与共用术语 | 按实体种类和稳定 ID 取词；原版名称与已接入的事件正文从安装包导入，各端消费同一份生成资源；工具自己的术语和消息独立维护 |
| 功能界面 | 导航、按钮、空状态、可访问性文案 | 各功能使用自己的命名空间；演示的 `replay` 不能成为地图、工作台或工具消息的公共容器 |
| 自然语言读数 | 卡牌机制、当前局面、合法动作说明、错误消息 | 沿 Rust/Node 的实际渲染 owner 使用结构化事实和具名参数，不翻译最终字符串后再解析；数值与效果顺序由规则 owner 提供 |
| Python 训练接口 | 结构化观察、动作、奖励及可选文字读数 | 稳定 ID 和数值特征不随语言变化；文字读数接现有渲染 owner，避免在 Python 再维护一套规则说明 |
| 原始记录 | 实际模型请求、输出和工具返回 | 保留产生时的原文；展示可从有来源关系的公开事实重绘，不用译文覆盖原始记录 |

`i18next` 是 JavaScript 消费者的格式化实现。原生 `sts_presentation` crate 位于同一目录，使用相同 JSON，编译时嵌入资源；Cargo 包包含所需源码和词典。Rust 和 Python 的传递构建因此不依赖 Node、浏览器、本机游戏安装或运行目录。原生格式化目前支持具名参数插值，不自动选择 i18next 的复数形式；新增复数读数时沿对应 renderer 提供数量选择。

Rust 命令行的帮助归 `cli` 命名空间所有，按 clap 的稳定命令路径和参数 ID 取词。`Cli` 统一持有全局 `--locale`，现有地图、机制、库存和 agent-shell 读数消费同一选择。帮助标题、默认值与可选值的说明从结构化参数定义呈现；实际参数名、值、默认值与合法性约束保持原样。全局参数由 clap 继承，子命令不另存相同说明；源码中的 derive 帮助正文迁入资源，由覆盖测试防止重新散落。

CLI 的返回点和标记列表从 `compact` 命名空间取词，使用同一全局语言。位置与资源直接读取已保存的公开状态，药水和遭遇名称按稳定 ID 取官方资源；标记名、返回命令和结构化返回点 JSON 保持原值。读取列表不恢复 checkpoint 或改变存档。

CLI 的 `status` 及新建、采用、执行和返回后的可玩摘要也消费同一语言。紧凑布局由 `decision` 的原有读数 owner 直接生成卡组计数、逐张手牌和可执行选项，不再拆分英文标题或成品列表；遗物摘要按计数和 typed 触发状态选择条目。商店的紧凑展示归 `compact`，复用原商品身份、价格、购买状态与机制资源。模型标准读数和结构化协议保持各自原有布局。

库存和卡组变化共用永久卡牌的分组身份与名称 owner，计数涵盖稳定 ID、升级、成长值、伤害与格挡改值、费用修正和瓶装标记，忽略页面 ordinal。变化先按这些字段计算，再选择语言和消除同名歧义；不同颜色的同名卡不会相互抵消。实际执行后的卡组与遗物变化，以及 agent 返回中的公开结果提示使用调用者语言。

`history --journey` 使用调用者语言重绘已记录的公开边界，复用实时战略选项、永久牌组和终局结果的展示 owner。战斗的主动出牌按稳定 ID 与升级次数计数，再选择名称；生命、遗物、药水和状态变化先比较结构化数据，哨兵状态只比较存在性。记录中的动作命令、来源版本、访问等级和原始文字保持原值；读取行程不执行动作或重写存档。

`history --combat-detail` 保留原始公开观察，直接复用实时战斗读数，不缓存另一套手牌、敌人或状态文字。普通历史、终局列表和构筑记录的说明也使用调用者语言；构筑卡组复用完整永久属性分组。诊断行中的固定字段、稳定 ID、已采用命令和来源编号保持原值，`construction-history --json` 与语言无关。

模型 JSONL 的请求校验使用连接语言生成说明，校验条件、字段名、参数限值和错误代码保持固定。校验失败逐行返回 `invalid_request`，不会进入动作处理；后续有效请求照常处理。封闭 schema 的原始解码诊断和底层来源错误按原文保留，各自的用户说明沿实际 owner 接入。

动作语法解析也显式接收展示语言，覆盖命令行、交互 shell、模型请求与卡牌升级查询。语法、稳定名称、升级次数、同名序号和目标栏位仍生成同一 typed selector；语言只决定错误说明。内部轨迹和策略代码显式使用英语诊断，不保存语言或依赖译文解析动作。

常用动作匹配错误从 `selector.resolve` 取完整消息，沿实际执行、事务动作序列和私下预演传递展示语言。手牌、同名副本、升级等级、目标与待完成选牌仍按同一公开候选匹配；语言不改变合法性或动作顺序。CLI 的正整数及规范卡牌、遗物、药水 ID 校验由原解析函数判断，运行时 clap builder 为相应命令路径和参数安装带语言的解析器；帮助、参数值和稳定 ID 共用原合同。

战斗草稿的状态、选项、后继、选牌来源与偏好读数使用连接语言，动作名称和后继资源摘要由 `sts_complete_turn_view` 共享渲染。`sts_complete_turn_env::selection_summary` 的语言参数只用于已有文字投影；数值观察、frame/T/S 引用、偏好、生成预算与草稿状态不保存语言。切换读数不推进生成或采用动作；原始回放诊断保留固定字段和稳定 ID。

普通 CLI 的会话、当前局面、精确节点参数、构筑节点过滤和动作输入说明使用同一展示语言。`deck-lab` 启动与准备摘要按稳定 ID 显示名称，保存的 RNG 合同与原始诊断 artifact 保持原值；详细诊断正文由 `deck_lab` 的独立 renderer 拥有。

普通 CLI 预演、模型私下预演的停止说明、自动换回合与终局生命变化也使用调用者语言。预演动作复用事件与战略选项 owner，战斗动作复用复盘的 typed 展示与有序选牌 owner；卡牌、药水和目标来自原始选中动作的公开帧。步骤、终点、停止类型、原始错误和已保存的轨迹保持原值，同一份结果可按语言重绘。

dsh 原生玩家的操作说明、模型工具和参数说明以及明确继续时的上下文使用 `native` 命名空间。`nativeGuide` 按玩法组合共用段落；每个聊天在自己的 scope 注册工具 schema，并从已保存绑定或新聊天配置取 `agentLocale`，互不改变。原生插件卸载时一并移除这些 scope 内的说明和工具。继续时只翻译说明前缀，实际状态读数与返回收据按原文插入；原始会话记录仍保持产生时的语言。

脚本玩家的普通跑局说明、`sts` 描述、启动任务和事实检查点使用 `scripted` 命名空间。语言沿启动器的 `agentLocale` 传入工作台，并保存在玩家绑定中；每个 Agent 的事实检查点独立保留语言选择。`scripted.runtime` 拥有插件校验、阶段操作要求、停止收据和查询刷新提示，本插件自有的完成和失败说明使用玩家语言，上游执行收据与原始错误按原文保留。`scripted.supervision` 拥有提案、指导和采用后的说明前缀；模型侧使用玩家语言，人工复核使用操作语言，命令、指导原文和已有记录保持原值。检查点只翻译说明文字，实际读数、查询结果、执行收据和用户任务按原文保留。`readingRange` 按 JavaScript 字符串索引标记原始读数范围，中文与代理对字符不会改变这一索引约定。

准备、选牌与购物的阶段指南和工具参数说明分别归 `scripted.preparation`、`scripted.cardChoice` 和 `scripted.shop`。指南中的分类 DSL、评级和引用 ID 不翻译。准备进度只渲染结构化的已采用命令与比较，恢复读取工具记录中的 typed metadata；成功和已确认执行后的失败都保存相同身份，不以中文或英文标题恢复状态。

准备条件中的攻击升级、虚无移除、幽灵保护套装、临时力量、状态牌抽取和事件战斗成本也由 `scripted.preparation` 持有正文。原生升级前后值、事件当前生命变化与生命上限变化、触发时机和条件引用继续来自同一份 typed 证据。中文分类保留命令、评级、实现方式与引用身份；已记录的原始比较不因切换读取语言而重写。

Boss 遗物、首精英准备窗口、永久复制、基础能量支付门槛和武装与突破极限的条件共用这一资源入口。持有药水与未来补充、现有金币与后续收入分别说明；路线窗口使用原生分段统计，复制的额外部署按各自触发时机解释。数值和可选引用仍由原条件分支提供，不从译文计算或验证。

准备分类的提示、行级纠错、部分接受收据、已记录表格、选牌约束和采用比较也从该入口取词。校验仍读取相同 DSL、命令和引用 ID；语言只改变说明与新生成的展示依据。已有草稿保留已接受评级和选择，记录中的旧文字按原文呈现。策略模块从 `scripted.strategy` 读取固定的卡牌类别、场景与单卡建议；两语展示共用同一份定义和卡牌集合，专家来源索引保留原文。构筑优先级、库存与事件取舍、持续伤害、回收输出、格挡转化和移除依据也使用这一入口，数字与条件分支来自原有计算。准备投影把语言传给移除策略，过滤仍使用 typed 命令；策略渲染器只翻译自身前缀，插入的已有说明按原文保留。其他选牌与比较正文继续由其 owner 提供。

卡组比较的库存覆盖、抽取参考、力量时机、状态牌路线和候选条件由 `deck.mjs` 消费 `scripted.deck`。概率、张数和实现方式来自同一份原生机制与计算，语言只改变说明。消耗路线是否存在由 `otherCardExhaustCopies` 与 `reusableOtherCardExhaustCopies` 判断，不检查显示出的“无”或 `none`。准备分类与已记录表格把玩家语言显式传入卡组比较；其他策略 owner 的正文按各自入口绑定。

`card-choice.mjs` 从 `scripted.cardChoice` 读取候选事实、比较页面、采用说明和自身错误。普通准备任务与 preparation-flow 都显式传入玩家语言，规则块原文、策略 ID、候选和来源检查保持原值；输入字节预算按该次实际读数与指南计算。策略模块提供的偏好与条件仍归策略 owner，选牌渲染器不改写这些记录。

`shop.mjs` 从 `scripted.shop` 读取替换药水和消费比较、预算展示及自身错误。商品身份、折扣后的真实价格、购买后余额、附带选牌与补货边界仍来自相同的原生私下预演。规则块按原文插入，策略标题的命令显隐由策略渲染器的 `includeCommand` 控制，不再从成品句子删除片段。玩家语言贯通准备读数、分类、已记录表格与后续消费绑定。

## 展示语言与模型语言

展示语言决定用户看到的名称和界面。模型语言决定后续请求中的工具读数、规则说明和相关提示。二者分别由对应边界拥有：中文界面可以查看英文模型对局，界面切换只重绘，不改写已运行会话的输入或历史。工作台的 `agentLocale` 默认 `en`，支持 `zh-CN`，原生聊天在绑定中保存该选择，重连时保持。当前接通药水与状态机制查询、卡牌定义查询、永久库存、战斗 `read/options`、战略概览与资源摘要、奖励与商店标签、营火升级差异、钥匙状态、完整钥匙规则和跨幕准备提示。卡牌与遗物完整机制补充使用连接语言；事件的结构化效果、概率与阶段转换已按连接语言呈现，事件名称、已接入的正文与按钮使用原版语言资源，候选中的原始事件标签仍保留源端文字。地图路线、精英数量范围、准备路径和文字全图也共用同一原生 renderer；其余机制正文按实际 owner 继续迁移。当前 Python 批量训练接口返回数值特征、稳定身份和结构化审计数据，不产生面向玩家的文字读数，因此不需要语言参数。若新增文字观察，应从同份公开事实调用现有原生 renderer，并将语言选择限制在文字投影入口。

dsh 地图使用宿主的语言偏好、订阅和 slot 翻译入口，离线演示使用自己的语言选择。宿主内置 `zh` 在资源边界映射到 `zh-CN`。宿主的 `{name}` 模板与 i18next 的 `{{name}}` 及复数规则不同：地图的界面资源使用宿主格式，领域资源只抽取无模板的名称，效果模板保留在对应格式化入口。

`run-play show --public-output` 将当前语言写入 `producer.text_locale`，导出的战略正文复用实时选项、商店和机制展示 owner。全部公开候选均保留，观察、候选身份及机制数据不随语言变化；旧导出与原始来源摘要保留产生时的内容。

Python `tools.presentation.Presentation` 直接读取同一份 JSON，实例语言固定，具名插值不重解析替换值；名称缺失时先回退英语，再回退稳定 ID。`definition_text` 的具名实体引用与 Rust 使用同一合同。`tools.expert` 的派生视图保存结构化库存位置；渲染器据公开事实选择正文，卡牌规则、药水与遗物数值仍来自 Rust 导出，资料引文与保存的候选说明保持原文。数值训练接口不因这个阅读器而增加语言参数。

详细比较与 `preview --detail` 也传递当前语言。动作标签复用 typed 逐步展示；终点使用同一份公开决策渲染器，重复维护的局面、牌组与候选文字实现已删除。`combat.explain` 拥有实际抽牌、消耗、朝向和回合末变化说明；数值归因继续调用原有规则，不从文字计算。比较线路、原始步骤、动作身份和已保存记录保持不变。

`show` 对当前来源和可丢弃局面使用同一份完整公开读数；来源元数据仍保持固定字段，旧的未核验决策保留原有诊断呈现，读取不会重建或推进它。终局按已保存的结果类别呈现。普通 `advice` 的来源标题与建议标签也接入当前语言，建议的来源、访问级别、动作和结果保持原值；详细策略审计中的固定数据由各自诊断 owner 提供。

历史牌组变化与实时库存共用完整永久实例身份：卡牌 ID、升级、misc、费用、伤害、格挡和瓶装遗物都参与比较，页面序号不参与。变化先按结构化身份计算，再附显示名；同名不同 ID 保留区分。历史牌组目录也使用同一分组与永久属性标签，原始历史数据保持不变。

## 后续消费者

地图服务端返回房间种类、Boss 身份、坐标和状态，由客户端组合图例和悬停文字，局部中文名称表已删除。工作台控制与日志界面也沿宿主语言设置呈现，原始日志保持原文。观察面板在新 RPC 请求中传入操作语言，服务器校验使用 `native.observation`；活跃 owner 的实时文本和执行收据保留产生时的语言。复制提示等异步状态保存消息键，在渲染时取词；语言切换不重新读取记录或执行控制操作。返回点由 Rust 提供药水稳定 ID 与结构化终局结果，客户端分别通过共用名称和工作台消息呈现，机制或协议诊断保留原文。

模型工具沿实际 renderer 接入：程序消费者先摆脱英文标题解析，再让相同公开事实产生中英文读数。药水查询由 Rust `mechanics_info` 提供，基础药效、稀有度与目标要求仍来自药水定义；42 条已审阅规则维护在 `game.potionRule`，原有英语消费者从同一资源取词，旧规则文案副本已删除。`mechanics.potion` 拥有查询句子和未知药水错误，查询始终接受原有英文身份，显示明确的稳定 ID。其他机制逐类迁移，检查条件、升级、目标与效果顺序。语言覆盖按消费者实际使用的内容验收，不能将词典中存在一个名称当作对应机制已经完成本地化。

状态的完整说明由 `PowerMechanics` 在实际执行 owner 旁绑定 typed `PowerId`，`game.powerRule` 保存数值含义、效果和触发时点的两语资源，英文副本已从原定义删除。持续时间、存在标记、承伤上限等结构化语义仍由原规则代码提供，不从说明反查。查询和当前状态共用此绑定，仍未提供机制资料的状态保留明确的缺失提示。敌人机制补充也使用同一连接语言读取状态说明。

卡牌的完整补充由 `CardMechanics` 在原定义位置绑定 typed `CardId`，正文保存在 `game.cardRule`；旧英文正文已从定义代码删除。查询、选牌、库存和营火升级比较读取同一绑定，是否有完整资料通过 `get` 的存在性判断，不从标题或译文判断。原版牌面仍由安装包资源提供，补充说明保留项目已有的完整条件和效果顺序。

遗物的完整补充由 `RelicMechanics` 绑定 typed `RelicId`，正文保存在 `game.relicRule`；原定义中的英文正文副本已删除。圆环和红圆环沿原有共用规则明确绑定同一个文本身份，执行身份分别保留。遗物查询、战斗规则、库存、奖励、商店和事件效果使用连接语言；查询中的持有状态和计数由公开观察提供，触发标记通过原有 typed 状态说明呈现。

颂钵资源选项的 `native_rule` 是展示文字，使用该次连接语言；动作、实际生命和生命上限增量仍来自原有一步预演。字符串的 JSON 字段和执行绑定保持原合同；切换展示语言不改写已保存的原始记录。脚本消费者继续读取同一字段，不以正文识别资源动作或计算收益。

库存中的机制关联由 `mechanics_info/deck_links` 消费原有数值请求与触发枚举，并从 `mechanics.cardLinks` 取两语句子。力量增长时间表、抽牌数、出牌费用、每次生命流失和消耗收益继续由原规则提供；显示语言不改变分组、复制数量或触发条件。关联说明附带的完整卡牌规则也使用同一连接语言。

敌人目录使用 `MonsterText` 保存展示消息、规则 owner 提供的数值与 typed 状态引用；`MonsterTurnPlan` 继续由原可执行招式函数提供。特殊攻击、难度分支和心脏强化序列保留各自的真实数值来源，语言只在查询边界渲染。`game.enemyRule` 拥有完整规则与项目自有招式名，`mechanics.enemy` 拥有查询句子、目标和每步效果。阵容与战前准备关联共用相同的敌人定义、加牌步骤和状态规则。

原版 `monsters.json` 的非空 `MOVES` 按敌人稳定 ID、固定索引和已核对的数组布局导入 `game.enemyMove`；空白位置、数组长度或类型改变时停止导入。原版没有提供的招式名由项目规则资源维护，不从最终英文输出反查来源。`{{entity_enemyMove_Lagavulin_SiphonSoul}}` 与其他实体引用一样，直接取共用资源；阶段后缀仍由项目消息拥有。

完整说明可用 `{{entity_card_HeavyBlade}}` 这样的显式具名引用取得官方名称。Rust `Locale::definition_text` 与 Node `definitionText` 默认只替换已绑定的实体名称，拒绝未知引用；有动态规则时，Rust `definition_text_with` 或 Node `definitionText` 的参数对象接收 owner 已提供的具名数值与子规则。参数和实体名称都只替换一次，不解释替换后的文字。数值、条件和效果顺序继续由机制 owner 提供；它们不会通过字符串查找或显示名称取得身份。

事件效果由 `render_event_structured_semantics_v1` 直接消费已有的 typed 效果和转换枚举，英语与中文共用分支。数量、目标、牌池、遗物池和概率由源端提供；未指定的池或概率保持未指定，不从标签补猜。药水立即入槽与奖励页领取分别说明，选牌入口明确下一屏选择，进入战斗时说明胜利后领取战斗奖励。候选中的原始按钮标签保留源端文字；已接入的按钮按事件、阶段和选项身份绑定原版模板，不按英文标签反查翻译。无参数 `info` 使用当前原生选项读数，CLI 的有参数定义查询仍直接调用原生查询；Node 不再解析诊断输出中的 `candidates=` 或 `transition=`。

事件按钮里的动态数量与公开概率直接取同一选项的 typed 效果；固定数量的原版变体先核对实际效果。篝火的稀有度奖励和竞技场的固定遭遇、战后返回规则沿实际事件 owner 共用两语正文，原版短按钮与完整规则一起显示。篝火选牌读取相同奖励函数，保留禁疗和重复遗物分支；图书馆的公开卡牌按 typed 身份和升级数显示，不从原始按钮解析名称。

`EventChoiceMeta.public_detail` 由事件 owner 提供按钮已经公开的事实，捕获时原样进入 `PlannerEventOptionPublicSemanticsV1`。转盘已到账的金币、已揭晓的竞技结果与尚待执行的效果分开；未揭晓阶段不发布结果。翻牌位置、请求的药水和纸条中的升级卡牌也沿 typed 身份传递，渲染端不读取内部随机结果或解码私有事件状态。纸条卡牌的升级投影保留已存次数，再应用原有获得预览规则。

钥匙状态、定义查询和准备提示共享 `mechanics.key` 的完整句子。`KeyRuleV1` 决定各入口显示的规则，已持有钥匙只影响当前状态及自动准备提示，不删减显式查询的完整规则。蓝钥匙与关联宝箱遗物二选一，绿钥匙可以和其他精英奖励一并领取；语言选择不改变这些条件。

完整 `info rules`、准备版 `info rules preparation`、`info transition <HP>`、`info help` 和机制查询错误也使用连接语言。`mechanics.run` 拥有对局规则，`transition` 拥有跨幕计算读数，`query` 拥有帮助与查询错误，`encounter` 拥有阵容标题、成员与权重。跨幕回血仍调用 `RunState::dungeon_transition_hp`；当前幕与待进入幕由公开状态区分，第四幕路线取实际 `ENDING_ROOM_SEQUENCE`。精英池、Boss 与阵容使用原版名称和稳定 ID，完整敌人机制及准备关联使用同一连接语言。查询名称仍接受完整英文名或稳定 ID，命令和升级后缀不随显示语言变化。

保存计划的完整 ID、比较引用和复盘分页命令由 Rust `combat_reading` 生成；Node 从候选的 `plan_id` 绑定 `planId`，直接展示报告原文。工作台不依赖保存计划的标题文字，也不在显示普通读数时追加计划查询。

搜索报告、已保存方案列表及其自动附带的标题使用连接语言，从 `combat.research` 取词。结果、用药分组、生命差额、奖励、永久卡牌数值与遗物计数仍直接来自同一份报告；实体名称按稳定 ID 取官方资源，命令和报告引用保持原值。14 种退出原因及各类搜索目标分别绑定完整消息，预算耗尽继续表示未知。切换读取语言不重写保存报告，也不启动新的搜索。

逐回合复盘从 `combat.review` 取词，简版、展开回合、分页及动作标签使用同一连接语言。`combat_trace` 从实际选中的公开候选保留临时 typed 展示信息，明确记录卡牌、升级、目标、药水、姿态和有序选牌；`combat_reading` 只据这些信息呈现，不解析英文标签或命令来猜身份。该临时信息不写入原始轨迹，原轨迹的固定语言标签、动作、边界和数值保持独立于复盘语言。生命变化继续区分玩家动作与结束回合转换，避免把总变化重复计算；未知来袭伤害和复活状态保留原有含义。

Node 工作台的共享路由、选项与搜索命令入口、旅行说明、手打权限提示和连接恢复消息从 `workbench.command` 取词。同步 token、当前选项和药水解析、导航参数校验也消费同一语言实例，保留原有验证和执行顺序；消息不参与动作或方案识别，方案引用直接读取原生候选的 `planId`。名称输入保留 Unicode 字母和数字，不能将中文或标点归一化成空串后误选当前选项。报错前已经执行的动作、此前输出和底层错误原文作为参数保留，错误代码、请求 ID 和连接记录路径继续传递；底层协议诊断仍由其真实 owner 提供。

CLI 在会话或命令之前接受 `--locale en|zh-CN`，默认英语。该选择同时传给 `workbench.cli` 的帮助和会话参数提示、原生连接及命名机制查询，不写入存档或共享语言偏好。例如 `node scripts/p.mjs --locale zh-CN --help` 查看中文帮助。脚本启动器单独以 `scripted.launcher` 呈现操作提示、进度和错误，`--locale` 与保存于玩家绑定中的 `--agent-locale` 分开；前者可以改变，后者控制模型说明和游戏读数。`player inspect` 的标题、分页和诊断来自 `scripted.inspection`，范围保留为结构化类别，原始请求、模型输出和工具返回按记录原文显示；查看另一种语言不修改日志或请求摘要。`observe` 使用 `native.inspection`；实时只读查询使用操作语言，历史返回保留原文。近期错误只按行数截取原文，不解析英文标题来判断已生效动作；SDK 输入的摘要核验说明直接读取捕获精度类别。

选项行、营火升级与奖励标签、单选和多选提示由 Rust `decision` 渲染；命令来自 typed choice 与 selector，说明文字不参与命令识别。Node 原样输出，战斗外显示不再补取观察。预演保留假设选择及规则，当前读数提供可复制命令。读数的 `summary` 与正文共用源端公开状态渲染器，预演直接展示执行前的摘要，不再按英文标题截取；`board` 的当前格挡、来袭伤害与合法命令使用同一份 typed 公开观察。

工作台将本次实际展示的最后一份局面作为 `currentReading` 返回，原生和脚本工具通过官方日志 metadata 保存，模型消息仍只包含原来渲染的文字。日志摘要与脚本玩家的压力压缩使用这份记录，不从中英文标题猜边界；失败或尚未返回的调用不会使旧局面成为压缩后的实际进度。主动上下文刷新记录正文的字符区间，由输入诊断直接读取。

战略观察的 `preparation_reading` 由 Rust 从同一份公开决策生成，`public_snapshot_id` 绑定当前帧。选项文字按完整命令绑定；库存卡牌按稳定 ID 和升级等级绑定，遗物按稳定 ID 绑定；商店商品还包含类型、槽位、价格和可用命令。卡牌规则的 `available` 表示源端是否提供了机制说明。脚本准备、选牌和购物比较消费这些块，不按英文标题、显示名或文本顺序拆分，不再为取得规则额外请求 `read, inventory effects`。库存全文与分块共用原有渲染 owner；文字保持完整，不由 Node 裁剪规则。概览、候选、库存、卡牌规则、商品和路线随连接语言呈现；脚本策略消息使用玩家语言。升级比较从真实永久实例应用同一升级函数，分组和是否已附完整规则由结构化字段决定，不检测英文句子。

`scripted.strategy` 拥有维护者策略的条件、偏好、比较问题和复核说明。普通选牌、同牌不同版本、抽取组合、新功能与 Singing Bowl 比较沿 `preparationCardPolicies` 接收语言；条件判断、数值、策略 ID 和合法命令不取决于译文。原生卡牌规则、专家原文与已经产生的记录按原值保留。不同版本的数值比较先匹配原生效果，再使用完整句子模板显示费用和比较维度。

地图和观察服务的会话校验共用 `native.validation`，读取请求携带操作者的界面语言。`native.updates` 拥有工具更新的固定错误；缓存失败保留错误对象，读出时再按请求语言渲染，外部加载器的错误原文保持不变。`workbench.transport` 与 `workbench.web` 分别拥有连接提示和本机 dsh 启动器提示。

## 运行

需要 Node.js 22 或更新版本。在本目录执行：

```powershell
npm ci
npm test
```

`i18next` 负责消息插值、英语复数和语言回退，`Intl.NumberFormat` 负责展示数字。`esbuild` 是离线页面的构建依赖；生成的页面不需要联网或安装 Node。

## 使用

```javascript
import { createPresentation } from './index.mjs';

const view = createPresentation({ locale: 'zh-CN' });
view.entity('card', 'ShrugItOff'); // 耸肩无视
view.text('game:effect.draw', { count: 2 }); // 抽 2 张牌
await view.setLocale('en');
view.entity('card', 'ShrugItOff'); // Shrug It Off
view.text('game:effect.draw', { count: 2 }); // Draw 2 cards.
```

`createPresentation` 只使用本地资源并同步返回就绪实例，同步校验和异步读数因此共用同一个格式化入口；现有 `await createPresentation(...)` 调用仍可使用。`setLocale` 仍可等待，但不修改其他实例的语言。Node 工作台按连接建立独立实例。board 的数值直接使用现有 typed 公共投影；无序牌堆与库存差异先按稳定身份和升级分组，再取原版名称。同名不同 ID 保留区分，`cardName` 与原生端一致保留灼热攻击的实际升级次数。

每个展示端创建独立实例。`setLocale` 只改变该实例的呈现语言，调用者拥有重绘和偏好保存。不要用它替换 dsh 的宿主 locale provider；插件应沿其公开 locale/slot API 接入，游戏名称使用这里的共用资源。

只消费资源或运行构建检查的 JavaScript 端可导入 `@sts-simulator/presentation/catalogs`，该入口不加载 i18next。JSON 资源也可通过 `@sts-simulator/presentation/locales/en.json` 等导出路径直接读取。dsh 地图只将所需领域名称注册到宿主，客户端构建时包含实际资源。

## 资源职责

共用内容位于 `locales/en.json` 和 `zh-CN.json`：`game` 拥有名称、术语、状态计数、遗物触发状态和规则，`mechanics` 拥有机制查询和卡牌规则消息，`inventory` 拥有永久库存消息，`combat` 拥有战斗与选牌读数，`decision` 拥有战略概览、选项与共用选择提示，`map` 拥有原生地图和路线读数，`event` 拥有结构化事件效果、牌池、遗物池、概率与后续阶段说明，`workbench` 拥有 Node 追加的命令、board、牌堆与预演读数，`replay` 拥有离线演示消息。dsh 地图和工作台自己的界面消息位于其 `locale/` 资源中，不在其中复制游戏名称。

`game.card`、`relic`、`potion`、`enemy`、`character`、`event`、`power`、`stance`、`encounter` 是原版资源导入的名称区段，由 [import_original.py](import_original.py) 更新，不手工翻译。卡牌、遗物、药水、敌人和状态按当前模拟器稳定身份核对；角色覆盖四名可玩角色，事件按现役 `EventId` 显式绑定原版条目，Neow 名称取 `characters.json`；退役事件不加入运行词典。遭遇名称覆盖全部稳定 `EncounterId`，具名遭遇显式引用敌人名称，组合遭遇优先取 `ui.json` 的 `RunHistoryMonsterNames.TEXT`，例如“三哨卫”和“矛与盾”；没有该条目的六组按明确数量组合原版敌人名称，神秘球体引用对应事件名。导入器检查身份不遗漏、不重复，以及已接入的原版数组布局；来源摘要分别记录直接条目、别名和组合。状态的本地化键差异显式记录，例如 `Regen` 对应怪物 `Regenerate`，`Regeneration` 对应会递减的再生，`DexterityDown` 对应 `DexLoss`；它们不按译名或相似类名合并。房间类型、界面消息和补充规则说明由项目维护。

原版资源位于安装目录的 `desktop-1.0.jar`：`localization/eng/` 为英文，`localization/zhs/` 为简体中文，`localization/zht/` 为繁体中文；本模块当前导入前两种。目录内的 `cards.json`、`relics.json`、`potions.json`、`monsters.json`、`powers.json`、`stances.json`、`characters.json`、`events.json` 等按游戏内容分类。导入只读取 ZIP 中的 JSON，不启动游戏或 Java。

从仓库根目录核对原版名称；加 `--write` 更新名称区段与来源摘要：

```powershell
.\scripts\py.ps1 tools/presentation/import_original.py --jar 'C:/path/to/SlayTheSpire/desktop-1.0.jar'
.\scripts\py.ps1 tools/presentation/import_original.py --jar 'C:/path/to/SlayTheSpire/desktop-1.0.jar' --write
```

卡牌、遗物使用现有身份 owner 提供的原版 ID；本地化键与协议 ID 不同的项在导入器中显式列出，不用译名、英文显示名或模糊匹配反查。例如稳定 ID `Elixir` 对应原版当前药水键 `ElixirPotion`，原版同名 `Elixir` 条目已经废弃。来源 [original-names.json](original-names.json) 记录语言、资源文件摘要、生成名称摘要与明确遗漏；逐项来源可以用 `--report <新 artifact JSON 路径>` 保存。`Impulse` 没有对应语言条目，`GuardianThreshold` 是模拟器辅助状态，`GenericStrengthUp` 的名称由遭遇在构造时传入，原版中立姿态的名称为空；这些情况明确记录并保留身份回退或现有领域标签。普通安装、构建和运行只消费已生成的 JSON，不依赖本机游戏；npm 和 Cargo 包保留来源摘要。

[original-event-text.json](original-event-text.json) 保存已有消费者使用的原版正文、按钮片段及来源摘要，并通过 npm 和 Cargo 随包分发。[event_text](../../crates/sts_run_play/src/event_text.rs) 拥有原生展示绑定：换脸商正文按当前事件阶段与已公开结果选择原版段落；按钮按事件、阶段和选项编号明确组装 `OPTIONS`，动态数值直接取该候选已公开的 typed 效果。按钮的原始记录、执行身份和候选来源保持不变。未接入的阶段、缺失或重复的所需数值保留源端标签；实际替代奖励不套用不相符的原版概率说明。数量不同且写死在原版片段中的按钮（例如灵体数量），先按公开效果选择对应变体；金翼的金币区间也直接取公开范围。原版预留的空文本格按固定位置校验，不作为按钮使用。牧师没有可删牌时的空净化流程，以及传送门的中间确认步骤，使用项目消息描述实际转换。清理排版标记发生在模板组装之后。运行时不打开本机 JAR，也不依赖 `STS_GAME_JAR`。新增字段或数组布局变化需先在导入器和对应 renderer 核对，不按屏幕号猜正文索引，也不复制游戏数值公式。

涅奥的对话按钮取 `characters.json` 的 `Neow Event.OPTIONS`，奖惩片段取 `Neow Reward.TEXT` 与 `UNIQUE_REWARDS`，输出字段 `REWARD_TEXT` 明确记录这层来源。一个编号在不同新局里可以对应不同奖励，因此奖励页按完整公开效果序列绑定，先组装代价、再组装奖励；生命与金币数值仍取该选项的公开效果。不支持的组合保留原始标签，不按初始随机数或未来结果补猜。

原版牌面与工具补充说明承担不同用途。卡牌 `DESCRIPTION` 中的 `!D!`、`!B!`、`!M!` 由游戏提供数值，`NL` 和 `#y` 等控制换行与颜色；药水和遗物的 `DESCRIPTIONS` 常是由 Java 按顺序插入数值的片段。当前 `game.potionRule` 是项目整理的完整机制解释，包括触发时点、目标、限制和原版短描述未展开的交互；它与原版名称分别维护，导入器保留它以及所有工具、界面消息。

[original-card-text.json](original-card-text.json) 保存同一次导入的卡牌 `DESCRIPTION`、`UPGRADE_DESCRIPTION` 与 `EXTENDED_DESCRIPTION` 原文和来源摘要，通过 `@sts-simulator/presentation/original-card-text` 导出，并嵌入 Rust crate。字段名不决定其用途：全身撞击的 `UPGRADE_DESCRIPTION` 是战斗伤害附加行，终结技用它显示不可打出的提示。`cards::mechanics::original_printed_card_text` 按原版实际升级方法选择定义牌面，使用同一份永久基础数值 owner 处理伤害、格挡和多次升级；`!M!` 使用当前升级态的定义数值。它不查询隐藏状态或计算当前战斗伤害。

共享格式化入口只替换已提供的数值、处理换行与关键字标记，将能量图标显示为 `[Energy]` 或 `[能量]`，保留原图标数量和 X 表达式。未知变量或缺失的已选模板返回错误。原版未收录的卡牌返回 `None`，由查询保留稳定 ID 和已有机制资料。`info card <ID>[+N]` 使用定义牌面，按工具语言显示名称、类型、属性与目标，并显示同语言的完整机制补充；选牌的简版与完整规则也共用该定义 owner。`inventory effects` 使用 `original_card_blueprint_text`，传入永久实例的升级、附加值及伤害/格挡改值；战斗中读取 master-deck snapshot，不以手牌的临时改值替代。基础请求另行标明定义范围。灼热攻击的名称保留 `+1` 等实际升级次数。

战斗手牌的费用、逐目标伤害、格挡和敌人意图直接来自同一份 `PublicCombatStateV1`，不会为翻译重新应用修正。未知伤害、隐藏意图、复活状态和逃跑结算保留各自含义。状态的回合持续时间、存在标记、负力量及承伤上限沿规则 owner 呈现；语言不改变计数。选牌原因由 `sts_complete_turn_view` 的同一个 typed reason renderer 提供，token、顺序、选择范围和取消动作不从显示文字推断。完整战斗读数中的卡牌牌面、药水规则、消耗与格挡规则也使用连接语言；状态的完整机制说明使用连接语言；敌人机制的长篇补充与招式步骤也使用同一连接语言。状态查询与敌人槽位查询共享相同的当前数值和意图 renderer，区分存在标记、持续时间、负数值、承伤额度与重置上限。

库存全文和结构化卡牌/遗物块从同一次渲染生成。卡牌按稳定 ID、升级和全部永久实例字段分组，不按名称合并；多个稳定 ID 共享同一显示名时附 ID 以便辨认。瓶装标记只经遗物 owner 的 typed lineage 绑定。遗物触发状态由规则 owner 提供枚举，再从共用消息取词；语言选择不反查英文状态文字。CLI 的 `inventory --locale en|zh-CN`、工作台库存命令和准备投影共用该 renderer；准备投影的库存块与同帧概览、候选、商品和路线使用连接语言。

工作台把 `agentLocale` 传给原生连接的 `--locale`；每次读数、执行后的返回、准备观察和私下预演都显式传递该参数，不将语言写入 controller 的持久状态或使用全局可变偏好。省略上下文的确认摘要包含呈现语言，语言改变时重新输出资源；用于执行的快照 ID、合法选择和来源引用保持原有身份。原始对局记录保留产生时的文字；用于证据采集的固定格式仍由其入口显式选择语言。

名称按领域和**现有稳定 ID**取值，例如 `game.card.StrikeG`、`game.encounter.TheHeart`。同名的 `Strike`、`StrikeG`、`StrikeB`、`StrikeP` 保持四个条目，不能按翻译文字反查动作。名称资源的具体覆盖见来源摘要，新增消费者沿稳定 ID 使用已有原版名称，再补所需消息。缺项先回退英语，再显示原稳定 ID；`onMissing` 提供开发检查信息，不向页面增加提示条。

界面消息使用完整句子和具名参数，不能拼接翻译片段。英语复数采用 i18next 的 `_one`、`_other` 规则，调用时保留数值 `count`。`validateCatalogs` 检查两种语言的键、非空值和参数一致性；未知消息键或缺少参数会报错。测试同时核对实体键仍属于当前模拟器的稳定词表。

费用、伤害、格挡、升级、每段效果、条件和动作目标均由调用者从现有公开事实提供。模板不计算规则，也不添加当前局面未提供的信息。`number()` 只用于展示，命令中的 ID、ASCII 数值与语法保持原样。

## 离线分发

```powershell
node tools/presentation/bundle.mjs --entry <viewer.mjs> --output <demo.js>
```

上述命令从仓库根目录运行。构建入口会先检查资源，再把消息库和词典打包进浏览器脚本。原始模型记录和结构化展示数据由消费者分别保存；切换语言不翻译或覆盖原始请求、工具返回和摘要。

当前离线演示对一份固定的历史公开工具记录做构建期整理，浏览器不再解析英文游戏文本。这不是新的通用采集协议；新采集的正式展示应沿原生 owner 取得 typed 公开状态。原始文本与结构化展示必须保留来源关系。
