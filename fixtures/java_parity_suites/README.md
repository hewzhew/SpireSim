# Constructed Java parity suites

Suites are exact probe-case orchestration manifests, not shared-runtime batches.
Every member still receives a fresh game process, isolated storage, scenario
UUID, capture, comparison, and workflow. The suite plan binds each probe draft
and its referenced root draft before execution. A suite reduces caller
supervision and binds the resulting evidence; it does not claim to amortize JVM
startup.

`cultist-end-turn-rng-boundaries` covers the oversized-draw double-shuffle
case, the five-card no-shuffle opposite, and one strict reproduction of the
former. Its aggregate remains `constructed_validated`, never natural, policy,
or training evidence.
