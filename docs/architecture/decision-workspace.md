# 决策工作区与语义计划

状态：**整体仍是候选设计；来源化单步、有限领奖计划、驻留工作区与具名节点切换已有实验实现。**本文细化[主架构](../ARCHITECTURE.md)中的
分析者交互，不宣布新的端到端 runner，也不规定最终 CLI/MCP 拼写。执行入口仍以
[RUNBOOK](../RUNBOOK.md)为准，证据与认证仍遵守[TESTING](../TESTING.md)。
实验实现不代表通用选择器、条件循环或完整决策工作区已经落地。

## 主要调用者与交互验收

主要调用者是负责决策的分析模型。项目所有者观察实际打法、结果和策略解释，提供反馈；
不以所有者学习命令、复制句柄或代为推进作为日常使用流程。

模型应通过结构化请求操作驻留工作区，使用观察结果提供的对象引用、有限操作与明确停点。
完整来源随请求绑定，由核心校验；避免让模型反复拼接来源字符串、解析终端重画输出或搬运
完整状态。正常结果优先返回影响下一次决策的变化、必要选项和停止原因，详细证据按需展开。
CLI 可以用于诊断，MCP 可以作为前端；二者都不拥有另一套状态或提交语义。

交互验收必须包含分析模型通过实际工具调用完成代表性操作，检查调用次数、所需上下文、
重复重建与等待，以及异常后的可继续性。来源门禁、离线预演和单元测试通过，只证明对应
正确性，不能单独证明交互已经适合模型。搜索仍只辅助，计划以外的新决策交还分析模型。

## 一份局面、一份工作区、一个执行核心

日常交互围绕观察局面、试验方案、检查结果、切换或撤回分支、采用方案展开。单步、选牌、
有限序列、条件循环和搜索提出的完整回合，都编辑同一个具有明确来源的私下工作区。
分析者负责策略取舍；搜索只在被请求时提供候选。列表顺序与首个可行结果不取得策略权威。

工作区保存采用过的意图、分支关系和重建来源。运行中的 Rust 分支可缓存精确状态以便快速
切换；耐久记录保存 typed 来源与编辑，冷恢复用当前实现重建、重放。比较器使用真实双端
状态；前端只读取决策视图，不拥有另一套游戏、分支或提交日志。

日常 `run-play` scratch 保存当前楼层的逐步回退、已完成楼层的精确落点及少量明确标记的局面；
构建源码摘要不作为继续玩的门禁。
当前实现能读取精确状态时从该处继续，不能读取则明确报告，不声称旧轨迹的胜利、自然来源
或跨端认证。证据实验单独保留生产者和来源；从旧会话挑选局面进入 scratch 只转移游戏状态。

私下试验、分析者采用的计划、Java 实际完成的动作分别记录。撤回私下分支不撤销已执行的
Java 动作；Java 的重新加载只沿已经验证的原生恢复边界进行。

## 短输入与稳定身份

显示顺序可以按阅读需要调整，短标签只用于定位一次观察里的对象或选项。执行请求须携带
其来源视图，并由核心验证；不得把旧标签重新解释为新列表中的同一位置。

| 引用 | 表达什么 | 有效范围 |
| --- | --- | --- |
| 视图内选择 | 在这次观察里明确展示过的动作 | 同一来源、游标修订与观察合同 |
| 对象引用 | 具有来源证明的卡牌、敌人、奖励或槽位内容 | 所声明的对象生命周期，动作前仍需检查状态 |
| 语义选择器 | 从允许的对象中按明确条件选出动作对象 | 所采用的规则及当前允许读取的视图 |

来源视图至少绑定会话/分支、单调编辑修订、相应提交位置和合同身份。实际状态与来源也要
验证，单独一个数字修订不能证明状态相同。重复观察未变化的游标不使选择失效；执行、撤回、
切换分支或重新加载使旧视图请求失效，即使画面或 HP 恰好相同。执行端不能从当前画面替
调用者补造丢失的请求来源。

同一编辑或提交游标由单一 writer 拥有。来源校验与动作预备在同一串行区间完成，避免另一个
前端在校验后推进局面。私下工作区与实际提交各有游标，读操作不隐式切换或推进任何一方。

卡牌在手牌中的位置变化不改变对象引用。复制品、同名牌和 reload 后的 Java UUID 按
[卡牌来源合同](card-lineage.md)处理。奖励引用要限定所属奖励页面与 occurrence；药水动作
还要检查槽位的实际内容。名称、裸 UUID、位置和局面摘要不能代替来源证明。

自然语言可用于讨论策略、为分支命名；执行前必须变成可检查的结构化对象与规则。名称输入
只能使用明确内容标识及唯一性校验，不在每一步猜测自由文本含义。允许的选择方式包括：

- 已绑定的具体对象；
- 当前条件下唯一匹配的对象；
- 分析者明确给定的对象优先顺序，选择首个满足条件者。

多个匹配且没有采用过选择顺序时暂停。未经证明，不因同名、伤害相同或显示相同而合并。
展示可以分组，已存在的合法选择仍必须可访问。采用的请求绑定解析后的实际对象。

## 信息与试探权限

信息范围、试探/回溯范围、试探知识的保留分别描述，不能仅由一个“SL 模式”开关代替。

| 维度 | 需要声明的边界 |
| --- | --- |
| 决策可见信息 | 正常公开信息、机制公开的牌序、分支试探结果、允许读取的内部状态 |
| 试探与回溯 | 不允许试探、真实原生保存边界、可重建的固定 seed 私下分支 |
| 知识来源 | 直接观察、内部读取、在哪条分支试验后得到；撤回状态不会抹去已获知识 |

近期候选能力针对固定 seed 的 Rust 分支试验及 oracle 对齐。NoSL 与较弱原生 SL 的隔离
不在本设计中宣称完成。比较器可以需要比决策视图更多的内部信息；以后限制决策信息时，
需要同时审查预测结果、候选排序、诊断与历史观察，不能只隐藏一张抽牌堆列表。

冻结之眼公开当前抽牌堆顺序，不自动公开未来所有随机结果。同一 seed、起点和动作轨迹
可重现；改变 RNG 消耗或动作轨迹后的抽牌事实属于新的分支，不能沿用旧分支的预测。

## 有限计划与精确动作轨迹

计划表达分析者采用的有限规则。候选的最小表达能力为：

- 具体语义动作与上述受限选择器；
- 按顺序执行；
- 在稳定边界检查无副作用条件，执行已采用的分支或显式暂停；
- 带有限工作预算、目标与退出条件的重复；
- 以明确的决策页面或边界为终点，交回判断权。

计划不是可执行的任意脚本，也不隐式调用搜索。终止目标达成时立即结束；条件失效时不补
动作。意外出现的选牌不会自动选择，目标死亡不会自动换目标，药水槽满不会自动丢药。
如果某种中间选择已在计划中明确指定，则只按那条指定规则继续。

在当前 oracle 对齐方式下，Rust 先从当前可复验来源展开计划。每一步选择器读取合法视图，
解析实际对象，调用正常 adapter 执行并记录后继；输出一条有限 `SemanticAction` 轨迹、
来源与合同、计划修订及明确终点。循环与条件不进入底层游戏动作枚举，也不进入 Java。

准备采用时必须用当前代码从相同来源复验整条轨迹，核对其真实前态、实际对象和预期后继。
批准的是这条具体轨迹及其剩余后缀。Java 通过既有共享核心逐动作 prepare、execute、settle、
记录原始证据、比较状态与 RNG 调用；不得因为计划在 Rust 中成功而省去中间比较。

战斗中的局部序列、选牌试验与循环是整场草稿的材料。战斗提交须有当前代码复验过的完整
胜局，或合法烟雾弹逃脱到存活空奖励页的闭合方案。逃脱单独验证 smoked 标记、资源和空奖励；
  原版逃脱由动画计时器自动结算，不提交结束回合，也不执行普通回合末效果。
它不是胜利，严格胜局验证仍拒绝它。非战斗有限计划可闭合到明确的决策停点，
不借用“完整胜局”标签，也不取得后续选择的权限。循环杀掉一个目标不等于整场战斗结束。

缺少将来信息时，可以把计划闭合到读取该信息的边界，再交回分析者。以后支持受限信息的
在线条件执行，需要独立证明允许读取的信息与继续权限；不能把 Java 后继用于悄悄改写
本轮已经采用的轨迹。

## 分支与工作预算

分支节点绑定共同来源、父节点、编辑与单调修订；名称只是指向具体修订的显示引用。
切换回先前分支时恢复那个节点，继续编辑形成新后继，不改写另一条分支。选牌中的暂停
也是合法节点，保留待结算队列及其来源。观察、比较与切换不自动消耗搜索预算。

比较优先展示会影响选择的差异：消耗了哪张牌、抽到了什么、能量/HP/格挡、敌人状态、药水
和持久资源。未完成的分支明确标为局部结果，不把当前伤害或 HP 当作整场优劣结论。

所有计划具有动作数与结算工作上限。循环可附加明确的进展条件；HP 暂时不下降并不足以
判定无进展，因为积累格挡或能量也可能是目标。只有可证明的状态/控制位置重复且没有所
声明进展，才报告无进展；其他预算耗尽保留为 Unknown，不解释为循环不可行。

工作区应驻留当前来源及可复用父节点。一次有限操作可以内部展开多步，只返回其结果或
暂停点；不能为了每张牌启动 JVM、重建整条自然路线或打印全部中间状态。冷恢复仍验证
来源与记录，缓存不能替代证据。

## 提交、中断与返回值

| 结果 | 含义与后续行为 |
| --- | --- |
| 完成 | 已达到明确目标或轨迹终点，报告实际完成范围 |
| 等待决定 | 到达约定页面或出现未包含的选择，保留游标并交回判断权 |
| 请求失效 | 来源视图、分支或修订不匹配，尚未发出本次动作 |
| 计划无法继续 | 缺对象、条件失效、歧义或已证明无进展，保留可复验前缀 |
| 工作预算耗尽 | 私下展开尚未闭合，结论 Unknown，保留已产生材料 |
| 执行异常或结果未确认 | 原始证据、双端差异或请求/收据需要诊断，冻结提交后缀 |

一次提交请求有来源、不可变计划修订、请求身份和动作游标。发出动作前先记录提交意图，
确认后继及双端比较并可靠写入收据后才推进游标。重复请求读取已确认进度，不重复发出
动作。动作可能已生效而确认丢失时，先核对请求、Java 原始后继和收据；无法确定则保持
Unknown，不能仅凭当前画面相同推断成功，也不能盲目重试。

已经实际完成的步骤不因后续失败而自动回滚。原始证据写入失败同样冻结后缀。私下计划
校验或失效输入属于提交前拒绝，不应把尚未执行的动作写成真实游戏转换。

默认显示来源端、游戏局面、必要变化和待选事项；批量进度或异常确实影响后续操作时才
显示步数和恢复提示。内部边界名、覆盖细节和计时按需诊断，不逐次重复实现说明。游戏
事实来自状态 owner，字段比较独立于显示措辞；不能把渲染文本用作状态差分或重放输入。
纯文本输出自行处理块间分隔，不依赖终端控制字符。

耐久语义记录保存具体动作、来源、生产者和分支关系；显示摘要、限制说明与性能采样属于
可替换的派生材料。工具升级不因文案变化迁移动作记录，有限序列仍落到同一逐步动作合同。
完整收据可按诊断引用展开。界面断开不拥有暂停/继续之外的策略权限。

## 三个共同验收场景

以下是候选能力的验收合同，不是已通过的测试或新的游戏机制规则。

### 领取奖励后停在选牌页

输入为明确的一份金币、一瓶药水和一份卡牌奖励；计划指定领取顺序并在卡牌选择页停下。
领取金币的遗物效果仍通过正常引擎结算，不把它假设成无副作用的加法。

- 拿到药水导致动作集合插入“丢弃药水”后，计划继续指向原奖励，不依赖菜单位置；
- 旧视图短标签被重新发送时必须拒绝，Java 动作计数不增加；
- 药水槽已满或奖励来源不符时暂停，不丢药、不替换奖励、不自动 Proceed；
- 成功终点正是选牌页，没有替分析者选牌；
- 第二步确认后中断，核实来源后只执行剩余步骤；确认丢失时先进入结果未确认状态。

### 燃烧契约的分支试验

从同一已验证战斗节点，试打具体燃烧契约。消耗选择页可暂停；分别选择不同的具体卡牌
形成两个分支，完成抽牌后比较，再切回任一分支继续。

- 两条分支有共同父节点；恢复同一分支重现牌区、队列、RNG 与资源；
- 卡牌位置变化、同名重复牌和升级差异不改变已经绑定的消耗对象；
- 抽牌事实带有分支来源，不能移植到改变 RNG 消耗的另一条路线；
- 撤回不抹去观察历史，也不声称恢复了分析者未经试探的知识状态；
- 试验不触碰 Java；只有选中分支形成完整胜局或合法逃脱结算并复验后才可按现有门禁采用。

### 双 Dropkick 循环

分析者选定循环所用卡牌、目标、候选顺序、条件、预算和停止目标。Rust 在每个稳定边界
解析当前可打对象，精确展开。洗牌使手牌位置变化时，规则仍使用对象与当前条件。

- 费用返还、抽牌与易伤检查均由真实模拟结算；计划不手算或复制 Dropkick 机制；
- 多张候选同时可打时遵守显式顺序；同名且没有规则的歧义会暂停；
- 易伤消失、费用变化、无法抽牌、手牌上限或意外选牌影响循环时，以真实后继检查条件；
- 目标死亡或出现新阶段后按声明停下；不自动换目标、不跳过敌人能力；
- 私下预算耗尽不授予 Java 执行权；完整结算方案通过后逐动作比较，不合并为一次循环比较。

## 动作膨胀与职责边界

对象、目标和多选集合应按需展开。多选可先编辑一个选择，再由 adapter 验证一次正式
`SubmitSelection`；不能为显示方便把原版一次选牌拆成多个真实游戏动作。

减少显示、延迟枚举、证明等价后剪枝是三种不同能力。有限显示不等于完整搜索；若完整
动作空间合同本身仍要求先枚举所有组合，单改 renderer 无法解决计算膨胀。改变该合同
必须同时调整共享声明、双端合法性验证和相应覆盖测试，不可单端省略后继续宣称 Exact。

候选职责分配：共享 lockstep 核心拥有来源化请求与精确动作提交边界；runner 的分析者
工作区拥有私下分支、计划展开和采用资格；双端 adapter 拥有对象绑定与正常游戏结算；
既有 planner/search 提供可选候选；前端拥有显示与输入编码。复用一个 source/journal/
snapshot owner，不为奖励、抽牌或循环分别建立服务、存档体系或一组 MCP 动词。

## 验证与待定问题

来源失效、标签重新排列、分支切换、暂停、重复请求、丢失确认和预算必须先由离线测试及
可注入故障的 adapter 验证。三个场景再通过正常 Rust adapter 检查对象、牌区、RNG 与
队列。需要新的 Java 机制证据时才运行最小实机范围，继续复用正常 comparator 和 journal。

这份设计不决定最终命令语法、分支存储编码或通用选择器语言。多候选等价规则、受限信息
下的在线分支、崩溃窗口的完整去重保证、缓存与延迟枚举收益，都需要各自验证；不得由
这三个示例推出它们已经成立，也不为迁移旧长链扩大实现范围。
