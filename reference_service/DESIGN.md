# 候选设计：整理后的知识与整局分析

日常决策使用已整理的知识。攻略原文保留在后台，供采集、整理和核查；不要求分析者在每次
选择时重新阅读原文，也不要求把已知局面编成自然语言查询。

[铁甲战士选牌与整局规划样本](../reference/expert/curated/README.md)提供这个方向的可运行试片。
它们只有选择性知识读取与来源审计，没有接管游戏会话或证明策略提升。游戏与实验权限继续遵守
[当前架构](../docs/ARCHITECTURE.md)和[运行边界](../docs/RUNBOOK.md)。

## 知识如何表达

| 内容 | 表达形式 | 判断边界 |
| --- | --- | --- |
| 机制事实 | 精确实体、效果、时序和已验证范围 | 来源报告与经过验证的游戏机制分别记录 |
| 条件经验 | 判断要点、前提、代价、反转条件、例外及来源差别 | 不自动成为通用动作分数或强制规则 |
| 决策方法 | 比较哪些变化、需要哪些信息、何时值得实验 | 提供思考方法，具体取舍属于分析者 |

结构负责身份、来源、访问与证据类别，中文正文表达概念和推理。不能为了结构化而将全部经验
压成布尔规则，也不能把原始长文换成 JSON 后继续整块返回。

可观察输入与需要判断的条件显式分开。例如“有消耗组件”可以观察，“能及时稳定启动”仍需
分析或实验。缺失信息保持 Unknown，不从文字标签、卡牌数量或作者的普遍偏好补造结论。

## 整理流程

采集与原文核查属于离线整理阶段：

1. 阅读带版本与范围的完整相关记录，保留论证条件和上下文；
2. 写出来源本身的简短主张，并绑定确切来源记录；
3. 合并真正相同的观点，区分情境不同的观点，并列仍有分歧的主张；
4. 写出综合后的条件经验或决策方法，标明整理者与验证状态；
5. 用不同局面检查压缩是否遗漏会改变判断的条件，再发布版本化知识包。

作者自述胜率、单卡等级、个人门槛不能直接转成训练标签、概率或执行条件。同一原文的转述、
译文和多个段落也不能计为多份独立证据。来源散列验证只能证明引用未变，不能替代转述审阅。

整局手册可以是这些知识的一个阅读视图。它不应成为每次决定都必须重载的大段固定提示。
新的案例与真实反馈用于修订条目，而不是不断向模型上下文追加原始攻略。

## 默认交互与上下文

- 入口提供短目录或明确对象关联，使用稳定条目身份；自然语言搜索仅作为可选补充。
- 一次可读取一个或几个条目，默认保留要点、需要确认的条件、反转限制和重要来源差别。
- 推导、可观察输入与待判断输入、引用归属按需展开，不重复附送全部来源材料。
- 只有调用方确认旧内容仍在上下文中，才按版本回执省略重复正文；压缩后可以直接重新读取。
- 展开级别、知识内容、所引来源或范围改变时，旧回执失效。知识没变也不表示新局面的取舍没变。
- 完整目录可访问，阅读数量和排序不取得候选筛选或行动权限。

知识样本按条目 ID 读取。Rust 公开战略导出提供短局面、完整候选与牌组/地图/页面等按需展开，
并按角色与决策类型检查知识包范围。奖励、商店等页面的公开读取不依赖选牌知识包存在，也不
自动借用它的经验。跨页面的路线与资源知识使用明确的决策类型列表，由分析者显式选包和条目；
范围检查不判断当前适用性，也不为不同页面复制同一条经验。说明由 Rust 的 typed 公开对象生成，与原观测和候选绑定；读取器不解析
自然语言来决定动作或查询实体。候选机制可按精确动作身份展开，只呈现 Rust 共享语义层的定义字段与
明确已审阅的请求和时序，缺失保留 Unknown；它不是完整卡牌说明或战斗结算预测。
条目仍由分析者选择；它没有实现对象相关度排名或局面推理，也未接入
Java 手动会话。CLI 读取同一研究核心，不复制推理或状态语义。

路线读取以明确的当前候选为起点。公开连线可压缩成保留顺序的连续路段，但必须保留所有可达
分支、合流身份和未知端点。图上的“可达营火”不证明可以休息，也不预测到达时的HP；不能用
各资源独立的数量上限冒充一条能同时取得所有收益的路线。

## 与游戏和实验的关系

游戏 owner 提供当前公开观测与完整合法动作，知识库不拥有 head、trajectory、恢复或合法性。
卡牌概念的实体 ID 与具体游戏实例的身份分开。动作句柄绑定发布它的观测，不能在新局面按
同位置复用旧动作。展开同一稳定边界时应复用 owner 已有状态，避免重复整局恢复。

分析者可以记录自由笔记，引用当时观测、知识版本与实验结果。新信息出现时显示变化，并由
分析者修正判断；旧笔记不会自动成为当前计划。资料读取不构成必经门禁。

即时资源变化、固定战斗实验和未知未来情景分别呈现。未知精英、未来掉落等不能因为研究工具
可以读取内部状态就进入普通策略判断。构造情景标明假设，搜索预算不足仍为 Unknown。

多步计划与当前合法单步动作分别呈现。“丢药再领奖”或“一路打精英后休息”不是天然存在的
单步动作。分析者负责选择方案，执行仍由现有 owner 校验；Java 只跟随采用的轨迹。

## 生命周期与评估

知识包的日常读取只依赖整理结果。来源原文、Wiki 派生图或整个模拟器实体目录的故障，不应
阻止读取已版本化的综合知识；相应来源审计或实体关联要明确报告自己的失败。不得为了继续
运行而放宽身份校验、猜测实体或静默选择旧映射。

评估分别回答：

- 结构、引用与版本是否正确，条件和分歧是否保留；
- 相同候选在不同资源与阶段下，知识是否支持不同的分析；
- 内容长度、重复读取和调用成本是否合适；
- 分析者是否因资料作出更有根据的判断；
- 在相同信息权限与实验预算下，实际策略表现是否改善。

合成试读只能回答前几类问题的一部分。模型综合、人工审阅、来源字节审计、实战表现和 Java
parity 是不同的证据，不能相互替代。扩展知识覆盖或修改综合观点，应由具体使用反馈与来源审阅决定。
